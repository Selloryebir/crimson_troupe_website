### SET-01｜产品身份、同人声明与素材责任

- 状态：已确认，待正式采纳
- 规划结果：用户第一眼应将页面理解为可信的泰拉剧团官网，而不是作品介绍页或开发演示页。
- 适用范围：全部表站、里站和国家版本的产品身份、页脚声明及公开素材责任。
- 不包含：访客侧逐项标注官方或原创属性，以及在正式内容区增加常驻角标、弹窗或重复声明。
- 正式迁入目标：`docs/blueprint/foundation/experience-system.md`、`docs/blueprint/content/content-contract.md`。

#### SET-01 规划正文

- 本站整体属于二次创作；“是否为游戏官方明示设定”不决定内容能否展示，也不触发访客侧的逐项标签、视觉分级、路由或功能差异。
- 非官方同人声明只出现在所有表站、里站和语言版本的页脚，不在正式内容区域增加常驻角标、弹窗或重复提示。
- 页脚声明必须具有正常可读性、对比度和辅助技术可访问性，不得通过极小字号、低透明度或叙事伪装使其事实上不可见。具体措辞和版权说明链接由后续内容统筹确定。
- 公开文字、图片、视频等以最终采用并审核通过的实际素材为准。素材来源、许可、署名要求和内部审核状态属于制作管理责任，但不转化为正文中的二创解释。

### SET-02｜文案口吻与信息边界

- 状态：已确认，待正式采纳
- 规划结果：表站常规文案采用中性的剧团运营口吻；角色口吻只用于具有明确叙事理由的署名内容。
- 适用范围：机构内容、系统反馈、署名内容、里站内容及其内部来源定位。
- 不包含：让角色表演取代常规服务反馈，以及向访客生成官方或原创标签。
- 正式迁入目标：`docs/blueprint/foundation/experience-system.md`、`docs/blueprint/content/content-contract.md`、`docs/blueprint/i18n/terminology-contract.md`。

#### SET-02 规划正文

- 机构内容：节目、剧团、观演服务和公告，克制、准确、面向观众。
- 系统反馈：搜索、筛选、错误和表单状态，直接说明结果，不进行角色表演。
- 署名内容：信件、访谈和角色发言，明确标示说话者及内容性质。
- 里站内容：可以不可靠、诱惑或侵入，但不得污染表站的常规服务文案。
- 创作资料可以区分内部背景、表站公开信息和里站揭示信息，以维持叙事节奏；该区分只服务作者侧组织，不向访客生成“官方/原创”标签。
- 署名、引语、翻译和改写内容应在内部资料中保留来源定位，避免版本迭代时失去依据。

### SET-03｜表站信息架构与视觉原则

- 状态：已确认，待正式采纳
- 规划结果：表站采用“首页编辑叙事、内页任务优先”的选择性扁平化设计。
- 适用范围：表站首页、四项主导航、内容页、搜索工具页、次级票务入口和整体视觉层级。
- 不包含：把全部内容堆入单页，以及复制参考站的构图、素材、文案、代码或品牌表达。
- 正式迁入目标：`docs/blueprint/foundation/core.md`、`docs/blueprint/foundation/experience-system.md`。

#### SET-03 规划正文

- 默认进入首页。首页通过文字、图片和克制动效建立高端、现代、明亮、权威的剧团形象。
- 主导航包括本季演出、历史演出、剧团和搜索，四项均拥有独立 URL；品牌标识返回当前国家版本的表站首页。
- 本季演出、历史演出和剧团属于内容页面；搜索属于工具页面，可以使用不同的信息密度，但必须支持直接访问、键盘和移动端操作。
- 观看方式与预约通过未来演出内容和独立票务工具页提供，属于次级服务入口，不扩张四项主导航；完整规则只由 SET-11 规定。
- 视觉扁平化指减少拟物边框和无意义层叠，以排版、图像、留白、色彩与克制动效建立层级。
- 信息扁平化指核心内容经过较少层级即可到达，不表示把全部内容堆入单页。功能内页可以使用筛选、列表、分页和详情层级。
- 图片必须承担剧目、人物、场景或品牌叙事功能，不作为无意义填充。
- 对维也纳爱乐等参考站只借鉴首页与功能内页的内容分工、留白层级和任务优先原则，不复制其构图、素材、文案、代码或品牌表达；具体转译依据继续由 `docs/references/` 负责。

### SET-04｜双时间层与年代叙事

- 状态：已确认，待正式采纳
- 规划结果：表站与里站属于同一项目中的两个独立网站体验，不是同一页面的明暗换肤。
- 适用范围：表站“现在”、1091 里站、两站的信息与视觉独立性、共享基础和切换方式。
- 不包含：为表站设置影响构建的固定年份，以及在同一 HTML 中显隐整站或把里站做成表站换肤。
- 正式迁入目标：`docs/blueprint/foundation/experience-system.md`、`docs/blueprint/foundation/narrative-state.md`、`docs/blueprint/modules/archive.md`、`docs/blueprint/content/content-contract.md`、仓库根目录 `README.md`。

#### SET-04 规划正文

- 表站位于《红丝绒》事件之后，表现傀影继承酒神相关权能并重新组建的剧团，其时间只定义为叙事语义上的“现在”。项目不为表站设置影响界面、路由或构建逻辑的固定泰拉年份，也不在全站界面直接公布当前年份。
- 历史演出、未来演出和新闻稿可以显示各自内容中的泰拉日期，让访客自然估算时间区间；内容的过去/未来归属由类型化状态或内容编排显式决定，不根据浏览器现实时间或隐藏的全站年份常量推导。
- 里站表现泰拉历 1091 年当时实际存在的旧剧团官网。`1091` 是历史快照的年代标识，也是内容与视觉设计依据；其 URL 表达只由 SET-07 规定。
- 里站拥有独立的信息架构、内容目标、浏览节奏、导航语言和交互反馈；其内容与表站不要求逐页对应。
- 里站采用古老、阴暗、怪异、扭曲的年代风格，但必须转译为泰拉媒介语言，不直接套用现实早期网页、维多利亚印刷品或 VHS 故障效果。
- 等级 `0` 的 1091 年网站本身必须内容完整、可信且可浏览；污染效果不能替代原始快照的内容建设。
- 两站共享 Astro 工程、构建工具、无障碍基础和必要品牌线索，同时使用独立路由树、页面布局、导航、内容模型、设计令牌子集和客户端状态。
- 表里切换可以保留过场和叙事反馈，但必须通过路由导航完成，不在同一个 HTML 中显隐整站；具体落点、直达与浏览器历史行为只由 SET-07 规定。

### SET-05｜响应式、可访问性与安全体验

- 状态：已确认，待正式采纳
- 规划结果：手机端与电脑端承载相同的任务、内容和结果，但不要求像素级一致。
- 适用范围：手机与桌面任务一致性、代表视口、导航、动效和 JavaScript 失败降级。
- 不包含：要求不同视口像素级一致，以及依赖 hover、动画或 JavaScript 才能完成的核心任务。
- 正式迁入目标：`docs/blueprint/foundation/experience-system.md`、`docs/blueprint/quality/stage-gates.md`。

#### SET-05 规划正文

- 导航形式、信息密度、图像裁切和动效幅度可以随视口调整。
- 最低检查宽度为 320 CSS 像素，并覆盖 375/390、768、1024、1280/1440 等代表性宽度及更宽桌面。
- 任何目标宽度下都不得出现页面级横向内容丢失、主要操作被遮挡、文本脱离容器或只能依靠 hover 完成的任务。
- 移动导航必须处理触控目标、安全区、展开后的页面滚动和焦点管理。
- 所有动效必须支持 `prefers-reduced-motion`，且不得依赖动画才能理解信息或完成操作。
- JavaScript 失败时，表站和等级 `0` 的里站核心内容仍可阅读，不得残留无法关闭的全页覆盖层。

### SET-07｜URL、版本切换、直达与索引

- 状态：已确认，待正式采纳
- 规划结果：根路径固定跳转至默认简体中文表站首页 `/yan/`，其余 URL、切换、直达和索引行为使用稳定规则。
- 适用范围：根跳转、公开路由、世界与国家版本切换、深层直达、索引和 canonical。
- 不包含：根据浏览器语言猜测根落点、把 `noindex` 当作保密机制，以及把污染等级写入 URL。
- 正式迁入目标：`docs/blueprint/foundation/core.md`、`docs/blueprint/foundation/narrative-state.md`、仓库根目录 `README.md`。

#### SET-07 规划正文

根路径不猜测浏览器语言。`routePrefix` 只取 SET-06 矩阵中的公开前缀；其后的路由段使用稳定、非本地化的 ASCII 名称和统一尾斜杠：

```text
/{routePrefix}/
/{routePrefix}/troupe/
/{routePrefix}/search/
/{routePrefix}/tickets/
/{routePrefix}/archive/site/1091/
/{routePrefix}/archive/site/1091/troupe/   # 仅当快照具有该页面
/{routePrefix}/archive/site/1091/search/
```

- 页面通过稳定内容 ID 建立跨版本对应关系，不能依靠翻译标题生成 URL。
- 表站的历史快照入口保持彩蛋性质，不要求所有访客立即发现；入口隐藏性不限制合法 URL 直达。
- 从表站点击历史快照入口时，进入同一国家版本的里站首页 `/{routePrefix}/archive/site/1091/`。
- 从任意里站页面点击返回入口时，进入同一国家版本的表站首页 `/{routePrefix}/`。
- 通过地址栏、书签或外部链接直接访问合法 URL 时，直接显示该 URL 对应页面，不强制重定向至首页。
- 切换国家版本时保持当前世界并优先进入等价页面；目标版本没有等价页面时，回到同一世界的目标版本首页并提供明确反馈。
- 只有简体中文表站首页 `/yan/` 允许被索引并进入站点地图。根路径只负责重定向；其他语言首页、全部表站内页和全部里站页面统一输出 `noindex,follow`，但保持直接访问能力。
- `noindex` 不承担保密功能。canonical 指向当前国家版本与当前世界的稳定 URL，污染等级不进入 URL 或 canonical；`/yan/` 的 canonical 指向自身。

### SET-08｜i18n fallback、完整度与发布门禁

- 状态：已确认，待正式采纳
- 规划结果：简体中文 `zh-CN` 是完整基准语言；开发预览允许翻译缺失，正式发布不允许已发布语言出现 fallback 内容。
- 适用范围：开发期中文 fallback、翻译覆盖率、正式发布语言集合和发布门禁。
- 不包含：在正式版本发布不完整语言，以及把缺失警告显示在沉浸式页面中。
- 正式迁入目标：`docs/blueprint/i18n/localization-contract.md`、`docs/blueprint/i18n/terminology-contract.md`、`docs/blueprint/quality/stage-gates.md`。

#### SET-08 规划正文

- 开发环境按“目标 locale → `zh-CN`”回退；回退不改变 URL、国家版本或搜索范围。页面根元素保持目标 locale，实际回退为中文的内容节点标记 `lang="zh-CN"`，避免辅助技术按错误语言朗读。
- 开发期回退生成面向开发者的缺失清单或构建报告，但不在沉浸式页面中显示警告。
- 正式构建只发布显式列入 `releaseLocales` 的语言。`zh-CN` 和其中每一种语言都必须达到 `100%`，否则发布门禁失败。
- 未完成语言可以存在于仓库和开发预览中，但不得进入 `releaseLocales`，也不得在正式入口形成中外文混排页面。
- 覆盖率分母包括发布范围内的正文、结构化内容、导航、系统反馈、元数据、图片替代文本、搜索索引文本及其他可被访客或辅助技术感知的字符串。
- 纯装饰内容、未进入发布范围的草稿和无需翻译的专名不计为缺失；专名必须遵守 i18n 术语矩阵。
- 发布门禁针对本次声明发布的语言集合：仅 `zh-CN 100%` 可以发布，多语言全部达到 `100%` 也可以发布；集合内出现任何不完整语言都不可发布。

{editionId}:front          -> /{routePrefix}/search/

#### SET-10 规划正文

##### 状态与生命周期

- 污染值为 `0 | 1 | 2 | 3`，依次表示原始快照、轻度污染、中度污染和重度污染。
- 状态归属于当前浏览器标签页，在同一标签页和不同国家版本的里站页面之间连续存在，不按语言拆分。
- 新标签页初始值为 `0`。每次有效判定成功时增加 `1`，只增不减，并在 `3` 封顶。
- 到达等级 `3` 后停止污染判定，但触发判定的导航、语言切换和搜索功能继续正常工作。
- 主动返回表站时先清除状态；关闭标签页后状态结束。不得使用账号、服务端状态、Cookie 或跨标签页同步维持污染。
- JavaScript 或客户端会话状态不可用时，污染状态退化为等级 `0`；内容与退出的降级要求只由 SET-05 规定。
- 不为污染状态增加生产遥测或服务端请求；其 URL 与 canonical 边界只由 SET-07 规定，搜索数据边界只由 SET-09 规定。

##### 判定触发白名单

以下用户行为各触发一次污染判定：

1. 从表站点击进入里站；
2. 通过地址栏、书签或外部链接直接进入里站；
3. 在里站内点击进入另一个里站页面；
4. 在里站内切换国家版本或语言；
5. 提交一次里站搜索。

每个用户动作最多判定一次。搜索提交若导航到结果页，由搜索事件负责，不再被通用页面导航重复计算；随后点击某条搜索结果属于新的页面导航，可以再次判定。刷新、浏览器前进/后退恢复、锚点跳转、输入搜索字符、查询参数的非提交变化和页面自身重渲染不触发判定。

##### 判定概率与验收

- 污染值未达到 `3` 时，每次有效判定均以固定 `42%` 概率增加一级，各次实际判定相互独立；不使用连续失败递增、按等级变化或其他渐进概率。
- `42%` 必须由单一配置拥有，不能散落在事件处理器或组件中；修改该配置时，触发白名单与等级状态机不随之改变。
- 从等级 `0` 开始，在前 10 个有效触发点内达到封顶等级 `3` 的理论概率约为 `86.2839%`，满足严格大于 `85%` 的验收条件；到达封顶后不再执行剩余判定。
- 上述概率通过自动化模拟、开发构建或受控体验测试验证；生产数据边界只由本规划的“状态与生命周期”规定。

##### 等级职责

| 等级 | 叙事状态 | 表现边界                                                                       |
| ---- | -------- | ------------------------------------------------------------------------------ |
| `0`  | 原始快照 | 年代网站本身完整成立，不出现异常                                               |
| `1`  | 轻度污染 | 少量可疑划线、替换或图像痕迹，不破坏布局理解                                   |
| `2`  | 中度污染 | 多处涂黑、图像异常和内容矛盾，主导航仍明确                                     |
| `3`  | 重度污染 | 大范围内容不可信、受控板块错位、明显视觉侵入和叙事失真，核心浏览及退出仍可操作 |

- 除表里切换出入口和页脚同人声明外，其他可见元素均可成为污染表现对象。
- 划线、涂黑、图片红叉、图片异常、受控错位和叙事替换属于可用手段，但不能变成无约束的随机噪声。
- 同一等级中的随机选择在当前标签页生命周期内保持稳定，避免每次渲染都改变位置或异常类型。
- 污染作用于呈现层和经过编排的叙事变体，不永久修改源内容、翻译完整度或其他数据。

##### 不可污染的技术底线

- DOM 语义、可访问名称、键盘顺序、可见焦点和辅助技术状态；
- 可靠退出、`prefers-reduced-motion` 和无 JavaScript 降级路径；
- 视口安全、页面级无横向内容丢失，以及出入口和页脚声明不被遮挡；
- 图片替代文本或可理解的异常占位反馈；
- 不使用闪烁滥用、强制全屏、伪造浏览器/系统警告、恶意下载或无法关闭的遮罩。

##### 测试控制

测试构建允许手动增加、减少或指定污染值，以便逐级验收。正式构建必须通过构建条件从产物中排除调试 UI 和控制代码，不接受仅用 CSS 隐藏。

#### SET-11 规划正文

##### 定位与入口

- 观看方式与预约实现为表站的独立票务模拟模组，目标是让浏览者体验“建立购票篮 → 经历购票流程 → 得到结局”的泰拉内购票过程，并通过票务暗黑模式讽刺和纪念票奖励增强参与感。
- 模组的导航层级与次级入口只由 SET-03 规定，稳定地址只由 SET-07 定义。
- 模组尚未实现或未启用时，全部购票入口仍指向真实存在的票务工具页。页面以泰拉内口吻显示“暂未开票”，提供返回未来演出等有效路径；启用模组后在同一地址承载购票流程，不修改既有站内链接。
- 启用或停用模组只改变票务工具页承载的能力，不改变未来演出的源数据、其他页面职责或稳定 URL；没有模组时，表站其余任务仍可独立完成。
- 未开票页面随当前国家版本生成，遵守 SET-08 的发布门禁及 SET-07 的索引规则；无 JavaScript 时仍能读取未开票状态。模组加载失败时也必须提供可理解的不可用反馈和返回路径，不留下断路或无法关闭的覆盖层。

##### 状态模型与生命周期

模组使用三个职责分离的状态：

1. **购票篮**：从当前可购买的未来演出中选择至少一场；每场只能选择 `C / B / A / S / 包厢` 中的一个分区，且一次体验中每场限购一张。总票数随可购演出数量变化，例如列出三场时最少一张、最多三张。
2. **购票尝试**：承载排队、验证、库存变化、价格分支和讽刺性互动；一次尝试不直接修改购票篮。
3. **结局**：至少包括购票成功、购票失败和网络波动。失败或网络波动后可以使用原购票篮重新尝试；成功结算后不得因重复提交而重复生成同一次结果。

- 购票篮在失败、网络波动、线路选择、取消线路、同标签页内页面切换和主动重试之间保持。
- 成功后状态冻结为只读结算结果，不能因生成票面立即清空而使下载入口失效；只有浏览者明确开始新一轮、清空或结束本次体验时才重置。
- 限购只约束单次“购票篮 → 购票 → 出票”体验。完成或结束后可以重新开始，不形成账号级、设备级或永久购买次数限制。
- 全部状态只属于当前标签页，不跨标签页或设备同步，也不写入长期持久化存储。关闭标签页即结束体验，并清除购票篮、流程分支、印章组合和结局；在同一标签页内关闭流程界面或离开票务页不隐式清空。

##### 分支、概率与价格

- 流程必须同时包含浏览者选择和概率结果，但不在本规划中锁定最终节点数量、文案或分支概率。普通线路失败后选择重新尝试或进入加价线路、加价线路分别可能成功或失败，可作为流程设计种子而不是固定流程图。
- 讽刺对象是抽象的票务暗黑模式，例如库存反复变化、服务费叠加、无意义验证、强制等待和伪稀缺提示；不复制现实网站的名称、商标、文案、独特构图或代码。
- 价格使用整数龙门币（LMD），并区分以下四个数据语义：
  - `basePrice`：各分区的单张基础票面价；
  - `baseTotal`：购票篮内所有票的 `basePrice` 之和；
  - `adjustments`：流程分支造成的加价、费用或其他结算差额明细；
  - `settledTotal`：`baseTotal` 加上 `adjustments` 中各项金额之和后的单次模拟实际结算总额；
- 纪念票不保存独立的票面价格字段，直接显示对应分区的 `basePrice`，因此不受 `adjustments` 或 `settledTotal` 影响。`baseTotal` 与 `settledTotal` 均由其来源数据计算，不作为可独立编辑的重复事实。
- 结算画面按演出列出 `basePrice`，并汇总 `baseTotal`、`adjustments` 和 `settledTotal`，使浏览者能够区分单张票面价格、基础总额与模拟实际结算总额。

##### 成功结算与纪念票

- 当一次购票体验进入成功结局时，显示一个屏幕内存单，汇总本次全部演出、分区、`baseTotal`、`adjustments`、`settledTotal` 和结局信息。存单就是成功结局的结算画面，不生成独立的订单或存单下载文件。
- 存单下方按演出逐一显示纪念票：每个演出生成一张独立票面，因此一次购买多场演出会得到多张票。各演出拥有自己的基础票面设计，不把不同演出压缩到同一票面。
- 每张票至少包含演出、日期时间、分区、`basePrice`、LMD 单位、虚构票号和二维码，并分别提供直接下载和打印入口。
- 屏幕、下载与打印版本共享同一组票务内容；版式可以适配媒介，但不得遗漏或裁切演出、时间、分区、`basePrice`、票号及二维码。
- 纪念票采用“演出基础票面 + 可组合印章”的生成方式。单次购票结局只产生一组印章语义，该组印章影响本次全部票面，不按演出重新判定；各基础票面可以为同一印章设置不同的安全落点和视觉适配，但表达的支线结果必须一致。
- 印章不得覆盖或改写演出信息、基础票面价及二维码内容。成功结算后不得再要求登录、填写身份、完成二次抽取、分享、兑换或其他附加任务；除浏览器对下载和打印必要的用户确认外，不增加纪念票获取门槛。
- 二维码只承载与票面旁侧显示一致的随机数值，不作为订单号、排序号、唯一键、验证凭据或兑换凭据，也不链接支付、追踪、验证或真实票务系统。随机值不全局去重，不同浏览者可以取得相同号码。

##### 数据、文案与体验边界

- 模组不设置任何浏览者身份：不填写、不预设、不随机生成，也不提供身份选择；购票篮、流程状态、结算画面和纪念票均不包含姓名、证件、联系方式、地址、支付账户或用户画像。
- 页面不收集信息，不进行真实交易、扣款或远端票务请求。泰拉内沉浸感由剧团、演出、票务规则和界面语言建立，不依赖虚构身份或伪造真实支付能力。
- 成功结算画面页脚以小字说明“仅为小游戏内容，不产生任何兑换责任”。该说明不写入纪念票、不扩张为流程常驻提示，也不替代 SET-01 规定的全站页脚同人声明。
- 演出、分区、价格、时间和翻译来自类型化内容数据，模组不复制稳定业务数据；结算画面与纪念票语言跟随当前国家版本，并遵守 SET-08 的完整度门禁。
- 所有结局提供继续、重试或退出路径，不使用无限排队、无法跳过的倒计时或键盘陷阱。减少动态效果模式保留完整规则与结局，只削弱排队、抖动和库存变化动画；其他响应式、可访问性和安全边界由 SET-05 统一规定。

### OPEN-09｜建立项目规范术语与别名声明

- 状态：已回答，待人工确认
- 所属规划：SET-02、SET-03、SET-04、SET-06、SET-11
- 问题：表站、里站、演出、剧目、场次、票篮和泰拉时间等跨蓝图概念容易因人工复述、简称或中英文混用产生不同解释，目前没有供人员与智能体共同读取的唯一规范术语表。
- 影响：同一需求可能被映射到不同世界、数据实体或时间语义；尤其“演出”可能同时被误当作作品与具体场次，别名也可能错误进入代码标识、路由或公开文案。
- 建议答案：建立一份小型、项目级的规范术语表，每项只记录规范中文名、稳定概念 ID 或内部英文名、精确定义、允许识别的别名以及需要避免的混用。别名只用于理解人工输入，蓝图、代码和智能体输出仍优先使用规范名；一个别名若可能指向多个概念，必须结合上下文消歧，不能静默选择。首批只覆盖跨两个以上蓝图且已经造成歧义的术语：表站 `front`、里站 `archive`、剧目 `Production`、场次 `Performance`、作为自然语言总称但不作为数据类型的“演出”、票篮、泰拉日期时间，以及相对于当前世界解释的本季演出和历史演出。
- 维护边界：项目领域定义只保留一个规范来源；i18n 专有名词契约继续负责各语言标准形式、显示别名和搜索别名，不重复定义产品与数据语义。普通 UI 用词、一次性文案和没有歧义的实现细节不纳入术语表，也不增加术语审批流程。
- 合并动作：人工确认后新增一项已定规划，规定术语表的唯一位置、最小字段和优先读取规则；正式迁移时建立一份平级规范术语文件，并从蓝图 README 和相关正式蓝图引用，不在各 SET 或源码注释中复制整张术语表。
