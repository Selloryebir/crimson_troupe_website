# 表站首页与票务场次同步蓝图草稿

- 文档类型：蓝图草稿
- 状态：候选，待正式采纳
- 规划效力：不构成正式产品约束；仅描述本阶段拟修正的场次、票务和本地化契约
- 分析基线：`BP-MOD-TICKETING`、`BP-CNT-CORE`、`BP-MOD-PROGRAMS`、`BP-I18N-CORE` 与 `dev_blueprint@e3cd2d7`
- 目的：让当前表站首页展示的七个本季场次全部进入票务选择，并补齐可验证的分区、报价和九国家版本票面依赖

## 正文

### SET-01｜当前首页场次全部可购

- 状态：待正式采纳
- 规划结果：当前内容根集合中表站 `homepagePerformanceIds` 的七个本季场次均具有完整 `on-sale` 数据，并在票务页按同一构建快照呈现；本阶段票务候选 ID 与首页策展 ID 集合相等
- 适用范围：表站首页、表站票务页、合作票务页、凭单和纪念票
- 不包含：把 `homepagePerformanceIds` 改成长期票务注册表，或让未开票、非本季、非 `scheduled` 场次绕过票务资格判断
- 正式迁入目标：`BP-MOD-TICKETING`、`BP-CNT-CORE`

#### SET-01 规划正文

`ticketAvailability` 继续是单个 `Performance` 的唯一开票事实源，票务模块继续只消费当前快照中属于表站、本季、`scheduled` 且 `on-sale` 的场次。本阶段把首页已经策展展示但仍为 `not-on-sale` 的四个场次补齐为可售，使当前七个首页场次与七个票务候选一致；不得在组件、页面或本地化文件中另建第二份票务场次列表。

| `performanceId`                           | 剧目                  | 地点        | 当前缺口                     |

| `red-banquet-montelupe-1102-0606`         | `red-banquet`         | `montelupe` | 开票状态、分区示意、逐区报价 |
| `seventh-lantern-linqu-1102-1212`         | `seventh-lantern`     | `linqu`     | 开票状态、分区示意、逐区报价 |

首页的顺序继续由 `homepagePerformanceIds` 拥有；票务页顺序使用当前快照中与首页一致的确定性顺序。未来若首页只策展全部可购场次的子集，仍应由内容决策分别调整首页策展与逐场开票状态，不在票务控制器中形成隐式耦合。

- 适用范围：`TicketOffer`、座席示意、票篮金额、合作平台费用、凭单和纪念票

### SET-03｜九国家版本与内容闭包验证

- 状态：待正式采纳
- 规划结果：新增可购场次在九个预览国家版本中具备完整界面、场次、地点、剧目、举办地主层和当前网站辅助层票面投影
- 适用范围：九国家版本预览、内容解析、票面投影、构建与浏览器门禁
- 不包含：把 AI 预览翻译认定为正式翻译，或改变 `release` 的人工批准门禁
- 正式迁入目标：`BP-I18N-CORE`、`BP-MOD-TICKETING`、`BP-QLT-STAGE`

#### SET-03 规划正文

四个场次已经存在于各国家版本的类型化场次与地点内容中；实现应复用这些稳定记录，不复制标题、场馆或日期字符串。新增开票状态后，内容闭包必须对每个可购场次验证：

- 当前网站语言的票务界面、剧目、场次、地点与分区标签完整；
- 举办地国家版本能够形成纪念票主层，当前网站版本能够形成必要的辅助层；
- 主辅同语时省略辅助层，英语语言族规则保持不变；
- 官网票篮、合作平台、凭单、屏幕票面、下载 SVG 和打印读取同一场次与报价事实；
- `showcase` 与九国家版本 `preview` 都能构建，`release` 仍因未批准内容按既有规则停止。

验证器不写死“原先三个”或新的具体总数作为独立业务事实，而应从当前快照的首页策展和票务资格派生期望集合，断言本阶段两者无遗漏、无多余、顺序确定，并逐项检查分区拓扑覆盖全部有效 `TicketOffer`。
