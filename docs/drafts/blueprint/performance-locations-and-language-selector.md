#### SET-01 使用边界

- 地点中文名、英文名和本国语名是不同显示形式，不互相推导；正式采用时由稳定 `locationId` 关联；
- 现有地点资料只有中文、英文和地点本国语名，不构成九个国家版本之间的完整翻译矩阵。其他目标语言的地点写法仍须进入该语言的翻译范围，并遵守现有人工审核与发布门禁；
- 原表备注是作者侧解释与创作提示，不是访客文案。包含“捏他”、剧情定位、写法冲突或推论的内容不得直接进入沉浸式页面；
- 地点性质可以在正式数据中规范为多值枚举，例如“首都/移动城市”拆为 `capital` 与 `mobile-city`，但访客显示文本由当前国家版本翻译；
- 搜索可以消费已批准的标准名称和别名，但不能把未审核备注整体写入搜索索引。

### SET-02｜地点、场馆与场次详情的组合方式

- 状态：待正式采纳
- 规划结果：地点目录只提供可复用的城市或地区锚点；具体场馆、厅室和地址说明继续属于场次内容，避免用一条地点记录伪造完整地址
- 适用范围：`Performance` 的城市、场馆、地址、搜索详情、票面和演出详情页
- 不包含：为每个场馆建立页面、现实地理坐标、地图服务、街道级真实性或自动生成后免审核发布
- 正式迁入目标：`BP-FND-DOMAIN`、`BP-CNT-CORE`

#### SET-02 最小内容关系

- `Performance` 引用 `locationId`，并继续拥有该场次特有的 `venueName`、可选 `venueArea` 与可选 `addressDetail`；同一场馆被多次复用前，不新增独立 `Venue` 实体；
- 场次列表可以只显示日期、地点和场馆短名；详情页、票务与纪念票按版面需要组合地点、场馆及厅室，不要求所有页面输出完整地址；
- 地址详情必须是经人工审核的泰拉内文案。地点备注可以帮助创作，但不能自动拼接成公开地址，也不能把现实捏他说明带入页面；
- 当前 `src/data/performances.ts` 中的 `cityId`、`cityLabel` 与 `place` 是候选迁移范围。正式实现时按稳定身份迁移，不从中文名或英文名生成 ID，也不在多个场次中复制同一地点译名。

### SET-03｜本国语言称谓的国家版本选择器

- 状态：待正式采纳
- 规划结果：提供一个以国家标识和本国语言称谓呈现的国家版本选择器；组件能力覆盖全部已注册版本，正式页面只展示已经通过发布门禁的版本
- 适用范围：表站与里站页眉中的国家版本显示、切换链接、等价页面导航和窄屏布局
- 不包含：显示未发布语言、“即将推出”占位、根据浏览器语言自动跳转、把国家标识作为唯一标签，或复刻 MediaWiki 的完整通用语言选择器
- 正式迁入目标：`BP-I18N-CORE`、`BP-FND-NARRATIVE`、`BP-FND-EXPERIENCE`

#### SET-03 信息与交互模型

- 控件切换“国家版本”，选项由 `releaseEditionIds` 生成；可见文字只使用 `languageName.native`，并以对应技术 locale 标注 `lang`；国家标识只辅助识别，当前选项使用 `aria-current="page"` 或等价语义；
- 正式产物当前只有炎国版本时，页眉只显示静态的 `炎语`，不打开只有一个选项的空下拉。第二个国家版本通过发布门禁后，同一位置再启用选择器；
- 切换时保持当前世界并优先进入稳定 ID 对应的等价页面；没有等价页面时进入目标版本同一世界的首页并提供可理解反馈。里站切换仍遵守既有污染判定，不在选择器中复制污染状态逻辑；
- 九个候选版本不需要语言搜索、地理分组或多列列表；使用稳定产品顺序，当前版本可置顶，不对不同文字系统做混合字母排序。

#### SET-03 控件形态建议

需要在选项前展示国家标识时，不使用无法可靠呈现图像和富文本的原生 `<select><option>`；采用“披露按钮或 `<details>` + 链接列表”，视觉上仍是下拉菜单：

- 每个选项是可直接导航的普通链接，无 JavaScript 时仍可切换；
- 按钮说明当前国家版本并暴露展开状态；键盘可以打开、遍历、选择和关闭，增强脚本支持 `Escape` 关闭并把焦点返回触发器；
- 国家标识使用统一尺寸的项目内 SVG 或已授权资产，默认视为装饰；素材缺失时回退为纯文字；
- 窄屏允许菜单占据可用宽度，但不得造成横向滚动、覆盖退出路径或改变主导航的任务顺序。

该方案借鉴的是 MediaWiki Universal Language Selector 使用本国语言称谓帮助识别语言的原则，以及选择后返回原浏览上下文、提供关闭路径的交互要求；不复制其代码、布局、字体或大规模语言检索能力。

### SET-04｜UTF-8、语言标注与字体覆盖方案

- 状态：待正式采纳
- 规划结果：所有国家版本共用 UTF-8 数据链路，以正确 `lang` 标注、按文字系统组织的字体回退和代表性字形测试承载当前多语言集合
- 适用范围：地点与术语数据、Astro 页面元数据、语言选择器、全局字体栈、下载或打印内容
- 不包含：按语言使用旧式字符编码、依赖访客安装某一款字体、未经许可调用远端字体服务，或当前阶段引入完整字体管理平台
- 正式迁入目标：`BP-I18N-CORE`、`BP-FND-EXPERIENCE`；外部参考候选迁入 `docs/references/design-reference.md`

#### SET-04 编码与数据规则

- 仓库文本、结构化数据、构建产物和响应统一使用 UTF-8；语言与编码是两个独立维度，不为俄语、日语或希腊语切换编码；
- HTML 在文档头部声明 UTF-8，页面根元素的 `lang` 使用当前国家版本技术 locale；页面内本国语言称谓或回退内容发生语言变化时在最小包围元素上声明对应 `lang`；
- 结构化数据验证 UTF-8、稳定 ID、必填名称和 NFC 规范化；验证只报告差异，不静默改写已审核专名。

#### SET-04 字体与排版规则

- 正文和选择器首先使用能够覆盖汉字、日文、西里尔、希腊及扩展拉丁字符的系统字体回退链；本国语言称谓不能使用仅覆盖拉丁字母的品牌展示字体；
- 使用 `:lang()` 为中文、日文和其他文字系统调整字体优先级、行高与必要的字距，不把一套 CJK 字距规则应用到西里尔或希腊文字；
- 若后续视觉要求必须使用 Web Font，只引入经过许可并存放于项目内的 WOFF2，按实际文字覆盖拆分；加载失败时仍由系统字体完整显示，不通过第三方远端请求补字；
- 字体选择以“无缺字、重音和组合字符正确、行高稳定、按钮不截字”为门禁，再判断是否满足表站或里站艺术风格；
- 最小字形样本覆盖全部 `languageName.native`、本草稿所有地点本国语名，以及 `Zwillingstürme`、`Грифенбург`、`Αθήνιος` 等关键字符组合。

#### SET-04 外部技术依据

- [MediaWiki Universal Language Selector](https://www.mediawiki.org/wiki/Extension%3AUniversalLanguageSelector)：语言选择能力及本国语言称谓思路；
- [MediaWiki ULS Specification](https://www.mediawiki.org/wiki/Universal_Language_Selector/Specification)：选择、返回、关闭和键盘退出原则；
- [W3C: Declaring language in HTML](https://www.w3.org/International/questions/qa-html-language-declarations.html)：页面与局部内容的 `lang` 标注；
- [WHATWG HTML Standard](https://html.spec.whatwg.org/multipage/semantics.html)：HTML 字符编码声明使用 UTF-8；
- [W3C CSS Fonts Module Level 4](https://www.w3.org/TR/css-fonts-4/)：字体族按顺序匹配及缺字回退行为。
