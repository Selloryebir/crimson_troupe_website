#### SET-01 保存边界

- 三个标题字段是同一来源记录的并列版本，不追加包围书名号、机器翻译、罗马字、字面译名或替代标题；
- `productionId` 以 `English` 来源形式一次性转换为小写 kebab-case：保留词序与冠词、空格转连字符、移除撇号及其他不适合 ID 的标点。表中 ID 写入后冻结，不在运行时从显示标题生成，也不因后续标题勘误自动改写；
- 活动名称和人工提供的来源说明保留在内部来源字段，不要求在沉浸式页面逐项显示来源标签；
- 正式迁移时，标题依据进入单一参考或术语来源；被实际采用的剧目再进入唯一运行时内容源，不能让参考表和 `src/data/productions.ts` 同时成为剧目事实源。

### SET-02｜标题参考与运行时 `Production` 的关系

- 状态：待正式采纳
- 规划结果：活页剧目与原创剧目作为两个并存来源分别维护，再通过唯一索引向场次、页面、搜索和票务提供统一的 `Production`；只有经过内容选择并补齐必要字段的活页项目进入运行时
- 适用范围：剧目策划、`Production` 来源分类、场次编排、双时间层引用、列表与详情页、搜索和票务衔接
- 不包含：一次性把 13 条标题全部写入运行时、生成空详情页、删除现有原创剧目或让消费者维护两套剧目逻辑
- 正式迁入目标：`BP-FND-DOMAIN`、`BP-CNT-CORE`、`BP-MOD-PROGRAMS`、候选剧目注册表

#### SET-02 采用边界

- 被采用的活页标题使用 `SET-01` 已冻结的 `productionId`，补齐当前阶段所需剧目字段，再由一个或多个 `Performance` 引用；
- 未被采用的标题只作为文案、档案或历史剧目构思参考，不生成页面、搜索结果、票务入口或空 `Production`；
- `Production` 使用 `sourceKind: 'folio' | 'original'` 标识来源类别。现有六项原创剧目保留稳定 ID 和当前内容并进入 `original` 分区，允许在未来阶段原位修正；
- 表站可以引用 `folio` 或 `original` 剧目；里站只允许引用 `folio` 剧目。该规则只约束来源类别，不表示每项活页剧目已经进入任一时间层的场次；
- 活页与原创由各自源模块维护，并在唯一索引中合并为平坦的运行时注册表。页面、场次、搜索和票务只消费统一注册表，不按来源复制实现；
- 里站来源限制由数据或构建验证机械检查，不能依靠命名习惯或人工浏览推断。

### SET-03｜三语标题与后续 i18n 的关系

- 状态：待正式采纳
- 规划结果：把中文、英文版本和日文版本名称作为三项已提供标题形式保存，但不把它们误写成当前九个国家版本的完整翻译覆盖
- 适用范围：术语数据、页面标题、搜索索引、跨国家版本对应和未来翻译范围清单
- 不包含：自动把英文版本名称同时批准为维多利亚与哥伦比亚发布内容，或用中文标题静默填充正式外语页面
- 正式迁入目标：`BP-I18N-TERMS`、`BP-CNT-CORE`

#### SET-03 语言映射规则

- 中文标题作为 `zh-CN` 来源形式，日文标题作为 `ja-JP` 来源形式；`English` 列先保存为未区分地域的英文版本来源形式 `en`；
- 维多利亚 `en-GB` 与哥伦比亚 `en-US` 可以在各自翻译开发中引用同一英文版本标题，但仍须分别纳入目标版本范围并通过人工审核，不能因存在 `en` 记录自动获得发布资格；
- 其他国家版本仍须建立各自批准标题。开发期缺失遵守“目标 locale → `zh-CN`”回退，正式发布不得保留回退标题；
- 中文、英文和日文标题字段均只保存标题正文，不包含 `《》`、`『』` 或其他包围书名号；组件不自动添加书名号，具体正文段落若因语法需要使用标点，由该段文案自行负责，不回写标题数据；
- 搜索索引只收录已经批准的标准形式和搜索别名。三语并列记录不授权一个国家版本跨语言返回其他版本内容。
- 各国家版本的剧目详情按 `folio` 与 `original` 分区维护，再由国家版本完整包合并为统一的 `ProgramContent.productions`。分区只降低维护耦合，不改变消费者接口；
- 语言包只为运行时剧目维护完整详情。被采用的活页剧目使用本目录提供的中文、英文和日文标题，标题以外的测试字段才允许按阶段要求由 AI 补写；
- 13 项稳定 ID 与三语标题可以完整保存在标题参考或术语来源中，但不得因此要求每种国家版本提前制作未采用剧目的简介、主创或页面内容。

### SET-04｜由标题扩写剧目详情的创作边界

- 状态：待正式采纳
- 规划结果：标题可以作为剧目概念和详情文案的创作起点，但所有扩写内容都作为概念站创作单独管理，不反向写入标题来源
- 适用范围：剧目简介、类型、宣传语、主创、时长、观演提示、视觉方向和历史演出文字
- 不包含：把智能体推演写成活动原文、要求访客侧逐段标注来源，或为尚未选用的全部标题批量生成低质量详情
- 正式迁入目标：`BP-CNT-CORE`；逐项创意候选进入 `docs/drafts/creative/`

#### SET-04 最小创作原则

- 只为确实服务当前页面或场次的标题创作完整内容，不为填满目录批量生成同质化剧目；
- 标题来源、人工提供的事实和本站扩写内容在作者侧保持可区分，访客侧仍遵守统一的沉浸式呈现与页脚声明；
- 标题暗示的地域、体裁、人物或剧情只能作为创意线索。除非另有依据，不写成活动已经确认的设定；
- 同一标题若被表站复排或被里站保存，可以共享稳定身份；只有具体版本确实存在不同内容时，才使用显式版本或关联字段，不复制两个无关 `Production`。
- `sourceKind = folio` 只表示标题及来源类别；本站补写的简介、主创、场馆与演出记录仍是概念站内容，不得因来源字段被误写成活动官方事实。
