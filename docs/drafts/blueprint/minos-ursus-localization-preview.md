- 目的：以米诺斯现代希腊语和乌萨斯俄语验证当前双时间层网站对新文字系统、完整本地化包、国家版本选择器、票面导出和等价功能的可持续扩展能力

## 正文

### SET-01｜构建范围与分切顺序

- 状态：待正式采纳
- 规划结果：在保留炎国默认展示和正式发布边界的前提下，将技术预览依次扩展为四语言和五语言；每种新语言独立实现、验证和提交
- 适用范围：`showcase / preview / release` 构建上下文、静态路由、国家版本选择器、等价页面切换及阶段验证
- 不包含：不改变根路径 `/`、炎国首发优先级或 `releaseEditionIds = ['yan']`
- 正式迁入目标：`BP-I18N-CORE`、`BP-FND-CORE`、`BP-QLT-STAGES`

#### SET-01 规划正文

- 国家版本沿用已确认注册值：米诺斯为 `editionId=minos`、`routePrefix=min`、`locale=el`、本国语名称 `Μινωικά`；乌萨斯为 `editionId=ursus`、`routePrefix=urs`、`locale=ru`、本国语名称 `Урсусский`。
- `showcase` 始终只生成炎国，根路径仍进入 `/yan/`；`release` 仍只读取炎国批准集合。本阶段不得把 AI 译文加入正式发布集合或标记为 `formal`。
- 代码开发遵循“一次一个国家版本”：
  1. 先完成共享解析、交互与 Unicode 票面前置，再接入米诺斯完整包，将 preview 从三语言扩展为炎国、东国、哥伦比亚、米诺斯四语言；
  2. 四语言严格预览独立通过后，再完成乌萨斯完整包，将 preview 扩展为最终五语言；
  3. 最后只进行五语言跨版本集成与阶段收口，不把两个语言压缩成一个不可回退的源码切片。
- 选择器保持已有三项顺序并顺次追加新项：`yan → higashi → columbia → minos → ursus`。该顺序避免重排已经验证的入口，不按混合文字字母排序。
- 每个国家版本生成相同页面集合。以当前每版 31 页为基线，四语言 preview 应生成 `1 + 4 × 31 = 125` 个 HTML 页面，最终五语言 preview 应生成 `1 + 5 × 31 = 156` 个；验证器应由快照和路由集合推导数量，不把数字作为第二份长期配置。
- 国家版本切换保持同一世界、同一稳定页面和既有标签页状态；表站票篮、冻结票务结果与里站污染状态继续跨国家版本保持，搜索词不携带。

### SET-02｜完整语言包与可维护解析边界

- 状态：待正式采纳
- 规划结果：米诺斯和乌萨斯各自拥有与现有版本相同的显式完整包；内容组织、严格解析和源修订不随语言数量增加而复制业务逻辑
- 适用范围：`src/data/localized/`、本地化 schema、包注册、记录级作者诊断、翻译源修订和 locale 校验
- 不包含：不建立动态目录扫描、运行时 glob、中文显示名程序键、第四个构建 profile 或翻译进度数据库
- 正式迁入目标：`BP-I18N-CORE`、`BP-I18N-TERMS`、`BP-CNT-CORE`

#### SET-02 规划正文

- 两个新版本分别建立 `src/data/localized/minos/` 与 `src/data/localized/ursus/`，每个目录固定提供：
  - `site.ts`：页面元数据、导航、页脚、机构与页面正文；
  - `messages.ts`：筛选、搜索、污染、票务、焦点和降级反馈；
  - `programs.ts`：地点、场次与票务分区显示内容，不保存完整剧目正文；
  - `productions/folio.ts` 与 `productions/original.ts`：分别保存活页和原创剧目内容；
  - `productions/index.ts`：合并两类剧目为统一接口；
  - `archive-projection.ts`：里站等级 `3` 按页面职责切换的可见叙事投影；
  - `index.ts`：唯一完整包入口。
- 新语言不得复制炎国和哥伦比亚当前“原创剧目先写入 `programs.ts`、再由 `original.ts` 反向导出”的过渡结构。接入前以不改变运行时内容的机械重排统一现有包职责，让所有语言使用上述同一目录语法；该重排与译文提交分开验证。
- AI 译文必须覆盖所有访客或辅助技术可感知内容，包括元数据、导航、页脚、按钮、表单、ARIA 文本、搜索、状态、错误、无脚本或初始化失败反馈、票务流程、存单、票面、打印和污染投影。稳定 ID、ASCII URL、LMD、枚举和纯数值不翻译。
- AI 现代希腊语和俄语只具备 `preview` 资格。译文是否自然、专名是否最终确定、世界观语气是否适合正式发布均不在本阶段验收；但不得用炎语 fallback、空字符串或乱码掩盖缺失。
- 作者侧允许 typed partial records 逐项准备译文，并由不可部署诊断入口报告 `sourceLocale`；三个可部署 profile 均通过同一严格解析边界拒绝缺失、旧译和回退，诊断入口不能生成页面。
- 源修订按当前 snapshot 内稳定记录和真实消息组计算，不为米诺斯、乌萨斯继续复制现有四个整包 hash。集合外实体或无关消息变化不得使整种语言失效。
- locale 内容检查对米诺斯和乌萨斯禁止意外汉字，并分别要求完整包各主要类别存在有意义的 Greek / Cyrillic 脚本文字；专名、地点、编号和 LMD 可以保留拉丁字母，因此不得要求每个字符串只含单一文字系统。
- 搜索仍使用 NFKC 和当前 locale 小写归一化，不增加分词库。本阶段以索引和查询采用同一规范形式时能够命中为通过，并验证希腊文大小写与词尾 sigma、俄文大小写。当前不自动去除希腊文重音，不把俄文 `ё` 与 `е` 合并，也不承诺词干还原或形态学搜索。

### SET-03｜国家版本选择器、字体与响应式显示

- 状态：待正式采纳
- 规划结果：现有原生披露式选择器无脚本可用，并在五项、俄文和希腊文下保持可读、可聚焦和不溢出
- 适用范围：国家版本选择器、页面根语言、系统字体、头部/导航/票务入口和最低 320px 布局
- 不包含：不使用 Web Font、原生 select、通用菜单库、自制 ARIA menu 或按主观偏好重做全站视觉
- 正式迁入目标：`BP-I18N-CORE`、`BP-FND-EXPERIENCE`

#### SET-03 规划正文

- 复用已存在的米诺斯与乌萨斯正方形透明单色徽记，通过显式 `editionId -> asset` 映射显示；选择器可见文字只使用 `Μινωικά` 与 `Урсусский`，每项分别标记 `lang="el"` 与 `lang="ru"`。
- 选择器的可访问名称同时表达当前本国语名称与“选择国家版本”动作，不能由泛化 aria-label 覆盖可见当前值；单语言 showcase 也必须读出“当前版本 + 炎语”。
- 保留 `<details> / <summary> + 普通链接`。五项列表在 320px 宽度与常见窄屏高度内可滚动到达，Escape、外部点击、焦点返回、无 JavaScript 导航和里站单次污染事件保持不变。
- 为 `html:lang(el)` 与 `html:lang(ru)` 添加常见平台系统 serif / sans 回退序列；首先复用非 CJK 系统字体，不因主观审美拆分字体包。只有实机发现缺字、行高或标点问题时才调整顺序和间距。
- 使用真实运行时最长字符串压力测试品牌头部、导航、选择器、标题、场次卡、场馆、筛选、搜索、票务按钮、存单、页脚和污染投影。必要时允许头部工具区与票务入口在窄屏分行，不使用 `overflow-x: hidden` 掩盖裁切。
- 不为尚未进入 preview 的国家版本预写字体兼容规则；本阶段结论也不能外推为德文、波兰文、意大利文或英式英文已完成验收。

### SET-04｜共享交互与 Unicode 票面等价性

- 状态：待正式采纳
- 规划结果：五种语言不仅页面文字完整，也能完成相同搜索、票务、污染、切换、下载、打印、键盘和降级任务
- 适用范围：本地化解析、搜索、国家版本选择、票务阶段焦点、纪念票 SVG/打印、三级投影公告和根集合基础正确性
- 不包含：不改变票务概率、污染概率、叙事方向、正式内容、票面艺术风格或搜索产品范围
- 正式迁入目标：`BP-I18N-CORE`、`BP-MOD-SEARCH`、`BP-MOD-TICKETING`、`BP-MOD-ARCHIVE`、`BP-CNT-CORE`、`BP-MOD-TERRA-TIME`

#### SET-04 规划正文

- 在每个新增语言进入可部署 preview 前，落实 `docs/drafts/recommendations/stage-code-audit-defense.md` 中的共享前置及该语言对应的字体、长文本与 Unicode 验收要求：
  - `REC-01` 的可执行 strict fallback 与本地化 build-scope 解析；
  - `REC-02` 的记录级源修订和 typed partial 作者诊断；
  - `REC-03` 的根集合世界归属与统一泰拉日期结构校验；
  - `REC-04` 的票务焦点、搜索初始化失败降级、三级投影公告和选择器可访问名称；
  - `REC-05` 的共享 Unicode 票面基础；米诺斯切片完成希腊文专项，乌萨斯切片再完成俄文专项。
- 搜索使用唯一默认不可用块：脚本完整解析索引和消息、绑定事件成功后，才原子启用表单并隐藏降级；无 JavaScript 和初始化失败不显示两份相同警告，也不保留伪可用提交按钮。
- 票务阶段转换后，焦点进入由当前本地化动态标题命名的区域或标题本身；live 状态只简短报告具体分支。成功、普通失败、网络波动、优先通道与重试在两种新语言中保持同一状态事实。
- 三级污染投影不改变页面 H1 的任务主次，不偷取焦点，也不把整段请柬作为 live region 朗读；只使用短本地化状态公告表达投影出现。
- 纪念票 SVG 的标题、地点和日期采用确定性受控换行与字号下限：按 Unicode 字素或合法语言断点处理，不按 UTF-16 下标拆字符；不得破坏日文无空格文本、俄文长词或带组合符的希腊文。
- 关键信息不能以省略号静默删除。版面达到字号下限后使用额外行或受控区域；完整场次、地点、分区和价格同时保留在屏幕存单、SVG 可访问替代、下载和打印结果中。
- 根集合成员与焦点必须匹配 `Performance.world`；effective、previous、固定网站时钟和未来 provider 输出统一验证 TerraDateTime 的结构范围。两项修正不得改变当前有效数据的页面分类。

### SET-05｜分切验收与最小质量门禁

- 状态：待正式采纳
- 规划结果：每种语言独立证明完整，最终五语言 preview 具有可复现的静态和浏览器证据，且不重复运行相同门禁
- 适用范围：质量调度、内容/locale/状态验证、preview 构建产物及代表性浏览器冒烟
- 不包含：不建立全语言乘全路由乘全视口截图矩阵，不把技术预览通过等同于人工译审或正式发布
- 正式迁入目标：`BP-QLT-STAGES`、`BP-I18N-CORE`

#### SET-05 规划正文

- 语言内容切片顺序为：共享解析、包职责、世界/日期校验前置 → 不依赖目标译文的共享交互与 Unicode 票面基础 → 米诺斯完整包、希腊文字体与四语言集成验收 → 乌萨斯完整包、俄文字体与五语言集成验收 → 最终五语言交叉冒烟和不重复门禁收口。每个切片都遵守项目级蓝图/代码双分支闭环，不把多个源码切片压缩为一个提交。
- 日常最小检查按改动能力调度：本地化包、版本集合、源修订和 locale 规则至少运行项目类型检查、相关 lint/format、内容验证和 `validate:locales:preview`；纯译文修正不无理由运行两次全局构建。
- 阶段收口只执行一次完整质量门禁，随后追加一次 preview 专属内容/locale、build 和 output 链；补充链不得再次运行 `quality:full` 或重复默认 showcase build。
- 源码与产物的远端载入防回归应覆盖常见自动请求、`sendBeacon`、`EventSource`、远端 iframe/object/embed 及 CSS 远端 URL，不误伤普通外部导航链接；该门禁用于受控仓库防回归，不声称证明任意混淆代码安全。
- 四语言中间构建机械验证 125 个页面；最终五语言构建机械验证 156 个页面、`html lang`、canonical、robots、等价切换链接、表里搜索隔离、票务输入和里站不可购票路径。页面数由构建集合推导。
- locale 验证必须证明米诺斯和乌萨斯无 fallback、无旧译、无空记录、无意外汉字，并含对应文字脚本；不能以 JSON 字符串非空代替功能等价。
- 代表性浏览器矩阵至少覆盖：
  - 一个桌面表站、一个不大于 320px 的窄屏表站票务流程和一个不大于 320px 的窄屏里站；
  - 日文、俄文、希腊文各一个最长页面外壳或头部样本；
  - 国家版本选择器的键盘、Escape、焦点返回和无 JavaScript 链接；
  - 一个无 JavaScript 表站、一个无 JavaScript 里站，以及一个“JavaScript 存在但搜索初始化失败”的页面；
  - 票务主要分支的焦点、俄/希下载 SVG 和打印边界；
  - 污染升级、减少动态效果与可靠返回表站。
- 响应式通过条件同时检查页面 `scrollWidth`、关键元素边界和当前聚焦元素是否仍在视口内；没有横向滚动条或截图看似完整不能单独作为通过证据。
- 自动浏览器检查只证明任务、边界和状态；译文质量、品牌审美和心理惊悚效果仍由人工另行验收，不通过截图相似度自动批准。
- 新增、重命名或删除功能源码时同步维护 `docs/blueprint/traceability.json`；架构、README 与开发指南只在最终运行时事实变化后更新，不把一次性执行日志写入长期文档。

## 待解决问题

无。用户已明确指定本阶段同时实现米诺斯语与乌萨斯语技术预览，并允许 AI 翻译；“一次一个国家版本”通过两个顺序切片落实，不需要新增产品选择。
