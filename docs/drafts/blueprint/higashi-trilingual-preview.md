# 东国语三语言预览与里站节目替换蓝图草稿

- 文档类型：蓝图草稿
- 状态：候选，待人工审核
- 规划效力：无；仅供本阶段讨论，不约束正式蓝图、源码、运行时内容或发布集合
- 分析基线：当前 `BP-I18N-CORE`、`BP-CNT-CORE`、`BP-MOD-PROGRAMS`、`BP-QLT-STAGES`，炎国与哥伦比亚双语言实现，以及 `docs/drafts/blueprint/production-title-catalog.md`
- 目的：在不改变炎国正式发布范围的前提下，以东国语技术预览验证第三语言接入成本、假名排版韧性、全站翻译覆盖、三选项国家版本选择器和里站测试内容替换能力
- 非目标：把东国语或哥伦比亚语批准为正式发布内容；审核 AI 译文准确性；把活页标题目录迁入正式蓝图；限制活页剧目只能用于里站；重做页面路由、双时间层状态机或既有视觉体系

## 正文

### SET-01｜炎国、哥伦比亚与东国三语言开发预览

- 状态：待正式采纳
- 规划结果：开发预览从炎国与哥伦比亚双语言扩展为炎国、哥伦比亚与东国三语言；三者生成等价的表站和 1091 里站页面，正式构建仍只发布炎国
- 适用范围：国家版本注册、预览构建集合、静态路由、本地化内容包、页面元数据、搜索、筛选、票务、污染反馈、下载与打印文字、国家版本切换
- 不包含：东国语人工译审、东国语正式发布资格、增加第三种构建模式或改变根路径 `/` 指向
- 正式迁入目标：`BP-I18N-CORE`、`BP-QLT-STAGES`

#### SET-01 预览范围与内容完整度

- `releaseEditionIds` 继续只包含 `yan`；开发预览集合按既有产品顺序包含 `yan`、`higashi` 与 `columbia`，不得另建与之含义重复的 locale 数组；
- 东国继续使用现有注册值 `editionId = higashi`、`routePrefix = hig`、`locale = ja-JP`、`badgeCode = HIG` 与本国语言名称 `極東語`，不从任何显示文字推导路径或 ID；
- 东国语内容可以由 AI 翻译生成，只用于架构与视觉测试。它必须覆盖炎国基线中所有访客或辅助技术可感知文字，包括元数据、导航、页脚、按钮、表单、状态、错误、无脚本反馈、ARIA 文本、搜索、污染、票务、结算和票面，不允许把页脚或系统消息留作中文；
- 最终三语言预览对三个构建内国家版本都要求记录完整且零回退。该机械完整度只证明结构可用，不表示哥伦比亚语或东国语已经通过人工译审；
- 三个预览国家版本必须在各自表站与里站实现当前 active 蓝图以及本阶段正式迁移后蓝图所要求的同一组功能、元素、失败路径和无脚本降级。开发预览身份不能成为省略搜索、筛选、票务、污染、选择器、下载、打印、无障碍或响应式适配的理由；
- 表站与里站的国家版本切换保持当前世界、稳定页面和业务状态；搜索词不跨语言携带，搜索索引仍按 `{editionId}:front` 与 `{editionId}:archive:1091` 隔离；
- 增加东国语不得复制页面树、领域事实、票务状态机、污染状态机或搜索实现。页面数量与链接期望从构建集合及领域数据推导，不在验证脚本中写死“双语言”或固定页面总数。

### SET-02｜东国语选择器与假名排版验证

- 状态：待正式采纳
- 规划结果：沿用现有原生披露结构增加 `極東語` 选项，并以真实三语言页面检验日语假名、汉字和全角标点在双时间层视觉系统中的排版稳定性
- 适用范围：页眉国家版本选择器、系统字体、文本换行、卡片与详情布局、表单控件、搜索结果、页脚、票务界面、纪念票及窄屏响应式表现
- 不包含：Web Font、通用菜单库、竖排日文、罗马字副标题或针对尚未开发语言的预先适配
- 正式迁入目标：`BP-I18N-CORE`、`BP-FND-EXPERIENCE`、`BP-QLT-STAGES`

#### SET-02 选择器与字体规则

- 国家版本选择器继续使用 `<details>`、`<summary>` 和普通链接；三个选项分别显示自己的本国语言名称和正方形临时标识，东国标识使用显式 `HIG`，当前项顺序不随所选语言变化；
- 无 JavaScript 时三个选项仍可导航；增强脚本只维持 `Escape`、焦点返回和外部点击关闭。里站切换继续只触发一次 `archive-locale` 污染判定；
- `ja-JP` 使用系统日文字体栈和 `:lang(ja-JP)` 局部适配，不引入网络字体。字体优先级应覆盖常见 Windows、macOS、iOS 与 Android 系统日文字形，并保留通用 sans-serif / serif 回退；
- 日文正文使用正常的日语换行与禁则处理，不用固定高度、强制单行或省略号隐藏关键信息掩盖溢出。只有标识码、日期或明确不可拆分的短字段可以保持单行；
- 只根据可部署页面中观察到的缺字、假名行高、全角标点悬挂、标题断行、控件截字或横向外溢调整字体顺序、字号、行高、间距和局部网格，不因主观偏好重做已通过验收的双站视觉语法；
- 代表性检查至少覆盖表站首页、表站演出列表与详情、表站票务、里站首页、里站演出列表与详情、里站搜索以及三语言选择器，并在 320、390、768 与 1280 CSS 像素视口检查。修正应作用于可复用布局模式，不按单页译文添加特例。

### SET-03｜里站活页剧目与九次演出测试矩阵

- 状态：待正式采纳
- 规划结果：本阶段让 1091 里站场次改用四项 `folio` 活页剧目，同时把既有六项原创剧目完整保留在 `original` 分区，并建立九次可复用 `Performance`，验证稳定内容 ID、多语言内容包、列表、详情和搜索在内容替换后的维护成本
- 适用范围：里站本季与历史演出、场次详情、剧目详情、搜索索引、三语言 `ProgramContent` 及里站不可购票反馈
- 不包含：替换表站三个既有剧目；将四项标题永久限制为旧剧团资产；批准全部 13 项活页标题；改变里站全部场次不可购买的契约
- 正式迁入目标：`BP-CNT-CORE`、`BP-MOD-PROGRAMS`；标题正文继续引用 `docs/drafts/blueprint/production-title-catalog.md`

### SET-04｜第三语言接入与内容替换的最小结构修正

- 状态：待正式采纳
- 规划结果：保留显式、类型化本地化注册，同时把每种语言的三个内容分区收束为一个完整包入口，并让验证从构建集合和稳定事实自动推导，避免第三种及后续语言重复修改消费者
- 适用范围：本地化 schema、各语言目录入口、统一解析器、预览集合、locale/状态/构建验证、地点国家归属与节目次数验证
- 不包含：运行时动态加载、文件系统自动扫描、Content Collections 迁移、翻译管理平台或为每个国家版本复制解析器
- 正式迁入目标：`BP-I18N-CORE`、`BP-CNT-CORE`、`BP-QLT-STAGES`

#### SET-04 内容包与注册边界

- `site`、`programs` 与 `messages` 继续按真实内容责任分文件；每个国家版本目录增加一个完整内容包入口，统一解析器每增加一种语言只导入并注册一个包，不再重复三组导入和对象拼装；
- 语言无关的剧目事实按 `folio` 与 `original` 分区维护并由唯一索引合并；各国家版本的剧目详情使用相同分区，再合并为统一的 `ProgramContent.productions`。组件、搜索、票务和场次不读取来源专用接口；
- 完整包的公共类型由中立 schema 层拥有，炎国仍是字段形状基线，但东国与哥伦比亚不得通过复制解析逻辑建立平行类型。注册保持显式，避免使用难以审查的动态路径或 glob 自动发现；
- 构建集合仍是路由、选择器、搜索和验证的唯一输入。增加 `higashi` 后，不应逐页增加条件分支，也不应出现 `if editionId === higashi` 的通用业务路径；确属目标文字系统的验证规则可以按 locale 明确配置；
- locale 完整度验证继续检查零回退、非空内容及地点、场次、剧目的精确稳定 ID。哥伦比亚的无汉字检查不能套用于日语；东国语采用完整形状、零回退、代表字段含日文假名的轻量检查及人工页面抽查，不用“不得含汉字”之类错误规则；
- 跨语言票篮与污染状态验证应覆盖所有预览国家版本，不固定只比较炎国和哥伦比亚。构建产物验证按实际构建集合推导等价链接、页面、`lang`、canonical、robots 与搜索隔离；
- 验证从当前构建集合和 active 蓝图要求推导功能矩阵，证明三个语言版本均生成相同页面类别并具备对应时间层的搜索、筛选、票务或不可购票、污染、选择器、状态恢复、下载、打印、键盘、无脚本和响应式路径；不得用只校验字符串完整度代替功能等价性；
- 增加地点国家字段后，验证九次里站演出按稳定数据得出：湖中至宝为莱塔尼亚一次、维多利亚一次；一百零一日为维多利亚两次；欢欣鼓舞为叙拉古、莱塔尼亚、维多利亚各一次；凯旋颂为叙拉古、莱塔尼亚各一次。
