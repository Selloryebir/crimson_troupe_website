# 草稿工作区

`docs/drafts/` 保存尚未获得人工采纳的提案，以及获准执行但完成后应删除的一次性计划。草稿不约束正式产品或源码，不进入 `docs/blueprint/traceability.json`，也不因所在分支或原型可运行而获得正式效力。

正式功能的蓝图草稿与计划在对应 `dev_feature_<slug>` 编写；必须通过原型判断的创意、专属研究和实验实现位于独立 `dev_experiment_<slug>`。完整分支门禁见 [`../guides/git-branch-workflow.md`](../guides/git-branch-workflow.md)。

## 目录职责

| 目录                                            | 内容                           | 正文对象 |
| ----------------------------------------------- | ------------------------------ | -------- |
| [`blueprint/`](blueprint/README.md)             | 新蓝图或 active 蓝图的候选修改 | `SET-*`  |
| [`recommendations/`](recommendations/README.md) | 宏观方向、下一步行动和候选方案 | `REC-*`  |
| [`creative/`](creative/README.md)               | 文案、叙事、表现和内容创意     | `CRE-*`  |
| [`plans/`](plans/README.md)                     | 已有正式契约下的一次性实施顺序 | `PLAN-*` |

普通功能开发不读取本目录；只有规划、草稿评审、获授权计划、正式迁移或用户明确指定草稿时才读取。四个子目录 README 是长期格式入口，清理实际草稿时保留。

## 公共格式

每份实际草稿在标题和元数据后使用三个顶层部分：

```markdown
- 文档类型：
- 状态：
- 规划效力：
- 分析基线：
- 目的：
- 非目标：

## 正文

## 待解决问题

## 正式拆分与影响定位
```

固定字段没有内容时写“无”或“原稿未说明”。正文对象标题携带所属 `SET-*`、`REC-*`、`CRE-*` 或 `PLAN-*` ID；类型专属字段只在上表对应 README 维护，不在本文件复制。

### 待解决问题

```markdown
### OPEN-01｜问题名称

- 状态：待回答 / 已回答，待人工确认
- 所属规划或关联正文：
- 问题：
- 影响：
- 建议答案：
- 合并动作：
```

- `OPEN-*` 保存仍需人工选择的事项；建议和创意分别使用 `REC-OPEN-*` 与 `CRE-OPEN-*`；
- `TEST-*` 只保存方向已明确、但参数必须由可部署版本验证的事项；
- 智能体可以填写建议答案，只有人工明确要求后才能把答案融入正文并删除对应问题；
- 新结论与正文冲突时直接修正唯一正文及其引用，不并列保存旧说法。

### 正式拆分与影响定位

该部分只定位迁移对象，不复制正文：

| 来源 ID                     | 目标位置                        | 影响性质               | 确认后的动作             |
| --------------------------- | ------------------------------- | ---------------------- | ------------------------ |
| `SET-*` / `REC-*` / `CRE-*` | 仓库根目录相对路径或正式蓝图 ID | 新增、修正、替代、删除 | 迁移、核对并删除草稿来源 |

定位表示候选影响，不要求每个目标产生修改。表格按业务主键、流程按稳定状态、分项档案按实体 ID 核对；不为句子建立永久编号，也不保存一次性覆盖报告。蓝图与源码的最终关系仍只由追踪表拥有。

## 人工门禁与生命周期

两个授权彼此独立：

1. **融入草稿正文：** 只更新临时材料，不授权修改正式蓝图或源码；
2. **正式迁移：** 人工明确提出迁移后，才允许将已选内容写入正式责任目录。

```text
提出问题 -> 建议答案 -> 人工确认并融入正文 -> 删除已解决问题
-> 人工要求正式迁移 -> 迁入唯一责任方 -> 核对完整 -> 删除草稿来源
```

优先级、推荐结论、计划批准、构建成功和原型可运行都不能替代上述门禁。一次性计划只能编排 active 蓝图已经允许的工作；自动执行及 Git 权限以用户当次授权和 [`plans/README.md`](plans/README.md) 为准。

## 迁移与删除

按信息责任迁移：

- 稳定目标、行为和内容规则进入 `docs/blueprint/`；
- 官方原文、来源身份与权利记录进入 `docs/sources/`，分析进入 `docs/research/`；
- 非运行时作者资料进入 `docs/project/`，工程事实进入 `docs/architecture/`；
- 运行时正文和结构化内容进入 `src/data/` 或未来唯一的 `src/content/`，素材进入 `src/assets/`。

迁移在一次完整改动中完成：写入目标、核对对象与关系、更新必要索引和追踪、确认无冲突或重复事实源，再删除已迁移正文与定位。OPEN/TEST 不能作为既定契约迁入。

只有正文已全部迁移、拒绝或作废，且没有有效 OPEN/TEST 或未完成定位时，才删除整份实际草稿。正文为空但问题仍有效时继续保留，或先无损移交问题。Git 已保存历史，不另建迁移日志或已完成摘要。

草稿文件使用小写英文 kebab-case；仓库路径使用根目录相对形式。草稿之间通过完整路径和稳定 ID 引用，不复制正文；不为普通讨论增加审批数据库、状态台账或专用校验器。
