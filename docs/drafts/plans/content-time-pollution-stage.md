#### PLAN-01 切片约束

- 每个切片按长期双分支流程独立完成 `dev_code` 提交、推送和回到 `dev_blueprint` 的状态收口；不得把两个切片压缩为一个代码提交；
- `CTX-01` 只建立与当前内容等价的解析基础，不提前改页面表现；`VIEW-02` 与 `FLOW-03` 分两步迁移消费者，但当前根集合保持不变，因此中间提交不得产生可见集合差异；
- 当前含日期或地点片段的 `performanceId` 作为冻结历史身份保留，不批量更名或改变 URL；新 ID 不从可变字段生成；
- 当前全部运行时内容保持未批准预览，不为了验证 `release` 创建虚假批准。摘要失效与批准成功使用隔离夹具验证；
- 流动时间接口在 `CTX-01` 只实现固定提供者及可替换调用边界。任何锚定参数、换算算法、计划构建或客户端实时流动均超出本计划；
- 不录入 5 + 12 场次，不借架构迁移重写现有剧目简介、AI 翻译、艺术资产或票务流程；发现现有内容错误时只修复会阻断本计划验收的高置信缺陷；
- 隔离夹具复用现有 Node 校验脚本和可注入的纯函数边界，不为本阶段引入测试框架、数据库、CMS、第二套内容树或自由构建配置矩阵；
- 新增聚焦检查不得与 `quality`、`build` 或 `verify` 重复执行相同门禁。日常切片使用相称检查；最终跨层闭环只执行一次完整 `verify`，另补三语言预览独有构建与产物检查；
- 每个切片完成时只更新本计划对应状态和真实追踪关系，不在正式蓝图写测试日志或实现快照。

#### PLAN-01 最终闭环

最终切片实现后执行一次跨层完整门禁，并补充以下不重复验收：

1. 默认 `showcase` 炎国双时间层构建、三语言 `preview` 构建及各自产物闭包；
2. 显式 `release` 在没有批准内容时以预期资格错误停止，不将该预期停止误作工具故障；
3. 代表性桌面与不大于 500px 窄屏下检查首页、场次列表与详情、搜索和票务状态；视觉没有改动时不重复全站艺术验收；
4. 浏览器验证里站进入、一次内部导航、第三次起升级、刷新、搜索、国家版本切换、返回表站和新标签页；
5. 对实际变更运行一次追踪与文档漂移检查，更新架构“当前实现快照”、根 README 和开发命令指南，随后在 `dev_blueprint` 删除本计划并完成阶段闭环。
