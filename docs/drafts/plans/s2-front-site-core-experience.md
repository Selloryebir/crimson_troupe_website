## 正文

### PLAN-02｜S2 炎国表站核心体验

- 状态：已批准执行，待人工授权源码开发
- 正式依据：`BP-FND-CORE`、`BP-FND-DOMAIN`、`BP-FND-EXPERIENCE`、`BP-FND-EXTENSION`、`BP-MOD-PROGRAMS`、`BP-MOD-SEARCH`、`BP-MOD-TICKETING`、`BP-CNT-CORE`、`BP-I18N-CORE`、`BP-QLT-STAGES`
- 范围：炎国表站首页、本季演出、历史演出、场次详情、剧目详情、剧团、表站搜索与票务占位页；表站页面所需的类型化内容、共享或表站组件、样式、渐进增强、元数据和追踪映射
- 完成条件：不进入里站时，浏览者能够从 `/yan/` 发现演出、区分场次与剧目、理解剧团、在表站范围内搜索并到达明确的票务状态；页面在目标视口、键盘、减少动态效果和无 JavaScript 条件下保持正式蓝图规定的任务与降级路径

#### PLAN-02 执行前提

1. 本计划只在 `dev_blueprint` 建立。同步至 `dev_code` 后仍须等待人工明确授权，才能修改功能源码；计划获准不等同于提交、推送、合并或发布授权。
2. S1 已建立的国家版本注册、稳定路由、`Production` / `Performance` 领域边界、canonical、robots 和双站分离是实施基线，不在 S2 重新设计或建立并行实现。
3. 开始每个切片前对实际候选源码运行 `npm run blueprint:where -- <路径...>`；下文路径只用于影响定位，不替代运行时反查和实际消费者判断。
4. active 正式蓝图始终高于本计划。若实现必须改变路由、领域语义、搜索范围、票务边界、内容口吻或 S2 非目标，应停止扩大改动并返回 `dev_blueprint` 处理。
5. 只复用仍符合正式目标的 S1 结构、内容和样式。不得为了“做出完整页面”虚构未经批准的历史场次、机构事实、人物经历或外部素材权利。

#### PLAN-02 实施边界

- **只完善表站：** S2 不扩写 1091 里站页面、内容或年代视觉。修改共享页头、页脚、基础令牌或数据时必须回归里站等级 `0` 的现有导航、返回、声明、元数据和视口安全，但不得借机实施 S3。
- **保持现有路由：** 使用 S1 已生成的稳定 URL，不新增别名路由、单页锚点入口或标题派生路径；只有 `/yan/` 保持 `index,follow`，其余页面继续 `noindex,follow`。
- **内容先于装饰：** 页面必须先建立清晰标题、摘要、主要内容、状态和下一步链接，再添加承担品牌、剧目或场景叙事功能的视觉。装饰不能代替内容，也不能成为完成任务的前提。
- **表站视觉方向：** 采用现代、明亮、权威、相对扁平的剧团官网表达，通过排版、图像或自有图形、留白、色彩和克制动效建立层级；不复刻参考网站、游戏界面或特定第三方构图。
- **搜索限于表站：** S2 只为 `yan:front` 生成构建期索引和浏览器内查询，不生成或加载 1091 里站索引。索引只保存稳定 ID、类型、批准文本、别名和目标 URL，不复制完整正文。
- **票务维持占位：** `/yan/tickets/` 继续显示“暂未开票”及有效返回路径；可以完善它与表站视觉和内容语气的一致性，但不建立票篮、价格分支、概率结局、存单或纪念票。
- **单语言发布：** 继续只生成并显示 `yan / zh-CN`。不得建立未发布国家版本页面、选择项、翻译范围清单或回退内容。
- **依赖与资产：** 默认使用已有依赖和项目自有 HTML/CSS/SVG 表达。只有页面结果证明必要且权利、体积与失败路径明确时才引入运行时素材；不为局部视觉引入前端框架或第三方脚本。

#### PLAN-02 内容与数据收口

- 当前三个 `Production` 及其表站 `Performance` 是 S2 的已存在内容基线；允许在唯一来源内补充页面实际需要的展示字段，但不得把场次日期、地点、状态或票务事实移入剧目。
- 页面级机构文案、状态文案和元数据可以使用类型化表站内容源统一维护；只有出现两个以上真实消费者时才抽取，不为每段短文建立配置对象。
- 历史演出若没有经过人工认可的实体数据，使用与剧团运营语气一致的空状态即为有效结果；不得把 1091 场次、搜索样例或装饰性文本伪装成表站历史事实。
- 搜索索引必须从已经发布的表站页面、`Performance` 与 `Production` 派生。搜索别名可以是明确批准的辅助文本，不得成为修改标题、摘要或实体归属的第二来源。
- 外部素材进入 `src/assets/` 前记录来源、许可、署名和使用边界；无法确认权利时使用项目自有图形或保留清晰的内容占位，不阻塞页面结构验收。

#### PLAN-02 渐进增强与样式边界

- 常规导航、列表到详情、返回、票务入口和历史快照入口使用普通链接，不依赖客户端路由、浮层或过场。
- 筛选增强失败时展示完整场次集合；搜索脚本失败或被禁用时搜索页仍显示范围、不可用反馈和正常导航。
- 客户端入口只初始化当前页存在的能力，不恢复 S1 已删除的无条件全模块入口、隐式全局状态或双世界同页切换。
- 移动导航若需要脚本，必须在脚本失败时仍可访问主导航，并处理触控目标、展开状态、焦点和页面滚动；不能只靠 hover 暴露操作。
- 先在现有样式入口中按责任整理。只有表站规则规模、页面加载或多人修改冲突出现实际收益时才拆分文件；拆分后同步追踪，不为形式分层。
- 动效只用于层级、状态或转场反馈，遵守 `prefers-reduced-motion`；减少动态效果不得删除内容、结果或操作。

#### PLAN-02 最终验收矩阵

1. **构建与追踪：** `npm run verify` 通过；全部新增、删除和重命名功能源码具有实际蓝图映射；运行时不读取 `docs/`。
2. **表站旅程：** 首页 → 本季或历史 → 场次详情 → 剧目详情或票务占位可以通过真实链接完成，并能使用浏览器前进、后退和刷新。
3. **内容一致性：** 列表、详情和搜索读取相同稳定实体；场次与剧目字段不混用；空历史不以虚构内容填充。
4. **搜索隔离：** `yan:front` 索引不包含 `/archive/site/1091/`、其他国家版本或未发布页面；结果链接、空状态和失败状态准确。
5. **元数据与索引：** 所有页面保持 `lang="zh-CN"` 和当前稳定 canonical；只有 `/yan/` 为 `index,follow`，其余页面为 `noindex,follow`。
6. **无脚本与键盘：** 禁用 JavaScript 后核心正文、主导航、详情、返回和票务占位仍可使用；搜索显示明确不可用反馈；焦点顺序、名称和状态可理解。
7. **视口与动效：** 检查 320、375/390、768、1024、1280/1440 CSS 像素及更宽桌面；无页面级横向内容丢失、操作遮挡或文本漂移；减少动态效果不损失任务。
8. **双站回归：** 1091 首页、主导航、搜索占位、不可购票页、页脚声明和返回表站仍可直接访问；共享样式或组件没有把里站变成表站换色版本。
9. **范围收口：** 产物不包含第二国家版本、里站正式搜索、污染状态、票篮、交易流程、存单或纪念票；未使用的兼容文件和占位抽象不保留。

#### PLAN-02 停止与回退条件

- 正式蓝图之间出现无法通过实现选择消解的冲突，或 S1 稳定路由与领域边界必须被改变时，停止对应切片并返回 `dev_blueprint`；不在 `dev_code` 用代码选择改写产品契约。
- 页面需要新增重大世界观事实、角色立场、历史场次或来源不明素材时，保留已验证结构并等待内容确认；不以临时文案冒充已批准内容。
- 表站搜索若需要跨世界索引、远端服务、查询记录或大型依赖才能继续，应保持现有可理解降级页并停止扩大实现。
- 单个切片无法通过作用域检查时先修复该切片，不通过继续堆叠页面、关闭检查或保留并行入口掩盖失败。
- 需要撤销未完成切片时只精确回退该切片新增改动，保留此前已验证切片和用户文件；禁止破坏性整库恢复。
