- 文档类型：一次性开发计划
- 状态：已批准执行
- 规划效力：只约束 S5 的实施顺序、范围收口与验收，不覆盖 active 正式蓝图
- 分析基线：已验证的 S4 炎国双站与污染主线；`BP-FND-DOMAIN`、`BP-FND-EXPERIENCE`、`BP-FND-EXTENSION`、`BP-MOD-PROGRAMS`、`BP-MOD-TICKETING`、`BP-CNT-CORE`、`BP-I18N-CORE`、`BP-I18N-TERMS`、`BP-QLT-STAGES`
- 目的：在稳定 `/yan/tickets/` 上实现当前标签页内的表站模拟购票闭环，包括多场次票篮、分区基础价、普通与加价线路、成功/失败/网络结局、重试、成功存单和逐场可下载可打印纪念票

## 正文

### PLAN-05｜S5 表站购票互动

- 状态：已批准执行
- 正式依据：`BP-FND-DOMAIN`、`BP-FND-EXPERIENCE`、`BP-FND-EXTENSION`、`BP-MOD-PROGRAMS`、`BP-MOD-TICKETING`、`BP-CNT-CORE`、`BP-I18N-CORE`、`BP-I18N-TERMS`、`BP-QLT-STAGES`
- 范围：表站未来场次的分区与基础价、票篮、纯状态机、标签页状态适配、票务页面、概率分支、结果反馈、存单、逐场屏幕票面、SVG 下载、逐票打印与追踪映射
- 完成条件：用户可选择一至三个不同场次、每场一个分区并进入包含概率与选择的流程；失败或网络波动后票篮不丢失，加价线路可以成功或失败；成功只生成一次冻结结果，显示正确存单及每场独立纪念票，并提供无需身份或附加任务的下载与打印；模组或 JavaScript 不可用时仍显示有效未开票页

#### PLAN-05 执行前提

1. S5 只在 `dev_code` 修改功能源码；功能修改前对实际候选路径运行 `npm run blueprint:where -- <路径...>`，新增或删除功能源码同步追踪映射。
2. 当前三个表站本季 `Performance` 是唯一可购场次。S5 只补充分区、`basePrice` 与启用状态，不复制日期、地点或剧目事实；1091 场次保持 `historic-snapshot` 不可购买。
3. `docs/drafts/creative/archive-anomalous-ticketing.md` 的 CRE-01 未获采纳，不读取为实现依据，不在状态机、UI、数据或测试中预留分支。
4. 模组以渐进增强启用：静态 HTML 默认显示“暂未开票”和常规返回路径；客户端完成数据与 DOM 校验后才隐藏降级区并显示购票体验。初始化失败不得留下半成品流程。
5. 不要求人工提供身份、联系方式、地址、支付账户或用户画像，也不生成虚构身份。所有操作与状态都停留在当前标签页，不发送远端请求。

#### PLAN-05 数据与价格边界

- `Performance.ticketAvailability` 扩展为显式可购状态，并在每个表站未来场次内保存 `C / B / A / S / 包厢` 五个分区及整数 LMD `basePrice`；价格可以相同或不同，但必须由场次来源读取。
- 每个 `performanceId` 在单次票篮至多出现一次；选择不同分区只更新该场次，不增加票数。当前三个可购场次因此形成一至三张票的票篮。
- `baseTotal` 每次从票篮 `basePrice` 求和；`adjustments` 只由成功线路结果生成；`settledTotal` 每次从二者求和。三项都不作为可任意编辑的副本。
- S5 采用以下首版基础价格，以页面与票面共用同一数据为验收目标：`C 180`、`B 280`、`A 420`、`S 680`、`包厢 1280` LMD。若个别场次未来需要差异，只修改该 `Performance`。
- 加价线路成功时生成一条整数服务差额，失败时不产生结算结果；纪念票始终显示所选分区的 `basePrice`，不显示分摊后的加价。

#### PLAN-05 状态与流程边界

1. **选择：** 用户勾选场次并选择分区；空票篮不能开始。票篮变化即时提供票数与基础总额文本反馈。
2. **尝试：** 开始后冻结当前票篮编辑，进入普通线路。流程可包含一次无意义确认或库存提示，但不使用真实倒计时或无限等待。
3. **普通结局：** 可得到成功、购票人数较多导致失败或网络波动。失败可原票篮重试普通线路或进入加价线路；网络波动可原线路重试或返回选择。
4. **加价线路：** 明示会产生额外服务差额，可成功或失败；失败可保留票篮重试或返回普通线路，不强制继续。
5. **成功：** 冻结票篮、线路、差额、随机票号、二维码数值与共同印章；重复提交或刷新只恢复同一结果，不重新抽取。
6. **重新开始：** 用户明确选择后清空本轮票篮与结果并回到选择；关闭界面或离开票务页不隐式清空，关闭标签页后自然结束。

- 状态使用版本化 `sessionStorage`；损坏、未知版本或字段与当前可购内容不一致时安全回到空选择状态。
- 纯状态函数接收可注入随机源与票号生成器，用于确定性验证；生产页面使用浏览器随机源。分支概率只服务体验，不写入领域内容，也不展示伪精确库存。
- 首版普通线路使用成功、失败、网络三种可达区间；加价线路使用成功与失败两种可达区间。精确阈值只在状态模块中定义一次，不成为长期产品事实。

#### PLAN-05 存单与票面边界

- 成功存单在一个结算区域列出全部场次、所选分区和各自 `basePrice`，再列出 `baseTotal`、全部 `adjustments` 和 `settledTotal`；末尾小字仅写“仅为小游戏内容，不产生任何兑换责任”。
- 每个票篮场次生成一张独立票面，读取同一 `Performance` / `Production` 事实并显示日期时间、地点、分区、基础票价、LMD、随机数值及二维码图样。
- 二维码图样由票面随机数值稳定派生，旁侧显示同一数值；不链接 URL、不作为验证、兑换、排序或全局唯一键，不执行联网扫描。
- 同次成功生成一组线路印章语义并应用到全部票面；印章有独立安全区域，不遮挡必要字段或二维码。
- 屏幕票面、下载 SVG 和打印读取同一冻结结果。下载使用本地 Blob；打印时只显示用户选择的一张票，并在 `afterprint` 后恢复页面，不修改结果。
- 票面不含姓名、订单账号、真实支付标识、兑换承诺或全站非官方声明；后者继续只由全站页脚承担。

#### PLAN-05 最终验收矩阵

1. `npm run verify` 通过；新增源码具有追踪映射；运行时不读取 `docs/`。
2. 三个可购场次在票篮中各限一张，空篮不能开始，分区和基础总额由唯一来源计算。
3. 普通成功、普通失败、网络波动、加价成功与加价失败均可由固定随机值复现；失败、波动、取消线路和重试不丢票篮。
4. 成功冻结；重复提交、渲染、下载和打印不重新生成票号、二维码、差额或印章。
5. 存单区分 `baseTotal`、`adjustments`、`settledTotal`；每张票只显示本场 `basePrice`，全部金额为整数 LMD。
6. 每个成功场次都有屏幕票面、SVG 下载和逐票打印；必要信息不被印章遮挡，二维码旁显示一致数值。
7. 无 JavaScript、初始化失败或损坏状态时 `/yan/tickets/` 显示“暂未开票”及返回路径；表站其他任务不依赖票务脚本。
8. 页面与产物没有姓名、证件、联系方式、地址、支付、账号、遥测、远端请求、兑换能力、CRE-01 或里站可购状态。
9. 1091 票务页、污染状态机、退出与搜索保持 S4 行为；票务状态不与污染状态共用存储或事件。
10. 320px 起票篮、分支、存单与票面不产生页面级横向丢失；键盘、文本反馈和减少动态效果可用。

#### PLAN-05 停止与回退条件

- 若实现必须引入后端、账号、支付、个人信息或跨标签同步，保持静态降级页并停止扩大。
- 若 SVG 下载或打印无法复用冻结结果，先修正单一渲染输入，不建立第二套票面事实；仍失败时保留屏幕票面并明确未验证项。
- 若票务改动导致 1091 场次进入可购集合、触发污染或出现 CRE-01 空分支，立即删除该耦合并恢复世界边界。
- 若某项讽刺互动要求不可跳过等待、伪系统提示或复制现实网站，删除该互动而不改变核心状态机。
