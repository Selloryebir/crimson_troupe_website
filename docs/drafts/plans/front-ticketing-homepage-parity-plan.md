#### PLAN-01 实施约束

- `SLICE-01` 只增加可复用拓扑及其结构门禁，不提前修改 `Performance`，因此该提交能够独立通过现有构建并安全回退。
- `SLICE-02` 以 `ticketAvailability` 为唯一开票事实源；不得在页面、组件或控制器新增七场 ID 数组。当前首页和票务顺序的等价关系由快照派生验证，不改变 `homepagePerformanceIds` 与票务资格的长期职责边界。
- 四个场次现有九国家版本剧目、地点和场次文字能够直接复用。只有验证证明存在真实缺口时才补充对应内容字段，不为形式对九套文件制造等价改写。
- 新增拓扑复用现有语义楼层标签；如果实现不需要新访客文案，则不修改消息 schema 和九套消息包。
- 预览报价只写入结构化 `TicketOffer`，费用、凭单和纪念票继续由现有计算与投影读取；不得启用 `docs/drafts/creative/performance-pricing-method.md`。
- 每个切片各自形成一个 `dev_code` 功能提交并按双分支流程回到 `dev_blueprint` 收口；最终跨层门禁只执行一次 `npm run verify`，不在同一轮重复其子检查。

#### PLAN-01 最终复核

完成两个切片后只核对以下结果：

1. 当前快照的七个表站 `homepagePerformanceIds` 与 `getTicketingOptions()` 的 `performanceId` 顺序一致；
2. 七场 `TicketOffer` 与对应拓扑分区集合相等，空缺等级不残留控件、价格或票面字段；
3. `showcase` 只增加真实需要的举办地主层语言闭包，`preview` 九国家版本不发生回退或跨版本泄漏；
4. 官网选择、合作平台状态恢复、成功凭单、逐场 SVG 下载与打印至少对一个原有场次和四个新增场次中的代表性不同拓扑成立；
5. 正式蓝图、验证输出和源码注释不再把表站可购能力描述为固定三个场次。
