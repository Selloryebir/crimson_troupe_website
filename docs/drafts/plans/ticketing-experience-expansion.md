#### CODE-01｜按场次分区示意与分区校正

- 继续以现有 `TicketOffer` 为价格和可售分区唯一运行时来源；分区图只描述拓扑与图形锚点，不另存第二份价格或可用性。
- 为特里蒙大剧院主舞台、维谢海姆宫廷剧院镜厅和诺伯特郡旧车站临时舞台提供三种语言无关拓扑；旧车站不再提供 `BOX`，另两个场次保留五类分区。
- 组件使用语义化控件与内联 SVG 表达场馆关系。图形点击与图外原生选择双向同步，但完整选择能力、名称、价格与状态仍由图外表单承担；SVG 路径不进入重复的屏幕阅读顺序。
- 多场次票篮一次只展开一个场次的示意，收起其他条目不清空选择；无 JavaScript 时维持现有“暂未开票”回退，不出现空图壳。
- 新资料保持语言无关，本地化短文案只进入现有三个国家版本内容层；不得把 SVG 可见文字、颜色或 DOM 顺序当作分区身份。
- 验收至少覆盖：三场次分区集合与报价一致、地图/表单双向同步、只用键盘完成选择、320px 无横向内容丢失、桌面展开不挤压票篮，以及东国和哥伦比亚版本没有回退中文。

#### CODE-02｜有上限且可复现的尝试状态

- 把线路、互斥尝试结果、报价变体、尝试次数、上次结果、一次性挽留和旅程标签拆成类型约束，禁止普通线路携带优先报价、未经历挽留却使用优惠等无效组合。
- 保留首轮普通 `32%` 成功、`36%` 席位冲突、`32%` 网络波动和优先 `58%` 成功作为测试基线，不在本切片调参。
- 同一体验不得连续两次网络波动；挽留只出现一次；最多三个需要重新提交的结果节点，达到上限后以席位回流或人工复核收束为普通成功。
- 状态继续只存稳定 ID，不存国家版本显示文案；语言切换、网络重试和失败返回均保留票篮。若状态结构升级，直接提高会话版本并安全重置旧版本，不维护一次性兼容分支。
- 结果选择允许测试注入或纯函数序列驱动，正式运行仍使用当前随机入口；测试必须稳定复现直接成功、网络恢复、失败后普通重试、拒绝优先后的回流和达到上限后的人工复核。
- 本切片先完成状态和控制器结构，不提前制作最终费用账目或完整印章视觉；必要的临时显示只复用现有组件，不新增平行结果页。

#### CODE-03｜席位回流报价与失败服务记录

- 普通失败后可进入站内“联合席位回流通道”；接受前同时显示基础总额、差额、最终报价、仍可能失败和模拟失败服务费，且不打开外站或引入第三方脚本。
- 原报价为基础总额 `150%`，即差额 `50%`；一次性挽留将差额降至 `48%`、最终报价降至 `148%`。所有金额由整数 LMD 的同一派生函数计算，界面不手写另一套数值。
- 优先失败生成屏幕内失败服务记录：获配席位为 `0`，模拟服务费为基础总额 `25%`，不生成成功存单、纪念票或下载入口，也不声称账户已真实扣款。
- 成功存单区分基础总额、调整项和模拟结算总额；每张纪念票仍只显示对应分区的 `basePrice`。修改票篮后重新计算，不把旧报价写回 `TicketOffer`。
- 三国家版本使用等价的冷静机构口吻；一条代表路径只保留两到三个讽刺节拍。拒绝、返回、修改与重试按钮保持稳定位置、焦点和可理解名称，不使用伪权限、倒计时或移动按钮。
- 验收以确定性路线证明 `150%`、`148%`、`25%` 和票面基础价恒等式；同时证明优先失败无票、语言切换不改金额或线路、减少动态效果下无需等待动画。

#### CODE-04｜旅程组合印章与稳定票面纹理

- 从成功线路和有限 `JourneyTag` 派生 `StampSemantic`，不为每种组合保存完整结果 ID。所有成功票具备核心入场章，并按实际经历叠加普通/优先路线、网络恢复、回流席位、优惠缺口或人工复核痕迹。
- 同一票篮的全部纪念票共享同一组印章语义；印章可以跨装饰边框，但不得遮挡场次、日期、分区、基础票价、票号或二维码。差异不能只依赖颜色。
- 优先失败仅在屏幕服务记录显示作废语义，不产生可下载票。界面不显示成就列表、稀有度、未收集项目或重复游玩引导。
- 复用现有十二位票号作为稳定种子，派生票纹、细线或打孔节奏；可复用 `CODE-01` 的极简场馆轮廓作底纹，但不新增持久随机字段、完整图片资产或 PNG 导出。
- 继续由现有 SVG 生成器、HTML 说明和打印样式共同表达凭据；本地化标题和解释保持为 HTML/文本，不在会话状态或装饰图形中固化译文。
- 自动验证覆盖合法组合、无效组合排除、相同冻结结果跨语言重新渲染稳定、相同票号生成相同纹理、不同场次仍共享本轮印章语义。浏览器验收覆盖屏幕、SVG 下载和打印预览。

充分性的结论具有一个必要前提：候选建议本身不能直接指导源码。完成 `BP-00` 后，产品行为由正式蓝图唯一约束，计划只保留依赖顺序、候选路径和验收方法；智能体无需从对话或旧 MMD 猜测产品意图。此时仅凭正式蓝图、当前源码和本计划即可连续开发，已采纳建议草稿应删除而不是继续作为平行事实源。

该组合足以支撑本阶段，理由如下：

- **边界完整：** 正向交付、失败路径、会话状态、三国家版本、无 JavaScript、键盘、窄屏、减少动态效果、下载和打印均有明确归属；
- **依赖闭合：** 分区资料先于状态，状态先于费用，费用和旅程先于票面，没有切片依赖尚未定义的未来模块；
- **实现最小：** 复用现有票篮、原生 TypeScript、SVG、会话存储和本地化注册，不新增框架、服务、真实场馆实体、资产管线或持久系统；
- **验证不成环：** 每个切片只验证自身新增风险，最终完整门禁只运行一次；同一轮不以 `quality`、`build` 和 `verify` 重复执行相同检查；
- **追溯单向：** 建议经 `BP-00` 消化后删除，正式蓝图定义产品，计划定义顺序，源码定义实现，Git 与验证命令保留执行证据，不产生第二份产品事实。

人工已经完成建议采纳、正式迁移与计划执行授权；`CODE-03` 已按独立切片完成并回到蓝图分支，当前不存在阻止 `CODE-04` 开始的产品或技术门禁。
