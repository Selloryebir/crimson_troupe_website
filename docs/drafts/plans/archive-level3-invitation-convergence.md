#### PLAN-01 切片边界

- `SLICE-01` 只建立邀请能力和退役旧说明框，不提前实现全页面内容收束；邀请内容可使用完整的非正式预览值，但不得延用当前解释污染机制的段落。
- `SLICE-02` 通过共享演出列表和海报投影同时覆盖首页、本季与历史，不复制三套场次内容，也不把克莱布拉松写入 `Performance` 或普通搜索索引。
- `SLICE-03` 只改变详情与机构记录的等级 3 可见投影，不改变 canonical、页面生成集合、实体关联或等级 0 元数据。
- `SLICE-04` 不修改搜索匹配算法、结果实体和票务领域模型；静态席位的等级 3 动作只发出邀请，不接入表站票务状态机。
- `SLICE-05` 以显式污染插槽和确定性会话变体编排视觉，不使用 DOM 序号猜测、运行时 `innerHTML`、持续随机动画、现实错误弹窗、全局滤镜或真实交互容器位移。
- 最终投影海报优先通过一个可替换引用复用项目已有且权利状态明确的里站预览素材，不复制资产、不直接使用本地参考材料，也不让未来更换正式素材需要改写页面组件。

#### PLAN-01 最小验证与收口

- 每个切片先运行 `npm run quality -- <实际改动路径...>`，再只追加该切片新风险要求的内容、locale、状态、preview 构建或代表性浏览器检查；不得在同一切片前后重复 `quality` 与其子门禁。
- `SLICE-01` 涉及新增／删除功能源码时追加一次 `blueprint:check`；后续只有真实新增、删除或重命名源码才再次运行，不把追踪检查变成每切片固定仪式。
- 页面输出变化在对应切片进行一次 preview 构建；浏览器断言随切片加入同一验证入口，但只检查新能力和既有可靠退出，不建立全语言乘全页面截图矩阵。
- `SLICE-05` 完成后只运行一次 `npm run verify`，随后补 `build:preview`、`validate:build:preview` 与 preview 浏览器验证；不重复 `verify` 已覆盖的完整质量、状态、内容和 showcase 构建。
- 人工视觉验收至少检查炎语桌面、炎语 320px 和一个长文字国家版本，比较等级 0、1、2、3 及减少动态效果终态；重点判断异常是否由页面内容关系生长，而不是退化为普通弹窗或通用故障网站。
- 全部切片完成、正式蓝图与追踪关系无漂移且没有未验证项后，删除本计划；Git 历史保存切片提交，不另建执行日志或完成报告。
