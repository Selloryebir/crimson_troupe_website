## 正文

### PLAN-01｜S1 炎国双站路由与领域骨架

- 状态：已批准执行
- 正式依据：`BP-FND-CORE`、`BP-FND-DOMAIN`、`BP-FND-EXPERIENCE`、`BP-FND-NARRATIVE`、`BP-FND-EXTENSION`、`BP-MOD-PROGRAMS`、`BP-MOD-ARCHIVE`、`BP-MOD-SEARCH`、`BP-MOD-TICKETING`、`BP-CNT-CORE`、`BP-I18N-CORE`、`BP-QLT-STAGES`
- 范围：类型化国家版本注册与路由构造；`Production` / `Performance` 领域数据；炎国表站及 1091 里站完整稳定路由的最小页面状态；页面元数据；真实站内链接；按页客户端装配；旧单页正式入口收口；必要追踪映射与 S1 验收
- 完成条件：正式炎国 URL 均可直接访问、刷新并由站内链接到达；根路径进入 `/yan/`；两个网站在无 JavaScript 时保留最小内容、主导航和返回路径；页面元数据与索引规则正确；旧 `Show` 和双世界同页 DOM 不再是正式页面、搜索或票务接口；一次完整 `npm run verify` 与限定浏览器验收通过

#### PLAN-01 执行前提

1. 按 `docs/guides/git-branch-workflow.md` 将包含本计划的 `dev_blueprint` 同步至 `dev_code`；同步只传递蓝图与计划，不授权开始源码修改，也不得在 `dev_blueprint` 主动产生 `src/` 功能改动。
2. 在 `dev_code` 开始每个切片前检查工作区，并对实际候选源码运行 `npm run blueprint:where -- <路径...>`；下文路径是候选影响范围，不替代运行时反查。
3. active 正式蓝图始终高于本计划。若实现必须改变用户结果、路由契约、领域语义、状态归属或阶段边界，应停止扩大源码修改并把问题送回 `dev_blueprint`，不能在代码分支用实现选择改写产品契约。
4. 复用旧 Demo 时只保留仍服务于目标页面的内容、组件和样式。不得为保留旧结构而继续装配两个完整网站，也不得为未来切片建立空抽象、占位模组或并行事实源。

#### PLAN-01 实施边界

- 国家版本注册完整保存 `BP-I18N-CORE` 已确认的矩阵字段，但 S1 的生成集合、页面入口和语言显示只包含 `yan / zh-CN`；不建立第二语言翻译范围清单。
- S1 生成 `BP-FND-CORE` 规定的炎国表站与 1091 里站路由。页面内容只达到可理解、可导航、可验证的最小状态，不借机完成 S2 或 S3 的完整内容、信息密度和视觉设计。
- 本季、历史和详情页从同一 `Production` / `Performance` 来源读取。迁移过程如需短暂兼容旧组件，只能由新领域数据派生只读适配结果，并须在 S1 收口前删除该适配及旧 `Show` 接口。
- 搜索页在 S1 只提供当前作用域说明、常规导航和明确的尚未实现状态；不生成 S2～S3 的搜索索引或伪造结果。表站票务页显示“暂未开票”，里站票务页显示历史快照不可购买，并各自提供有效返回路径。
- 主导航、品牌返回、表里切换、列表到详情和页面内返回均使用真实 URL。过场、浮层与脚本只可作为渐进增强，不得成为到达目标页的唯一方式。
- 语言区域只显示当前 `yan / zh-CN`，不渲染空选择器、未开发选项或“即将推出”入口；表站与里站页脚均以低干扰方式保留同人非官方声明，不在其他常驻区域重复提示。
- 允许为多页面安全装配进行必要的基础样式调整，但不执行整库视觉重构，不提前实现污染效果、票务流程或最终年代视觉。

#### PLAN-01 数据迁移与兼容收口

- 先把现有 `Show` 字段逐项归入剧目、场次或两者关联，无法按正式字段归属确定的内容不得静默丢弃或随意复制；只影响展示的旧字段可以在新模型中保留明确的展示归属。
- 页面、搜索占位和票务入口只从新领域来源派生。不得让旧 `shows` 与新 `performances` 分别保存可编辑副本。
- 旧组件若在切片中暂时需要扁平数据，只允许使用由新来源计算的内部适配；S1 完成前删除该适配或确认它已改为无业务事实的纯呈现映射。
- 稳定 ID 保持跨列表、详情与未来搜索、票务消费者可复用；标题、国家显示名和翻译文本不参与实体身份或 URL 推导。

#### PLAN-01 最终验收矩阵

1. **构建与追踪：** `npm run verify` 一次通过；`blueprint:check` 报告的新增、删除和重命名源码映射与实际消费者一致，不为 S2～S5 的未来源码预填记录；运行时产物不读取 `docs/`。
2. **路由产物：** `dist/` 包含 `BP-FND-CORE` 规定的炎国表站与 1091 里站页面及数据中存在的场次、剧目详情；不存在其他国家版本页面、旧 `#archive-091` 正式入口或无目标站内链接。
3. **元数据：** 各页面 `lang="zh-CN"`，canonical 指向当前稳定路径；仅 `/yan/` 允许索引并进入站点地图，其余页面输出 `noindex,follow`；页面标题、描述、世界和页面类型与当前路由一致。
4. **直接访问：** 首页、主任务页、场次详情、剧目详情、搜索页和票务页均可直接打开、刷新、复制地址并通过浏览器前进后退恢复。
5. **无脚本与交互不变量：** 禁用 JavaScript 后两个网站的最小正文、主导航、跨站返回及页面内返回仍可使用；键盘可以按可理解顺序到达相同目标，焦点不被旧浮层或过场截留；减少动态效果不会删除信息、导航或反馈。
6. **视口安全：** 检查最低 320，以及 375/390、768、1024、1280/1440 CSS 像素代表视口；页面不出现横向内容丢失、主导航不可达或主要操作遮挡。S1 不以此验收最终视觉完成度。
7. **降级状态：** 两类搜索页不伪造搜索结果；表站票务页明确暂未开票，里站票务页明确历史快照不可购买；所有状态均提供返回相关演出或首页的有效路径。
8. **遗留边界：** `src/` 内不存在页面、搜索或票务对旧 `Show` 接口的正式依赖，不再由一个 HTML 同时装配表站和里站；保留的旧文件均有明确当前消费者。
9. **沉浸与本地化边界：** 表站与里站只显示当前 `yan / zh-CN`，不出现未开发语言入口；两站页脚均包含同一低干扰同人非官方声明，其他常驻区域不重复设置声明、角标或弹窗。

#### PLAN-01 停止与回退条件

- 发现正式蓝图之间存在无法通过实现选择消解的冲突时，保留已验证的最小改动并停止后续切片，记录冲突蓝图、受影响路径和最小复现，等待 `dev_blueprint` 修正。
- 发现内容不足时使用正式蓝图允许的最小状态或现有已批准内容，不为填满页面自行扩写世界观、剧团历史或票务规则。
- 某一切片无法独立通过作用域检查时，先修复该切片，不以继续堆叠后续页面掩盖失败；不得通过关闭检查、扩大忽略或保留两套正式入口规避问题。
- 需要撤销未完成切片时只精确回退本切片新改动，保留此前已经验证的切片和用户工作；禁止使用破坏性整库恢复。
