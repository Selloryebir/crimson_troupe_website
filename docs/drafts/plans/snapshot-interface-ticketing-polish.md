- 文档类型：一次性开发计划
- 状态：已批准执行
- 规划效力：只约束本计划的切片顺序，不覆盖正式蓝图；未获执行授权前不得修改源码
- 分析基线：`dev_blueprint` 当前 `HEAD`、本轮迁移后的 active 蓝图与当前 `src/` 实现
- 目的：以可回退的有限切片落实日期快照、同期里站、首页编排、搜索与语言选择器修正，以及表站分层场馆和预览票价校正
- 非目标：不新增可访问快照、不实现损坏快照页面、不接入里站异常购票、不认可候选票价或五语言 AI 文案为正式内容、不改变表站概率线路、纪念票结局或污染状态机

## 正文

### 可执行性与最小变更结论

三份已批准蓝图草稿的稳定决策已经原位迁入 active 蓝图，未遗留产品方向问题。现有源码已经具备独立表里页面树、统一内容快照、五国家版本包、分域搜索、表站票务状态机和可复用分区类型；本阶段只需替换快照身份与路由入口、增加一个里站静态席位表现、限定首页列表变体，并修正现有票务资料和选择控制，不需要重建领域模型、页面系统、本地化框架或票务流程。

六个源码切片按依赖顺序拆分：快照身份先于所有里站 URL 和搜索范围；访客外壳先于同期内容；里站静态席位与表站票务状态机隔离；首页编排与票务互不依赖；票务先建立正确拓扑与报价，再调整预选和入篮交互。每个切片都有独立可观察结果和至少一个专属 `dev_code` 提交，不用最终集成替代阶段提交。

#### PLAN-01 切片边界

- `SLICE-01` 只建立快照身份、路由和消费者关系；损坏记录不生成内容，旧路由只做静态兼容，不保留通用多快照框架或同日多捕获预案。
- `SLICE-02` 只修正馆藏披露、搜索口吻和选择器字体。系统字体实测足够时不引入 Web Font、菜单库或全站字体重设计；不得把内部隔离事实换成另一种剧透文案。
- `SLICE-03` 的里站席位页是无持久状态的同期静态表现，不复用表站 `TicketBasket`、尝试、结局、存单或纪念票；现有 `TicketAvailability` 若强制把 `on-sale` 与表站座席图绑定，应只在领域类型和表站候选校验之间解耦，使里站报价无需虚构场馆图，同时继续由同一 `offers` 保存价格事实。延期的异常购票创意继续留在独立创意草稿。
- `SLICE-04` 使用显式首页变体复用必要数据与标记，不复制第二套 `Performance` 内容，不把完整列表组件强制改成首页布局。
- `SLICE-05` 不建立独立 `Venue` 实体、逐座位模型、容量、现实测绘或动态经济公式；具体价格保持未批准预览资格，只校验相对关系和数据贯穿。
- `SLICE-06` 不改变每场限购一张、空篮提交、概率、重试上限、报价路线或结果；只调整预选与入篮的责任边界。

#### PLAN-01 最小验证与最终收口

- 每个切片先运行 `npm run quality -- <实际改动路径...>`，再只追加该切片改变的内容、状态、locale、构建或浏览器检查；同一轮不重复执行已经包含在其他命令中的门禁。
- 路由、五语言和跨层切片使用一次与风险相称的 `build:preview` 及对应产物验证；纯布局或交互切片在最小质量后复用 preview 浏览器入口验证代表页面，不建立全语言乘全页面截图系统。
- `SLICE-06` 完成后只运行一次 `npm run verify`；随后补一次 `npm run build:preview`、`npm run validate:build:preview` 与 preview 浏览器验证，因为 `verify` 已覆盖的完整质量、状态、内容和 showcase 构建不得重复运行。
- 最终浏览器矩阵至少覆盖桌面及320px表里首页、表站搜索、东国语选择器、里站馆藏进入与退出、旧路径重定向、里站无脚本席位页、三个表站场馆、键盘分区选择、减少动态效果及污染下可靠退出；联合检查页面 `scrollWidth`、焦点和关键元素边界。
- 每个切片遵循 `docs/guides/git-branch-workflow.md` 的双分支逐切片闭环。最终源码同步回 `dev_blueprint` 后，只按真实实现更新必要追踪、架构事实和计划状态；没有独立源码结果的收口不制造第七个代码提交。
- 全部切片完成且无未验证项后删除本计划；不把执行日志、候选路径或临时票价迁入长期蓝图。
