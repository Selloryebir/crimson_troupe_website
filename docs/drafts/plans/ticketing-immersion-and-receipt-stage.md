#### PLAN-01 实施约束

- 四个切片遵循 `docs/guides/git-branch-workflow.md` 的逐切片闭环。每个切片在 `dev_code` 至少形成一个只属于该切片的 Conventional Commit；上一切片回到 `dev_blueprint` 并完成状态收口后，才能批准下一切片。
- TKT-01 只修复票面媒介有效性，不顺带重写票面结构；TKT-02 只调整票面投影与内容闭包，不改结局或访客路线；TKT-03 不改变状态机概率和金额；TKT-04 复用既有状态、消息与渲染边界，不为凭单引入订单后端或第二套价格事实。
- TKT-02 的辅助版本直接取当前 `ResolvedLocalization.edition`，不读取 `navigator.language`。内容闭包由“当前构建版本集合＋实际举办地版本”派生，不再固定加入维多利亚；批准摘要、内容验证和运行时投影使用同一规则。
- TKT-04 在成功结果中保存结构化 `TerraDateTime`，并随状态版本升级安全拒绝旧结构。实际时间由页面从 `getSiteTerraNow('front', buildSnapshot.context)` 或等价唯一接口传入状态机；渲染器只负责按当前 locale 格式化，不自行读取任何时钟。
- 挽留成功的对外费用行必须表达原始 `50%` 渠道附加与使最终附加成为 `48%` 的负向减让；实现可选择等价的整数派生方法，但所有行之和必须精确等于现有 `settledTotal`，不得通过浮点显示或重复金额源制造一龙门币误差。
- 正常流程只在成功凭单底部保留一次“仅为小游戏内容，不产生任何兑换责任”。失败记录使用“未发生扣款”的事实说明；不得跨内容包批量删除剧目观演提示中的“模拟”正常语义。
- 不新增依赖、页面、路由、状态分支、Ending 或下载格式；既有无 JavaScript 降级、焦点恢复、减少动态效果、标签页生命周期和平台 Logo 不得退化。

#### PLAN-01 验证节奏

- 各切片只执行表格列出的相关 `quality` 与确定性验证，不在每次闭环重复全量构建或完整浏览器矩阵。
- TKT-04 完成全部跨层装配后运行一次 `npm run verify`；该命令包含的完整质量、状态和 showcase 构建门禁不在前后重复执行。
- 九国家版本差异另运行一次 `npm run build:preview`、一次 `npm run validate:build:preview` 和一次 `npm run validate:browser:preview`。`preview` 与 `verify` 的 showcase 是不同构建范围，不用其中一个代替另一个，也不重复第二轮九国家版本浏览器验收。
- 浏览器矩阵至少覆盖炎语页面购买莱塔尼亚场次、同语言场次、维多利亚／哥伦比亚英语同族、普通成功、完整加价成功、挽留成功、失败记录、SVG 解析与解码、语言切换恢复、键盘焦点和 320px 无横向丢失。
- 任一验证失败先在当前切片内修复并只重跑受影响的最小检查；只有改动跨越最终集成边界时才重新运行相应完整门禁，不通过循环执行同一命令碰运气。
