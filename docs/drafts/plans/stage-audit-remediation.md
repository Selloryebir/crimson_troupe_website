### PLAN-01｜阶段审计修正与有限体验组织

- 状态：已批准执行
- 正式依据：`BP-CNT-CORE`、`BP-I18N-CORE`、`BP-MOD-PROGRAMS`、`BP-MOD-SEARCH`、`BP-MOD-ARCHIVE`、`BP-MOD-TICKETING`、`BP-MOD-TERRA-TIME`、`BP-QLT-STAGES`
- 范围：修复最终变体与闭包校验、作者层本地化边界、不可变快照、长标题票面与隐藏投影资源、污染无障碍和代表视口门禁；增加显式首页精选集合、标题优先与类型分组搜索
- 完成条件：七个源码切片分别完成独立 `dev_code` 提交并按长期双分支流程闭环；聚焦检查和一次最终 `npm run verify` 通过；正式蓝图、追踪表、实现与草稿状态一致

#### PLAN-01 启动门禁

本计划不能替代正式蓝图。开始第一个源码切片前必须由人工另行授权正式迁移，并把以下已确认结论写入唯一 active 责任方：

1. `BP-MOD-PROGRAMS` 与 `BP-CNT-CORE`：内容根以 `homepagePerformanceIds` 保存显式、有序且属于对应本季集合的首页精选场次；它不替代单个 Hero 焦点 `featuredPerformanceId`，完整列表继续展示全部本季场次。
2. `BP-MOD-SEARCH`：保持语言与时间层隔离，使用稳定的标题命中优先和结果类型分组，不引入模糊搜索、分页或复杂评分。
3. `BP-QLT-STAGES`：当前自动化支持证据限定为 Chromium，补齐 768 代表视口与组合覆盖，不宣称 Firefox/WebKit 已验证。
4. `BP-CNT-CORE`、`BP-I18N-CORE`、`BP-MOD-ARCHIVE` 与 `BP-MOD-TICKETING`：核对审计确认的最终变体、闭包、本地化、投影、不可变快照和最终 offers 约束；只补当前蓝图未明确表达的差异，不复制实现细节。
5. 同次迁移修正 `root-sets.ts` 的 `BP-MOD-TERRA-TIME` 追踪关系，以及参考／延期创意中的过期 1091 当前快照口径；迁移完整后按草稿生命周期处理审计稿，不保留双重事实源，并把本计划的分析基线改为迁移后的 active 蓝图。

迁移后运行一次 `npm run blueprint:impact -- <实际变更的蓝图 ID...>` 和一次 `npm run blueprint:check`。这两项是蓝图阶段门禁，不在后续每个源码切片重复执行；只有新增、删除或重命名功能源码时才按仓库规则再次执行追踪检查。

#### PLAN-01 最终验证与清理

1. 各切片日常只运行与实际路径相称的 `npm run quality -- <paths...>` 和表中聚焦检查；运行时产物变化时执行一次对应构建，不在同轮通过 `quality` 与 `build` 重复门禁。
2. `SEARCH-01` 回到 `dev_blueprint` 后，确认七个切片状态、实际提交和蓝图追踪一致；解决过程中若未新增功能源码，不制造追踪表占位修改。
3. 只在阶段候选闭环执行一次 `npm run verify`；随后针对不同构建配置依次执行一次 `npm run build:preview`、`npm run validate:build:preview` 和 `npm run validate:browser:preview`。已有 `verify` 子门禁不重复单独执行。
4. 核对首页与搜索的可见行为、里站可靠退出、九语言路由、票务纪念票和污染邀请未回归；明确报告 Firefox/WebKit 未在本阶段自动验证。
5. 将长期有效且尚未落位的规则收回正式责任文件，删除已完成的一次性计划；若审计草稿正文已经全部迁移且无问题与定位残留，按草稿机制删除该来源。
