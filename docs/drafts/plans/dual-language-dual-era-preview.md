- 状态：已获人工授权，执行至 STAGE-01
- 规划效力：只编排本次双语言架构与双时期视觉升级的开发顺序，不覆盖 active 正式蓝图，不授权源码修改、Git 同步或发布

3. 执行前重新核对本计划中的正式蓝图 ID、命令名称、当前页面数量与源码路径；若只发生不改变切片边界的基线漂移，原位更新本计划，不重做全局规划；

#### PLAN-01 执行约束

1. 源码功能改动只在 `dev_code` 产生；每个切片先对实际路径运行 `blueprint:where`，新增、删除或重命名功能源码时同步 `traceability.json`；
2. 保留当前 Astro 动态路由、表里独立页面树、稳定内容 ID 和原生 TypeScript；不为 `/col/` 复制 `.astro` 页面，不引入运行时 i18n 依赖；
3. 每次迁移遵循“建立目标类型与数据 → 切换全部消费者 → 核对输出 → 删除旧副本”，不得让旧中文数据和新国家版本内容长期并行；
4. 先完成只构建炎国时的等价迁移，再把哥伦比亚加入预览集合；不得为了观察下拉效果提前公开中英混排或断路页面；
5. AI 英译覆盖全部现有访客范围，保持表站机构口吻与里站年代语气的区别，但不在本轮追求正式译审或扩写内容；
6. 活页剧目标题目录不属于本轮实现范围；无论其是否在执行前完成正式迁移，本轮都只迁移当前源码已经使用的原创剧目，不引用该目录替换标题或扩张内容；
7. 每个切片只对实际路径运行一次 `npm run quality -- <路径...>` 并服从其调度结果；若它因工具链或跨层改动已经执行 `verify`，同一切片不再重复其子门禁。未包含构建且运行时产物改变时再运行一次对应构建；正式和预览是不同产物范围，可以各构建、验证一次。
8. 本阶段视觉与排版验收只覆盖炎语和哥伦比亚语。其他已注册国家版本可以沿用同一数据、`lang`、路由和选择器接口，但其字形、字体顺序与版式问题留到对应语言开发阶段处理，不为本轮提前增加字体或兼容分支。
9. `I18N-01—05` 全部完成后才进入 `VIS-*`，避免用页面级中文、旧内容字段或单一语言长度固化新版式；视觉切片不得反向改写本地化模型或状态契约。
10. 视觉实现只使用项目自有 HTML/CSS 图形与权利清晰素材；本次分析材料只提供抽象证据，必须在提交前从工作区删除，不进入 `src/assets/`、构建产物或 Git。

#### PLAN-01 已定实施接口

以下接口是现有正式目标的最小实现选择，用于避免执行阶段重新发明架构；它们不增加新的产品能力。

1. **构建模式：** 使用单一 `SITE_BUILD_PROFILE`，只接受 `release` 与 `preview`，未设置时为 `release`，非法值在静态路径生成前失败。`releaseEditionIds` 固定为 `['yan']`，`previewEditionIds` 固定为 `['yan', 'columbia']`，页面只遍历由当前模式派生的一份 `buildEditionIds / builtEditions`；路由文件、组件和验证脚本不得各自维护国家版本数组。
2. **命令边界：** `npm run dev` 与 `npm run build` 保持正式模式；增加 `dev:preview`、`build:preview`、`validate:locales`、`validate:locales:preview` 与 `validate:build:preview`。正式 `verify` 增加正式 locale 覆盖检查但继续只验证正式模式；最终先运行一次正式 `verify`，随后只运行 `validate:locales:preview`、`build:preview` 与 `validate:build:preview`，不重复正式质量子命令。由于两种构建共用 `dist/`，每次产物验证必须紧跟生成它的同模式构建。
3. **内容记录：** 类型层显式定义页面、消息组、地点、场次和剧目五类国家版本记录。炎国包完整；其他版本在开发中可以缺少整条记录，但已经存在的记录必须完整。统一解析器仅按整条记录回退并返回 `sourceLocale`，组件不得进行字段级 `??` 中文拼补。
4. **内容分组：** 每个国家版本的 `site.ts` 保存按 `front / archive` 与稳定页面 ID 组织的页面、元数据、导航和结构文案；`programs.ts` 保存按稳定实体 ID 组织的地点、场次和剧目显示内容；`messages.ts` 保存共享、筛选、搜索、票务和污染等消费者消息。文件可以因真实规模合并，但这三类职责不能重新混在领域事实或页面模板中。
5. **构建期与客户端边界：** Astro 页面和组件接收当前 `Edition` 与解析后的完整记录；客户端筛选、搜索、票务和污染脚本只通过各自根节点获得当前 locale、必要消息子集与当前功能数据，不导入全站翻译包，不读取全局当前语言，也不保留中文兜底字符串。
6. **等价页面链接：** 布局把当前无查询参数的 canonical 路径交给选择器；共享路径辅助只替换已验证的首个 `routePrefix`，保留其后的世界、页面和稳定实体 ID。搜索参数不复制；目标记录确实不存在时才回到目标版本同世界首页。里站目标链接带既有 `data-locale-switch`，不另建污染事件。
7. **票务状态：** 将会话状态提升为新的明确版本，只保存 `performanceId`、分区、阶段、线路、差额与印章语义 ID、金额和票号；`zoneLabel`、差额标签、印章文字和所有反馈在目标国家版本重新解析。旧状态版本直接安全重置，不保留一次性兼容分支；新状态必须能在炎国创建、切换哥伦比亚后恢复同一票篮和冻结结果。
8. **覆盖门禁：** 覆盖检查从炎国页面 ID、消息组和全部当前运行时稳定实体 ID 机械派生缺失路径，不把尚未被场次采用的地点候选加入覆盖分母，也不维护第二份手写翻译清单。开发回退只用于本地未完成过程；本阶段双语言可部署预览和正式构建都必须零缺失、零回退，区别仅在哥伦比亚仍是未获人工译审的预览内容。
9. **视觉样张起点：** 表站候选包括编辑纸色 `#F1EDE5`、抬升纸色 `#FAF8F3`、墨黑 `#171310`、舞台暗面 `#20272B`、酒红 `#811B28`、舞台红 `#C43A4A`、冷青 `#3E7F86`、灰粉 `#D4A9AA` 与暖铜 `#AD7542`；里站候选包括深廊黑 `#100A09`、煤烟黑 `#17100E`、漆木暗面 `#211714`、旧纸 `#D8C9AD`、褪色墨 `#9D8D77`、帷幕红 `#7D1722`、鲜血红 `#BB2835`、旧金 `#9A6A32`、烛光琥珀 `#D09A55` 与烟紫灰 `#66555F`。这些数值是语义令牌的测试起点，不是完成条件；最终只保留通过对比度、任务层级、双站辨识和窄屏验证的值。
10. **视觉空间：** 每个代表页面至少建立页面环境、内容表面和舞台或档案焦点三层关系。表站通过浅色编辑段、舞台暗面、跨列裁切和方向线形成节奏；里站通过暗色前厅、旧纸档案、中心轴、嵌套框景和烛光焦点形成纵深。不得用连续同构卡片、通用阴影或全页纹理替代空间设计。
11. **页面模式：** 表站首页先验证不对称编辑网格，表站票务验证高密度任务与品牌共存；里站首页先验证等级 `0` 的仪式档案剧场，里站搜索验证旧站事务可读性；两站演出列表或详情各抽查一个内容模式。代表模式稳定后才覆盖其余同类页面。
12. **功能保护：** 视觉切片只调整必要 Astro 结构、CSS 呈现和装饰性属性，不改变页面任务顺序、稳定内容 ID、搜索范围、票务结局、污染判定或状态格式；增加的装饰节点默认 `aria-hidden` 且不进入键盘顺序。

#### PLAN-01 目标源码边界

```text
src/data/
├── editions.ts                 # 九个注册版本、构建模式及正式与预览集合
├── locations.ts                # 当前被场次引用地点的语言无关身份
├── productions.ts              # Production 语言无关事实
├── performances.ts             # Performance 语言无关事实
└── localized/
    ├── schema.ts               # 五类记录、消息与已解析结果类型
    ├── resolve.ts              # 整记录解析、来源 locale 与缺失收集
    ├── yan/
    │   ├── site.ts
    │   ├── programs.ts
    │   └── messages.ts
    └── columbia/
        ├── site.ts
        ├── programs.ts
        └── messages.ts
```

新增的选择器和正方形标识分别使用独立共享组件；只有确有必要的关闭增强才新增客户端脚本。目录只表达职责，不要求为每个页面建立文件。若实际内容规模在实现时更适合合并同一国家版本的小文件，可以在不改变单一事实源、类型边界和追踪关系的前提下收敛；不得把全部页面、全部语言和全部模块堆入一个无边界字典。

当前 `main.css` 同时拥有共享基础、两站页面、票务、污染、响应式和打印规则，视觉重设计将持续触及这些责任，已达到一次职责拆分的实际收益。`VIS-01` 使用以下最小目标，不为单个组件继续碎片化：

```text
src/styles/
├── main.css          # 唯一装配入口，只声明有序 imports
├── foundation.css    # 共享尺寸、重置、无障碍、外壳及真正共享的任务基础
├── front.css         # 表站令牌、外壳、页面模式与表站响应式规则
├── archive.css       # 里站等级 0 令牌、外壳、页面模式与里站响应式规则
├── ticketing.css     # 票务流程、存单、纪念票和打印规则
└── pollution.css     # 污染等级、变体、装饰层及减少动态效果规则
```

拆分时保持原选择器、顺序和呈现等价，随后为新增文件建立真实追踪映射；若同一规则同时服务两个世界且语义确实一致才进入 `foundation.css`，不能仅因代码相似强行共享。

#### PLAN-01 扩展性验收

1. 页面、布局和现有模组中不存在按 `yan`、`columbia` 或 `zh-CN`、`en-US` 分支选择具体文案；差异只来自国家版本注册、解析后的内容和必要 `:lang()` 排版；
2. 新增下一个真实国家版本只需添加内容包、术语、必要字体覆盖和预览集合项；不得新增同构页面、复制领域事实或改写搜索、污染和票务状态机；
3. 开发缺失由统一覆盖报告定位到消息键或稳定实体 ID；正式构建拒绝回退，预览构建不把缺失警告显示在沉浸式页面；
4. 构建验证按版本集合循环检查，不依赖固定页面总数作为唯一事实；26 与 51 只用于本轮规模核对；
5. `releaseEditionIds` 保持 `['yan']`，哥伦比亚 AI 英译与预览入口不被描述为 formal 或已审核发布。
6. 双站语义令牌与页面模式按世界和用途扩展，不按语言复制；新增国家版本只允许必要的 `:lang()` 排版修正，不复制表站或里站样式树。

#### PLAN-01 停止与回退条件

- 若实现必须改变正式路由、双时间层语义、搜索范围、票务结果或污染状态才能继续，停止对应源码扩张并返回 `dev_blueprint`；
- 若某个中文字段无法判断属于共享事实还是国家版本内容，先依据领域蓝图与唯一消费者定位；判断会影响多个模组时提交人工确认，不复制字段绕过；
- 若哥伦比亚内容在进入预览集合前仍存在页面级缺失、断链或不可理解回退，则保持只构建炎国，不提前开放 `/col/`；
- 若系统字体无法覆盖或稳定排版关键字符，先调整回退顺序；只有项目内许可字体确有必要且来源明确时才扩大素材范围；
- 若代表页面必须改变任务顺序、领域内容、搜索、票务或污染状态才能形成目标视觉，停止视觉切片并返回正式蓝图判断，不用结构性功能变化伪装美术优化；
- 若某项候选颜色、纹理、框景或动效不能同时通过对比度、双语言长文本、320px、键盘或减少动态效果验证，删除或降低该参数，不把单一视觉偏好升级为全局例外；
- 若浏览器环境不可用，完成可执行的类型、构建与静态产物检查，并把选择器视觉、焦点和代表视口保留为人工验收项，不用静态推断替代。
