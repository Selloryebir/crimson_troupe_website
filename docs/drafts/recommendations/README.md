# 建设建议草稿

本目录保存尚未获得人工采纳的宏观方向、下一步行动和候选方案。建议应说明为什么值得做、最小如何落地和怎样观察结果，但不因优先级、推荐结论或写入正文而自动成为正式产品契约。

每份实际建议草稿必须同时遵守 `docs/drafts/README.md` 的固定元数据、“正文、待解决问题、正式拆分与影响定位”三个顶层部分和人工门禁。本文件只维护建议草稿专属的 `REC-*` 正文格式。

## 建议草稿正文模板

```markdown
#### REC-01｜建议名称

- 状态：候选，待人工判断
- 优先级：
- 价值：
- 成本：
- 推荐结论：

##### REC-01 原因

##### REC-01 最小落地

##### REC-01 可观察验收

##### REC-01 非目标
```

所有固定字段必须显式出现。允许在固定字段下增加确有必要的小节，但不能用散落的自然语言替代固定字段；原稿没有提供的信息写“原稿未说明”，不得为了填满格式自行补充结论。

完成采纳、迁移、拒绝或作废后删除实际建议草稿；即使本目录暂时没有建议草稿，也保留本 README 作为稳定职责和格式入口。
