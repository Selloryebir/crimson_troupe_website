## 正文

### 建议解释规则

1. 本文件只保存建议，不复制 `docs/drafts/blueprint/scope-alignment.md` 的已定规划正文；建议需要约束时引用 SET ID。
2. 每项建议给出默认结论、原因、最小落地切片和验收结果，避免只提出问题。
3. 优先级只表达推荐顺序，不表示必须同时实现：
   - `P0`：后续结构依赖，宜先处理；
   - `P1`：完成基础框架后具有明确收益；
   - `P2`：可独立延期，不阻塞核心体验。
4. “总体判断”只是当前仓库快照，不成为长期架构事实；只有重新讨论相关 REC 时才核对受影响源码，不要求每次代码修改都维护本建议稿。

### 总体判断

当前 Demo 已经证明 Astro 静态构建、类型化剧目数据、原生 TypeScript 交互、响应式视觉和双时间层概念可以工作。它适合保留为视觉与交互素材库，不适合作为目标站点继续横向堆叠区块。

当前最大差距不是“功能数量不足”，而是目标口径已经从单页原型转向多国家版本、独立路由树和独立表里站，而现有工程仍具有以下 Demo 假设：

- `src/pages/index.astro` 是唯一页面，表站和里站装配在同一份 HTML 中；
- `src/scripts/main.ts` 无条件初始化全部模块，页面缺少任一必需 DOM 时会中断后续装配；
- `src/components/overlays/SiteDialogs.astro` 同时承担搜索、剧目详情、预约和影像，多项未来独立页面仍是浮层；
- `src/data/shows.ts` 把作品、具体场次和展示文案合并为一个 `Show`，难以同时支持历史演出、多场次票篮和多语言；
- 现有源码与部分正式蓝图仍保留单页切换、表站固定年份、表站搜索暴露里站以及票务身份表单等旧口径。

因此，推荐先迁移目标契约，再建立路由与内容骨架，然后逐项恢复和扩展体验；具体可部署顺序只在 REC-13 维护。不要先重写视觉、翻译十种语言或实现随机污染。

### P0：结构与核心产品建议

#### REC-01｜先完成一次有边界的正式蓝图迁移

- 状态：候选，待人工判断
- 优先级：`P0`
- 价值：高
- 成本：低至中
- 推荐结论：在新增目标源码前，用一次集中修改把已定 SET 拆入正式蓝图、架构说明和追踪表，不把蓝图迁移与大规模页面重写放在同一切片。

##### REC-01 原因

正式蓝图和架构文档仍把“单一公开路由、同一 HTML 中切换表里站、表站异常搜索结果”等 Demo 行为视为当前基线，而蓝图草稿已经确定独立路由、搜索隔离、表站“现在”和新票务模组。继续按旧蓝图开发会让智能体和人员得到相反指令。

##### REC-01 最小落地

1. 按蓝图草稿末尾映射更新现有基础、模组、内容、i18n 和质量蓝图；
2. 新增独立票务模组蓝图，但不同时实现票务源码；
3. 更新 `docs/blueprint/traceability.json` 的蓝图节点和依赖，不预填尚不存在的源码映射；
4. 同步修正 `docs/architecture/repository-structure.md` 和仓库根目录 `README.md` 中已失效的单页、固定年份与锚点入口描述；
5. 删除已经完成迁移的临时 SET，未迁移内容继续保留在蓝图草稿，不制造两套正式事实。

##### REC-01 可观察验收

- `npm run blueprint:check` 通过；
- 正式蓝图中不再同时存在“同页显隐整站”和“独立路由整站”两种目标；
- 任一后续源码切片都能定位到唯一主要蓝图。

##### REC-01 非目标

- 不把蓝图迁移与大规模页面重写放在同一切片；
- 不为尚不存在的源码预填追踪映射。

- 价值：高
- 成本：中
- 推荐结论：采用下面的表站演出路由，补齐 SET-03 已确定但 SET-07 尚未给出路径的三个页面：

##### REC-02 原因

“历史演出”不能使用 `/archive/`，否则会与 1091 历史快照的叙事路由冲突；剧目详情也需要正式 URL，不能只依赖列表内浮层。


1. 根路径静态重定向到 `/yan/`；第一阶段只生成炎国表站的首页、演出、历史演出、剧团、搜索和票务占位页；
2. 所有国家版本路径由 SET-06 的单一类型化注册表和路由构造函数生成，不手工复制十套路由字符串；
3. 让 `BaseLayout.astro` 接收 `lang`、标题、描述、canonical、robots、主题色和页面类型；
4. 增加表站与里站各自的布局外壳，共享内容仅限真正通用的跳转、页脚声明和基础可访问性结构；
5. 将主导航、品牌链接和页脚链接改为普通路由链接，无 JavaScript 时仍可导航；
6. 将客户端装配改为“先判断页面能力，再初始化对应模块”。必需 DOM 查询只在模块根节点存在后执行；票务和污染等重模块使用动态导入；
7. 移除 `world.ts` 对表里两个面板必须同时存在的假设，过场只作为路由导航的渐进增强。

##### REC-02 可观察验收

- 每个目标 URL 可直接刷新、从外部打开并返回；
- 任一页面缺少其他页面的 DOM 时不会导致全站客户端初始化失败；
- 关闭 JavaScript 后仍可使用主导航、阅读内容和通过普通链接表里切换；
- 页面输出正确的 `lang`、canonical 与 robots。

##### REC-02 非目标

不要在这一切片同时创建十个国家版本的全部页面内容，也不要先建立通用插件注册中心。显式页面装配足以支撑第一批路由，等至少两个高交互模组出现重复装配需求后再抽象。

#### REC-03｜把“剧目”拆成作品与场次两个稳定实体

- 状态：候选，待人工判断
- 优先级：`P0`
- 价值：高
- 成本：中
- 推荐结论：保留 TypeScript 数据源，但将现有 `Show` 逐步拆成至少两个领域实体：

```text
Production   作品与制作：标题、类型、简介、主创、视觉、观演提示
Performance  具体场次：作品 ID、日期时间、城市、场地、状态、分区与基础票价
```

##### REC-03 原因

历史演出、未来演出、一个作品的多个场次、按演出购票以及跨语言复用都需要区分“演什么”和“何时何地演”。继续扩充单个 `Show` 会让日期、票价、搜索和详情出现重复副本。

##### REC-03 最小落地

- 为两个实体保留稳定 ID；所有列表、详情、搜索和票务数据通过 ID 关联；
- 场次使用显式 `upcoming | past | cancelled` 等内容状态，不用浏览器现实时间推导；
- 日期保留可本地化的结构值和泰拉纪年显示规则，不直接依赖现实世界 `Date` 时区；
- 当前基于 `Asia/Shanghai` 的实时钟不进入多版本基础能力；只有内容明确规定泰拉城市时间规则时，才按国家版本或地点重新设计该功能；
- 票务分区和 `basePrice` 只属于可购买场次，作品正文不持有库存或结算状态；

##### REC-03 可观察验收

- 修改一个场次的日期或票价时，列表、详情、搜索和票务入口同步变化；
- 同一作品可以具有多个未来或历史场次而不复制简介与主创；
- 纪念票能从唯一场次与作品来源组合出完整信息。

##### REC-03 非目标

在编辑协作或长篇正文产生真实规模前，不迁移到 Content Collections。

- 推荐结论：保留当前首页的编辑式气质，但把任务型内容迁入独立页面，不把现有单页所有区块原样复制到新首页。

| 页面       | 主要任务                                         | 首页只保留什么                 |
| ---------- | ------------------------------------------------ | ------------------------------ |
| 首页       | 建立品牌可信度，引导进入本季演出或票务           | 主视觉、重点演出、简短剧团介绍 |

- 首页不承担筛选、完整历史、完整剧团说明和搜索结果等互相竞争的任务；
- 用户从任一场次最多经过一次明确选择即可到达剧目详情；
- 剧目详情和主要功能页都可复制 URL、刷新和从搜索结果直接进入。

##### REC-04 非目标

现有“剧团手记”可以先作为首页编辑内容或剧团页内容。只有形成多个持续维护的正式条目后，再建立独立手记栏目；不为了保留当前区块而提前增加一级导航。

#### REC-06｜分两步验证 i18n，不同时制作十套完整内容

- 状态：候选，待人工判断
- 优先级：`P1`
- 价值：高
- 成本：中
- 推荐结论：先建立完整版本注册表和发布门禁，再用炎国正式内容、开发伪本地化和一个真实第二版本验证架构；推荐哥伦比亚 `en-US` 作为首个真实第二版本。

##### REC-06 原因

英文能够较早暴露标题变长、按钮扩张、拉丁字体、换行和搜索别名问题，翻译与校对资源通常也比其余候选语言容易获得。伪本地化只用于开发布局，不作为第十一个公开国家版本。

##### REC-06 最小落地

1. 以 SET-06 矩阵生成类型化 `editionId`、`routePrefix` 和 locale 注册表；
2. 页面壳、导航、元数据和系统反馈使用稳定键，内容实体继续使用稳定 ID；
3. 开发构建允许目标版本回退到中文，并为实际回退节点设置正确 `lang`；
4. 正式构建只生成通过发布门禁的国家版本；
5. 字体初期使用可靠的分语种系统字体栈，不在尚无正式视觉资产时引入覆盖全部文字系统的大型字体包；
6. 日期、时间和数字通过项目格式化层输出，不在组件中拼接中文单位。

##### REC-06 可观察验收

- 增加哥伦比亚版本不要求复制页面组件；
- 长标题、按钮、导航和票面在伪本地化及 `en-US` 下不溢出；
- 未达到 `100%` 的发布版本不会出现在正式构建路由和切换入口中。

##### REC-06 非目标

- 不同时制作十套完整内容；
- 伪本地化不作为公开国家版本；
- 尚无正式视觉资产时，不引入覆盖全部文字系统的大型字体包。

##### REC-07 原因

##### REC-07 最小落地

- 搜索条目只保存稳定 ID、类别、批准标题、摘要、别名和目标 URL，不复制完整正文；
- 每个 `{editionId}:front` 与 `{editionId}:archive:1091` 分别生成静态索引；

##### REC-08 最小落地

###### 表站方向

- 以编辑式排版、剧目主视觉、清晰事务信息和充足留白建立高端感；
- 猩红作为行动与品牌强调色，不让每个区块都使用同等强度的红色；
- 首页可以更具叙事节奏，列表、详情、搜索和票务页优先保证任务效率；
- 正式阶段逐步用拥有权利的原创剧目视觉替代纯 CSS 占位艺术，但不要求第一轮路由迁移同时完成全部插画。

###### 里站方向

- 等级 `0` 先像一个真实存在于 1091 年的剧团网站，而不是预先损坏的恐怖页面；
- 年代感优先来自纸张、油墨、印刷套准、节目单、排演记录、旧照片和信息编排，不依赖 CRT、VHS 或通用故障滤镜；
- 表站与里站可以共享品牌印记、编号方式或某一构图比例，但不共享整套组件皮肤。

###### 最小令牌范围

只先统一字体角色、正文与背景色、强调色、间距级别、内容宽度、层级、焦点样式和动效时长。组件只有在两个以上页面复用且状态相同后才抽象，不为每个区块建立设计系统条目。

基础布局只加载通用基础样式，表站与里站布局分别加载自身视觉层；搜索、票务和污染等样式随对应页面或模组进入。现有大文件按页面迁移的实际需要逐步拆分，不先做与用户结果无关的 CSS 文件重排。

###### 资产切片

第一批正式资产建议只覆盖：首页主视觉、三部作品基础视觉、三张里站记录图像、一个表站品牌标记和一套票面基础模板。每项资产记录来源、许可、替代文本责任和窄屏裁切；视频、音频与大字体包不作为基础框架前置条件。

##### REC-08 可观察验收

- 表站任务页在移除装饰后仍有清晰层级；
- 里站等级 `0` 不依赖污染也能被识别为独立旧剧团网站；
- SET-05 规定的代表性视口下，主视觉裁切和长文本不遮挡主要操作；
- 焦点、错误、选择和污染等级不只依赖颜色表达。

##### REC-08 非目标

- 不建立大而全的设计系统；
- 不整库重写现有分层 CSS；
- 不要求第一轮路由迁移同时完成全部插画、视频、音频或大型字体包。

#### REC-09｜污染效果使用“声明式变体”，不要随机破坏 DOM

- 状态：候选，待人工判断
- 优先级：`P1`
- 价值：高
- 成本：中
- 推荐结论：将可污染区域声明为具名插槽，每个插槽提供经过设计的 `0/1/2/3` 变体；污染状态决定选择哪些变体，不在运行时任意移动、删除或改写 DOM。

##### REC-09 原因

原稿未单独说明。

##### REC-09 最小落地

- 等级 `0` 使用完整原始内容；
- 每个页面只声明少量可污染插槽，例如标题批注、图片状态、记录编号、旁注和受控布局偏移；
- 同一标签页使用稳定种子选择变体，使刷新或重渲染不会不断跳变；
- 使用 `sessionStorage` 保存当前标签页的等级与稳定种子，不写入 Cookie、`localStorage` 或服务端；
- 将概率函数、状态推进和表现选择拆成纯逻辑，开发构建可以注入固定随机值；
- 正式构建从产物中移除污染调试控件，而不是仅隐藏；
- 站内点击、搜索提交和版本切换在导航前完成一次判定并保存新状态；直接 URL 访问在目标页完成一次入口判定。页面从已保存状态渲染，不能因源页和目标页各自处理而重复计算；
- 必要时用最小的页面头部状态引导在首次绘制前设置污染等级；状态读取失败则按等级 `0` 渲染，不用全页遮罩掩盖闪变；
- 退出和页脚声明永远位于不受污染的稳定层。

##### REC-09 可观察验收

- 自动化输入固定随机序列时可以复现全部等级；
- 任何等级都不改变语义结构、键盘顺序、焦点、替代文本和退出；
- 关闭动态效果后仍能通过静态内容差异理解污染升级；
- 不需要为每个随机结果编写页面级 CSS 补丁。

##### REC-09 非目标

不使用全页 Canvas 噪声、WebGL 故障、随机 DOM 重排、持续闪烁、伪浏览器警告或强制全屏。这些方案成本高、难以验收，也削弱“旧网站本身可信”的前提。

### P2：高互动模组与可选彩蛋

#### REC-10｜购票模组采用显式状态机与 SVG 票面

- 状态：候选，待人工判断
- 优先级：`P2`
- 价值：高
- 成本：中至高
- 推荐结论：在演出场次模型稳定后实现购票；流程状态和票面生成分别演进，第一版纪念票使用 SVG 与打印样式，不把 PDF、账号或真实支付作为前置条件。

##### REC-10 原因

SVG 适合第一版，因为它可以无损缩放、打印并组合文字和印章。若浏览者反馈确实需要位图，再追加 PNG 导出。

##### REC-10 最小落地

1. **选择层**：读取可购买 `Performance`，管理每场一张、分区和票篮；席位使用 `C/B/A/S/包厢` 区域示意图，不制作单个座位选座系统；
2. **流程层**：使用类型化节点描述选项、概率、金额差额、印章和下一节点，不用层层嵌套的条件语句写死完整剧本；
3. **结果层**：失败与波动保留票篮，成功冻结只读存单和纪念票；
4. **产物层**：每场票由作品基础 SVG、场次文字、随机数值二维码和本次统一印章组组合；屏幕打印使用同一来源；
5. **存储层**：使用 `sessionStorage` 保存当前标签页范围的最小状态，不使用 `localStorage`、账号或服务端；
6. **装配层**：票务脚本延迟加载，未启用或加载失败时稳定回到“暂未开票”页面。

##### REC-10 可观察验收

- 至少覆盖成功、失败、网络波动和加价线路成功/失败；
- 失败、波动和取消支线后票篮不丢失；
- 一至三个所选场次分别生成票面，同次结局的印章语义一致；
- 存单显示基础总额、差额明细和结算总额，票面只显示 `basePrice`；
- 票面无需身份、登录、二次任务即可下载和打印。

##### REC-10 非目标

不把 PDF、账号、真实支付或为了模拟真实票务而引入的 PDF 生成依赖作为第一版前置条件。
