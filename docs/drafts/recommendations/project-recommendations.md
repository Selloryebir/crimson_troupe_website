### 后续开发阶段

#### REC-09｜用稳定的声明式变体实现污染

- 状态：候选，建议纳入 S4
- 优先级：`P1`
- 价值：高
- 成本：中
- 推荐结论：将污染实现为当前标签页中的纯状态机与受控呈现变体，不随机破坏 DOM 或底层内容。

##### REC-09 原因

稳定变体可以同时满足固定概率、等级单调上升、浏览器历史恢复、可复现测试和不可污染的技术底线；随机移动或删除 DOM 无法可靠满足这些约束。

##### REC-09 最小落地

- 由单一配置保存 `42%`，由纯逻辑处理等级、白名单事件和封顶；每个用户动作最多判定一次；
- 使用标签页范围状态保存等级和稳定变体选择，不使用 Cookie、跨标签同步或服务端状态；
- 页面只声明少量可污染槽位，等级上升时保留、强化或明确替代已有异常；
- 浏览器前进后退、刷新和重渲染不追加判定，主动返回表站清除状态；
- 开发构建允许指定等级和随机结果，正式构建从产物中移除调试控制；
- 退出、页脚声明、语义、焦点、替代文本、视口安全和减少动态效果始终使用稳定层。

##### REC-09 可观察验收

- 固定随机序列可以复现四个等级和全部触发类型；
- 任何等级都不会改变搜索范围、内容归属、键盘顺序或可靠退出；
- 等级上升不会因为重新渲染而减弱或随机跳换已经成立的异常；
- 状态不可用时等级 `0` 网站仍可完整浏览。

##### REC-09 非目标

- 不使用随机 DOM 重排、持续闪烁、强制全屏、伪系统警告或全页不可关闭遮罩。

#### REC-10｜用显式状态机实现表站票务模组

- 状态：候选，建议纳入 S5
- 优先级：`P1`
- 价值：高
- 成本：中至高
- 推荐结论：在场次数据和票务占位页稳定后实现表站购票模组；流程状态与纪念票渲染分离，第一版优先使用 SVG 和打印样式满足下载与收藏。

##### REC-10 原因

`BP-MOD-TICKETING` 已确定票篮、重试、价格、成功存单和逐场纪念票的契约。显式状态机便于保证失败后保留票篮、成功后冻结结果，并避免流程分支散落在页面事件中；SVG 可以用较少依赖组合文字、二维码和印章。

##### REC-10 最小落地

1. 选择层从可购买 `Performance` 读取分区和 `basePrice`，按场次限购一张；
2. 尝试层用类型化节点表达选择、概率、金额差额、印章和下一节点，不修改票篮事实；
3. 结果层覆盖成功、失败和网络波动；失败与波动保留票篮，成功冻结只读存单和票面；
4. 产物层从同一票务结果为每个场次生成一张票，并让同次结局使用同一组印章语义；
5. 当前标签页保存最小流程状态，不收集身份，不引入账号、支付或远端请求；
6. 模组未启用、无 JavaScript 或加载失败时，稳定地址继续显示“暂未开票”和有效返回路径；
7. SVG 是第一版实现建议，不写成领域事实；若实际下载或字体兼容验证失败，再在同一内容源上调整格式。

##### REC-10 可观察验收

- 失败、波动、取消支线和主动重试不会丢失票篮；
- 成功存单区分基础总额、差额和结算总额，每张票只显示对应基础票价；
- 每张票无需身份、登录或二次任务即可下载和打印；
- 模组关闭或失败时不影响表站其他任务。

##### REC-10 非目标

- 不实现真实支付、账号、订单兑换、全局唯一编号、PDF 前置依赖或单座位选座；
- 不为 CRE-01 预留异常购票分支，里站继续执行不可购买规则。

### 后续阶段收口

#### REC-13｜按可验证纵向切片完成当前阶段

- 状态：S2 已完成、S3 已转入计划；仅保留 S4～S6 后续顺序
- 优先级：`P0`
- 价值：高
- 成本：中
- 推荐结论：按下表顺序推进，每个切片形成可直接观察的页面或模组结果；日常执行最小相关检查，只在跨层集成和最终候选阶段运行完整验证。

##### REC-13 原因

路由、内容、样式和交互共同变化时，按技术层批量重写会长时间失去可浏览基线。纵向切片可以尽早暴露路由、数据和体验边界问题，同时避免每轮重复运行无关门禁。

##### REC-13 最小落地

| 切片 | 可交付结果                       | 主要工作                                                           | 暂不处理             |
| ---- | -------------------------------- | ------------------------------------------------------------------ | -------------------- |
| S4   | 污染主线闭环                     | 四级状态、白名单判定、声明式变体、历史恢复、生产调试排除           | 票务流程             |
| S5   | 表站票务支线闭环                 | 票篮、分支、重试、结局、存单、逐场票面、下载与打印                 | 额外模组             |
| S6   | 简体中文双站形成当前阶段正式候选 | 批准内容和素材、跨层集成、关键旅程、性能、无障碍与构建产物完整验证 | 非中文版本、附加模块 |

每个切片只更新实际改变的蓝图和追踪映射，并运行与改动相称的最小检查；工具链、跨层集成或 S6 才运行完整 `verify`，不得让 `quality` 与 `build` 重复执行相同门禁。

S6 只需完整验证以下五条用户旅程：

1. 表站首页 → 本季或历史演出 → 场次/剧目详情 → 票务入口；
2. 表站首页或内页 → 剧团/搜索 → 内容详情或明确无结果反馈；
3. 表站彩蛋入口 → 1091 首页 → 里站浏览 → 返回同国家版本表站首页；
4. 直接访问 1091 深层页面 → 里站搜索与污染升级 → 浏览器历史恢复或主动退出；
5. 表站票篮 → 失败/波动重试或成功 → 存单与逐场纪念票 → 下载、打印或退出。

##### REC-13 可观察验收

- 每个切片结束时，已承诺页面仍可构建和直接浏览，失败路径不会留下断路；
- S6 在桌面、320～500 CSS 像素窄屏、键盘和减少动态效果下完成五条旅程；
- 静态产物的目标路径、内部链接、本地资源、`lang`、canonical、robots 和重复 ID 检查通过；
- 表站和等级 `0` 里站在无 JavaScript 时核心内容可读，高交互模组失败时可以返回；
- 正式产物只包含通过门禁的 `yan / zh-CN` 网站。

##### REC-13 非目标

- 不把切片表写入长期正式契约；
- 不为静态页面提前建立大型自动化测试体系，也不把全部文案和装饰做成快照；
- 不在当前阶段加入非中文版本或附加模块。
