## 正文

### 建议解释规则

1. 已确认的产品事实只读取 `docs/drafts/blueprint/scope-alignment.md`；延期的里站异常购票只读取 `docs/drafts/creative/archive-anomalous-ticketing.md`。本文件不复制或重新裁决其正文。
2. REC 状态只表示建议适用阶段：`候选，迁移阶段`、`候选，迁移后开发阶段` 或 `候选，当前阶段收口`，不表示已经获得实施授权。
3. 当前阶段只交付可验证的简体中文双站。国家版本矩阵和 locale 感知边界需要具备扩展能力，但不开发第二语言内容、公开路由或切换选项。
4. 正式迁移完成后，源码开发只读取 active 蓝图。届时本文件只提供切片与实现取舍，不得覆盖正式契约。
5. 当前阶段完成后删除已失效或已转入一次性开发计划的建议，不把本文件维护成长期 backlog。

### 当前判断

现有 Demo 已证明 Astro 静态构建、原生 TypeScript 交互、响应式视觉和双时间层概念可以运行，但仍以单页原型为装配前提：

- `src/pages/index.astro` 在同一 HTML 中装配表站、里站和全部浮层；
- `src/scripts/main.ts` 无条件初始化全部客户端模块，模块之间依赖同一页面的 DOM；
- 搜索、剧目详情和票务入口仍主要由 `SiteDialogs.astro` 承载；
- `src/data/shows.ts` 的 `Show` 同时持有剧目、场次和展示字段；
- 当前搜索数据和 `world.ts` 仍允许在同一页面中切换世界，与已确认的独立路由和搜索隔离口径不一致。

因此当前不适合继续向原单页横向追加功能。最小可行路径是先完成一次正式蓝图迁移，再按页面与用户结果逐步替换旧装配；既有代码和视觉只作为可复用素材，不默认成为新架构约束。

### 蓝图迁移阶段

#### REC-01｜完成一次有边界的正式蓝图迁移

- 状态：候选，迁移阶段
- 优先级：`P0`
- 价值：高
- 成本：低至中
- 推荐结论：新增目标源码前，按统筹草稿的反向定位一次性迁移 SET-01 至 SET-12；迁移与页面重写分开进行。

##### REC-01 原因

当前正式蓝图、架构说明和 Demo 源码仍保留单页切换、旧时间口径和旧领域模型。若先改源码，开发者会同时面对新草稿与旧正式蓝图两套相反约束。

##### REC-01 最小落地

1. 按统筹草稿的“正式蓝图定位”更新现有蓝图，并新增其中已确定的 `BP-FND-DOMAIN` 与 `BP-MOD-TICKETING`；
2. 按“支持文档定位”同步蓝图索引、架构说明和仓库入口，不把建议正文写入正式文件；
3. 仅在蓝图依赖或源码映射确实改变时更新 `docs/blueprint/traceability.json`，不为未来源码预填映射；
4. 对被修改的蓝图运行一次影响定位，核对候选文件后只处理真实影响；
5. 迁移完整后从统筹草稿删除对应 SET 与定位行；若全部 SET 均已迁移且没有问题项，按草稿规则删除整份统筹草稿。

##### REC-01 可观察验收

- 正式蓝图不存在与 SET-01 至 SET-12 相反的旧契约；
- 每项正式事实只有一个责任蓝图，演出领域术语与票务模组具有明确归属；
- `npm run blueprint:check` 和与文档改动相称的最小质量检查通过；
- 迁移后的每个后续源码切片都能反向定位到 active 蓝图。

##### REC-01 非目标

- 不同时修改 `src/`；
- 不把迁移过程、检查日志或本建议稿写入正式蓝图；
- 不迁移任何未采纳创意。

### 迁移后开发阶段

#### REC-02｜建立炎国双站的多页面装配基线

- 状态：候选，迁移后开发阶段
- 优先级：`P0`
- 价值：高
- 成本：中
- 推荐结论：以迁移后的路由、双时间层和体验蓝图为依据，先建立只发布 `yan / zh-CN` 的表站与 1091 里站页面树。

##### REC-02 原因

独立 URL、直达、浏览器历史、搜索隔离和无 JavaScript 导航都依赖真正的多页面结构；继续在同一 HTML 中显隐两个世界会让后续污染、票务和索引状态继续耦合。

##### REC-02 最小落地

1. 用一个类型化国家版本注册表和路由构造器提供 `editionId`、`routePrefix` 与 locale；当前正式发布集合只有 `yan / zh-CN`；
2. 按正式路由蓝图生成炎国表站与 1091 里站页面，不在本建议稿复制第二套路由清单；
3. 表站和里站使用独立页面布局、导航、内容入口、视觉资源和客户端状态，只共享基础文档结构、页脚声明与无障碍能力；
4. 普通链接承担主导航、品牌返回和表里切换，过场仅作为路由导航的渐进增强；
5. 页面外壳显式接收 `lang`、标题、描述、canonical、robots、世界和页面类型；
6. 客户端按页面能力初始化。页面没有某个模组根节点时直接跳过，污染和票务代码按需加载；
7. 删除 `world.ts` 对两个世界面板同时存在的依赖，不保留旧锚点作为并行入口。

##### REC-02 可观察验收

- 每个已实现 URL 可以直接打开、刷新、复制和通过浏览器历史返回；
- 任一页面缺少其他页面的 DOM 时不会中断客户端装配；
- 关闭 JavaScript 后，核心内容、主导航和表里返回路径仍可使用；
- 生成页面的 `lang`、canonical、robots 和站内链接符合正式蓝图。

##### REC-02 非目标

- 不生成或公开第二国家版本；
- 不在页面骨架切片同时完成全部内容、视觉资产、污染或票务流程；
- 不预建通用插件平台。

#### REC-03｜按正式领域模型重构类型化内容

- 状态：候选，迁移后开发阶段
- 优先级：`P0`
- 价值：高
- 成本：中
- 推荐结论：保留本地 TypeScript 内容源，但以正式领域术语蓝图替代现有 `Show` 混合模型，再让页面、搜索和票务共同引用稳定 ID。

##### REC-03 原因

现有 `Show` 无法稳定表达一个场次编排多个剧目、同一剧目进入多个场次，以及场次独有的日期、地点、状态和票价。若各页面自行拆字段，会形成新的重复事实源。

##### REC-03 最小落地

- 依照正式领域术语蓝图建立 `Production`、`Performance`、`TicketBasket` 和泰拉时间的类型边界，不在实现层重新定义其语义；
- `Performance` 通过稳定 ID 和有序关联引用 `Production`，页面数据、搜索条目和票务选择都由相同来源派生；
- 集合归属和票务可用性使用显式内容状态，不依赖浏览器现实时间；
- 国家版本与翻译内容通过稳定内容 ID 关联，标题和显示名不参与路径或实体身份推导；
- 在编辑协作或长篇内容出现真实规模前继续使用现有本地数据目录，不提前迁移 Content Collections。

##### REC-03 可观察验收

- 修改一个场次的日期、地点、状态或基础票价时，相关列表、详情、搜索和票务入口使用同一结果；
- 同一剧目可以被多个场次复用，一个场次也可以按顺序引用多个剧目；
- 页面和票务代码不再直接依赖旧 `Show` 混合对象。

##### REC-03 非目标

- 不在领域重构时重写全部文案或视觉；
- 不为未来后台、账号或远端 CMS 设计数据层。

#### REC-04｜以任务页面完成表站与等级 0 里站

- 状态：候选，迁移后开发阶段
- 优先级：`P0`
- 价值：高
- 成本：中至高
- 推荐结论：先让表站和未污染的 1091 里站分别成为完整网站，再在其上装配污染与票务模组。

##### REC-04 原因

表站需要先以清晰任务和专业运营口吻建立可信度；里站等级 `0` 也必须依靠自身内容、编排和年代媒介成立，不能依赖污染填补页面完整性。

##### REC-04 最小落地

- 表站首页负责品牌与重点内容，演出、历史、剧团和搜索分别在独立页面完成主要任务；票务保持次级入口；
- 里站实现正式蓝图要求的等级 `0` 页面集合与独立内容，里站票务页只给出历史快照语境下的不可购买反馈和返回路径；
- 建立少量共享基础令牌，以及表站和里站各自的排版、色彩、媒介质感与页面模板；只在两个以上页面具有相同语义和状态时抽取组件；
- 逐页复用现有成熟 CSS 与交互，不先进行与页面结果无关的整库样式重排；
- 运行时素材只纳入当前页面确实需要且权利状态明确的内容，不预设固定资产数量；
- 所有页面遵守正式蓝图中的文案口吻、页脚声明、代表视口、键盘和减少动态效果边界。

##### REC-04 可观察验收

- 不进入彩蛋时，表站仍能完成发现演出、理解剧团、搜索和到达票务入口的主要任务；
- 等级 `0` 里站在没有污染时已经具有独立年代感、完整导航和有效返回路径；
- 320 CSS 像素起的目标视口不出现页面级内容丢失或主要操作遮挡；
- 表站与里站可以共享品牌线索，但不会被理解为同一组件的明暗换肤。

##### REC-04 非目标

- 不建立大而全的设计系统；
- 不要求首轮同时完成全部插画、视频、音频或大型字体包。

#### REC-06｜只实现简体中文发布基线

- 状态：候选，迁移后开发阶段
- 优先级：`P0`
- 价值：高
- 成本：低至中
- 推荐结论：当前阶段实现 locale 感知的工程边界，但只制作、审核和发布炎国 `yan / zh-CN` 内容。

##### REC-06 原因

SET-08 已确定其他语言必须等待简体中文网站整体通过发布门禁。提前选择第二语言或制作不完整公开版本会扩大当前切片并制造返工。

##### REC-06 最小落地

1. 以正式国家版本矩阵生成类型化注册数据，显示名、URL 前缀和技术 locale 不互相推导；
2. 页面壳、导航、系统反馈、元数据和内容读取接口接受 locale，但当前 `releaseLocales` 只包含 `zh-CN`；
3. 语言区域可以显示当前语言，不渲染空下拉、未开发选项或“即将推出”入口；
4. 日期、数字、搜索归一化和辅助技术语言使用 `zh-CN` 规则，不在组件中散落语言判断；
5. 当前阶段不建立第二语言翻译范围清单；该动作只在简体中文网站通过人工发布审核后启动。

##### REC-06 可观察验收

- 简体中文双站不依赖其他语言即可构建、审核和发布；
- 页面与内容代码没有把 `/yan/`、中文单位或显示标题当作跨版本实体身份；
- 正式产物不包含未开发国家版本的页面和可操作入口。

##### REC-06 非目标

- 不选择首个第二国家版本；
- 不制作其他语言译文、公开 fallback 页面或跨语言搜索；
- 不建立长期翻译进度数据库。

#### REC-07｜为炎国表站和里站生成独立搜索索引

- 状态：候选，迁移后开发阶段
- 优先级：`P1`
- 价值：高
- 成本：中
- 推荐结论：保留构建期类型化索引和浏览器内查询，只实现当前 `yan / zh-CN` 表站与 1091 里站两个隔离作用域。

##### REC-07 原因

当前搜索把里站入口与表站内容放入同一索引。新口径要求搜索只在当前国家版本、世界和快照年份内返回结果，且搜索页本身具有正式 URL。

##### REC-07 最小落地

- 索引条目只保存稳定 ID、类别、批准标题、摘要、别名和目标 URL，不复制完整正文；
- 从同一内容源分别生成炎国表站与 1091 里站索引，不在浏览器加载全站索引后过滤；
- 搜索页承担查询和结果，快捷键或浮层只作为进入该页面的增强方式；
- 空查询、无结果、索引不可用和无 JavaScript 状态均提供可理解反馈；
- 里站结果可以被污染呈现，但不得修改索引归属、源数据或目标路由。

##### REC-07 可观察验收

- 表站查询不能得到里站结果，里站查询不能得到表站结果；
- 结果链接可直接访问且始终留在当前搜索作用域；
- 一次里站搜索提交只触发一次污染判定。

##### REC-07 非目标

- 不引入远端搜索服务或大型索引依赖；
- 不为尚未开发的国家版本生成搜索索引。

#### REC-09｜用稳定的声明式变体实现污染

- 状态：候选，迁移后开发阶段
- 优先级：`P1`
- 价值：高
- 成本：中
- 推荐结论：将污染实现为当前标签页中的纯状态机与受控呈现变体，不随机破坏 DOM 或底层内容。

##### REC-09 原因

稳定变体可以同时满足固定概率、等级单调上升、浏览器历史恢复、可复现测试和不可污染的技术底线；随机移动或删除 DOM 无法可靠满足这些约束。

##### REC-09 最小落地

- 由单一配置保存 `42%`，由纯逻辑处理等级、白名单事件和封顶；每个用户动作最多判定一次；
- 使用标签页范围状态保存等级和稳定变体选择，不使用 Cookie、跨标签同步或服务端状态；
- 页面只声明少量可污染槽位，等级上升时保留、强化或明确替代已有异常；
- 浏览器前进后退、刷新和重渲染不追加判定，主动返回表站清除状态；
- 开发构建允许指定等级和随机结果，正式构建从产物中移除调试控制；
- 退出、页脚声明、语义、焦点、替代文本、视口安全和减少动态效果始终使用稳定层。

##### REC-09 可观察验收

- 固定随机序列可以复现四个等级和全部触发类型；
- 任何等级都不会改变搜索范围、内容归属、键盘顺序或可靠退出；
- 等级上升不会因为重新渲染而减弱或随机跳换已经成立的异常；
- 状态不可用时等级 `0` 网站仍可完整浏览。

##### REC-09 非目标

- 不使用随机 DOM 重排、持续闪烁、强制全屏、伪系统警告或全页不可关闭遮罩。

#### REC-10｜用显式状态机实现表站票务模组

- 状态：候选，迁移后开发阶段
- 优先级：`P1`
- 价值：高
- 成本：中至高
- 推荐结论：在场次数据和票务占位页稳定后实现表站购票模组；流程状态与纪念票渲染分离，第一版优先使用 SVG 和打印样式满足下载与收藏。

##### REC-10 原因

SET-11 已确定票篮、重试、价格、成功存单和逐场纪念票的契约。显式状态机便于保证失败后保留票篮、成功后冻结结果，并避免流程分支散落在页面事件中；SVG 可以用较少依赖组合文字、二维码和印章。

##### REC-10 最小落地

1. 选择层从可购买 `Performance` 读取分区和 `basePrice`，按场次限购一张；
2. 尝试层用类型化节点表达选择、概率、金额差额、印章和下一节点，不修改票篮事实；
3. 结果层覆盖成功、失败和网络波动；失败与波动保留票篮，成功冻结只读存单和票面；
4. 产物层从同一票务结果为每个场次生成一张票，并让同次结局使用同一组印章语义；
5. 当前标签页保存最小流程状态，不收集身份，不引入账号、支付或远端请求；
6. 模组未启用、无 JavaScript 或加载失败时，稳定地址继续显示“暂未开票”和有效返回路径；
7. SVG 是第一版实现建议，不写成领域事实；若实际下载或字体兼容验证失败，再在同一内容源上调整格式。

##### REC-10 可观察验收

- 失败、波动、取消支线和主动重试不会丢失票篮；
- 成功存单区分基础总额、差额和结算总额，每张票只显示对应基础票价；
- 每张票无需身份、登录或二次任务即可下载和打印；
- 模组关闭或失败时不影响表站其他任务。

##### REC-10 非目标

- 不实现真实支付、账号、订单兑换、全局唯一编号、PDF 前置依赖或单座位选座；
- 不为 CRE-01 预留异常购票分支，里站继续执行不可购买规则。

### 当前阶段收口

#### REC-13｜按可验证纵向切片完成当前阶段

- 状态：候选，当前阶段收口
- 优先级：`P0`
- 价值：高
- 成本：中
- 推荐结论：按下表顺序推进，每个切片形成可直接观察的页面或模组结果；日常执行最小相关检查，只在跨层集成和最终候选阶段运行完整验证。

##### REC-13 原因

路由、内容、样式和交互共同变化时，按技术层批量重写会长时间失去可浏览基线。纵向切片可以尽早暴露路由、数据和体验边界问题，同时避免每轮重复运行无关门禁。

##### REC-13 最小落地

| 切片 | 可交付结果                       | 主要工作                                                           | 暂不处理                 |
| ---- | -------------------------------- | ------------------------------------------------------------------ | ------------------------ |
| S0   | 唯一正式口径                     | 迁移 SET-01～SET-12，更新必要索引、架构和追踪                      | 源码实现                 |
| S1   | 炎国双站路由与领域骨架           | 版本注册、页面布局、根跳转、元数据、按页装配、领域数据             | 完整内容、污染、票务流程 |
| S2   | 简体中文表站核心任务可用         | 首页、演出、历史、剧团、详情、表站搜索、票务占位、表站视觉         | 污染、票务流程           |
| S3   | 1091 等级 `0` 里站完整可浏览     | 里站页面、内容、搜索、不可购票页、直达、返回、年代视觉             | 污染                     |
| S4   | 污染主线闭环                     | 四级状态、白名单判定、声明式变体、历史恢复、生产调试排除           | 票务流程                 |
| S5   | 表站票务支线闭环                 | 票篮、分支、重试、结局、存单、逐场票面、下载与打印                 | 额外模组                 |
| S6   | 简体中文双站形成当前阶段正式候选 | 批准内容和素材、跨层集成、关键旅程、性能、无障碍与构建产物完整验证 | 非中文版本、附加模块     |

每个切片只更新实际改变的蓝图和追踪映射，并运行与改动相称的最小检查；工具链、跨层集成或 S6 才运行完整 `verify`，不得让 `quality` 与 `build` 重复执行相同门禁。

S6 只需完整验证以下五条用户旅程：

1. 表站首页 → 本季或历史演出 → 场次/剧目详情 → 票务入口；
2. 表站首页或内页 → 剧团/搜索 → 内容详情或明确无结果反馈；
3. 表站彩蛋入口 → 1091 首页 → 里站浏览 → 返回同国家版本表站首页；
4. 直接访问 1091 深层页面 → 里站搜索与污染升级 → 浏览器历史恢复或主动退出；
5. 表站票篮 → 失败/波动重试或成功 → 存单与逐场纪念票 → 下载、打印或退出。

##### REC-13 可观察验收

- 每个切片结束时，已承诺页面仍可构建和直接浏览，失败路径不会留下断路；
- S6 在桌面、320～500 CSS 像素窄屏、键盘和减少动态效果下完成五条旅程；
- 静态产物的目标路径、内部链接、本地资源、`lang`、canonical、robots 和重复 ID 检查通过；
- 表站和等级 `0` 里站在无 JavaScript 时核心内容可读，高交互模组失败时可以返回；
- 正式产物只包含通过门禁的 `yan / zh-CN` 网站。

##### REC-13 非目标

- 不把切片表写入长期正式契约；
- 不为静态页面提前建立大型自动化测试体系，也不把全部文案和装饰做成快照；
- 不在当前阶段加入非中文版本或附加模块。
