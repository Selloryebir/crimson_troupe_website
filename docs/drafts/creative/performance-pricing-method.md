#### CRE-01 素材与实现提示

- 全部报价集中存为“`productionId` → 场馆报价键 → 五元组”的稀疏矩阵，由唯一函数按 `[C, B, A, S, BOX]` 转为 `TicketOffer[]`；`Performance` 只引用结果，不复制数值。
- 五元组使用数字与 `'-'` 的类型化元素，不使用需要解析的斜杠字符串。`'-'` 表示该矩阵单元不存在对应分区。
- 蒙特卢佩样本只提供 `C / B / A`，用于验证分区子集；这只是当前场次事实，不定义蒙特卢佩所有场馆永远没有 `S / BOX`。
- 全部国家版本继续复用数值，只本地化分区标签；价格不写入翻译包。
- 等级 `3` 可在呈现层重释席位关系，但不能覆盖或回写本表进入的等级 `0` 数据。

### CRE-02｜未来正式定价方法候选

- 状态：候选，待未来人工独立规划
- 内容类型：定价规则方向
- 适用时间层：未来可能覆盖表站和里站的正式场次内容
- 内容目的：在正式内容阶段把地点条件、剧目规模和席位等级转为可解释价格，而不是继续人工凭感觉填表
- 预期入口：未来内容编辑或构建期价格生成；当前阶段不提供运行时入口
- 设定边界：未确定字段、权重、公式、舍入、历史经济差异和人工覆盖规则，不得在当前源码启用
- 正式迁入目标：未来人工采纳后判断 `BP-CNT-CORE`、`BP-MOD-PROGRAMS`、票务蓝图、领域 schema 与唯一运行时内容源

#### CRE-02 内容正文或叙事蓝本

未来定价可以由三组语言无关的结构化输入共同决定：

1. **地点与场馆：** 城市经济和巡演成本、场馆等级、容量、设施与可用席位集合；
2. **剧目规模：** 结构化的分钟数、幕或章节数量，以及经过人工定义的制作规模等级；
3. **席位等级：** `C / B / A / S / BOX` 的相对系数和场馆实际可用子集。

最终模型可以采用“场馆基价 × 剧目系数 × 席位系数后统一舍入”的方向，也可以采用人工报价加规则校验；二者在正式规划前不作选择。无论采用哪种方法，都必须允许场次级人工覆盖并保留可解释来源，不能解析“约 110 分钟”“五章”等本地化显示文字计算价格。

#### CRE-02 素材与实现提示

- 若未来启用，应先为分钟数、结构数量和制作规模建立语言无关字段，再讨论计算函数；不从现有译文反向抽取。
- 地点候选池只提供参考，不自动等同于经济系数；场馆等级和价格关系需要人工内容研究。
- 正式模型应离线或构建期计算并落为 `TicketOffer`，页面消费者仍只读取确定报价，不在浏览器中动态推算。
- 不因保留这一方向提前新增空字段、规则引擎、配置开关或未使用模块。
