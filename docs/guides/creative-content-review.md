# 演出创意审查与替换

本指南执行已有内容、领域、时间与本地化契约，不授予正式内容资格，也不把年鉴研究当作完整官方世界史。它适用于剧目、地点与剧场、人物、排期、售票、延期、取消，以及这些事实的多语言表达。研究分支负责证据与流程；运行时仍只消费 `src/data/` 的唯一内容快照。

## 主动审查

开发智能体在相关信息新增、修改、删除后主动完成本节流程，无需再次请求“是否审查”的授权。这项持续授权包括查证、内部一致性检查、AI 预览翻译、客观缺陷修正和修正建议，不包括替人工选择剧情方向、改写已采纳项目前提、批准正式译文或执行 Git 晋级。

1. 先运行 `npm run review:creative:plan`，读取相对上次审查的新增、修改、删除路径及当前指纹。首次接入或记录丢失时做全量基线审查；普通更新只审查变化和实际关联范围。
2. 阅读实际补丁和关联内容，按下表完成语义审查。文件指纹只是触发器；纯排版、等价重构也可能触发，此时核对没有内容或行为语义变化后，记录 `no-creative-change` 及具体理由即可，不重做年鉴研究。
3. 给每个发现提供实体／字段定位、来源定位、判断级别和可执行建议。分清确定冲突、来源分歧、证据不足、项目原创与普通改进；未知不写成“符合官方”，原创也不因找不到同名官方记录而判错。
4. 完成修正建议与关联复核后，由实际执行审查的智能体写入报告，通过 `npm run review:creative:record -- <报告.json>` 保存当前记录。未受影响的待处理发现继续保留；关闭已有发现时，在 `resolutions` 中用 `findingKey` 精确对应原发现，逐项写明修正理由与可定位证据；跨文件补证可以闭环，不要求为消项修改原定位文件。纯排版／重构不得清空旧问题。命令只验证报告结构、路径和指纹一致，不能代替阅读、推理或生成审查结论。记录前若内容再次变化，重新定位增量，不能把旧报告直接换成新指纹。
5. 执行与改动相称的 `quality`；完整候选使用一次 `verify`。门禁读取同一当前记录，内容未变时直接复用，不重复调用 AI、不访问网络。记录过期时明确失败，智能体应继续审查和处理，不以失败为由每次向人工索取检查授权。

| 维度                   | 必查关系                                                                                           | 依据                                                             |
| ---------------------- | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 时间 `chronology`      | 事件、演出、获知、公告、捕获时间分别成立；城市与人物在该时段是否存在／在场；不把年精度补成确定月日 | [时间审核方法](temporal-content-review.md)、年鉴事件与日期主张   |
| 设定 `worldview`       | 官方事实、项目已采纳前提、原创补写分层；身份／时代名不混淆，叙事角色不能知道未来或秘密             | [项目时间前提](../project/temporal-context.md)、来源表与术语证据 |
| 内部一致 `consistency` | 同一实体在剧目、场次、剧场、公告、售票、搜索与各语言中相符；删除无悬空引用                         | 领域数据、根集合、现有内容／状态验证器                           |
| 快照 `snapshots`       | 同期正文、现代档案说明、污染投影分离；未来快照不能覆写既有历史；状态以该捕获时刻为准               | 内容与时间蓝图、快照解析器                                       |
| 翻译 `localization`    | 事实、时态、否定、语气、专名、称谓、量价和日期一致；AI 候选不冒充人工译审                          | 本地化契约、术语研究、源修订摘要                                 |

自动触发覆盖领域与本地化数据、页面／布局／组件及客户端 TypeScript（防止内联文案漏检），以及年鉴、术语证据、`docs/sources/` 下全部已支持的文本来源（Markdown／MDX、JSON／JSON5、CSV／TSV、TXT、TOML、XML、YAML）（包含未来新增子目录）、已采纳时间前提和本指南。新增、删除、已提交变更与未跟踪内容均比较实际文件内容，不只看 `git diff HEAD`。每次 `quality`（包括限定 CSS／文档路径）先核对全局创意指纹，避免漏掉已提交但未审的变化。纯 CSS、图片二进制和未采用草稿不改变创意指纹；草稿在被选择接入运行时时审查。若未来将创意正文移入新格式或新目录，必须同步扩展触发范围和测试。

年鉴或术语证据更新、项目时间前提变化，即使运行时文字未变，也应重审受影响关系。相关创意变更及准备晋级时，智能体主动定向核对受影响的官方来源是否有新材料；纯技术变更不反复联网。本地证据不足、互相矛盾或无法读取官方材料时明确记录限制，不能以无搜索结果断言不存在冲突。新证据先进入现有来源记录，保留来源身份、实际读取方式和核对时间，再审查关联内容。本阶段不建立定时联网监测；尚未被读取或登记的外部更新无法由离线指纹自动发现，不能承诺对所有未来官方更新零延迟或零历史债。审查记录仅保留当前指纹、结论和待处理建议，不保存第二份演出事实、不维护永久审批历史、不参与网站构建。已有待考据项在内容未变时不反复开审；出现新证据时重新判断。

## 演出信息替换

先确认替换的是同一实体的新表达、同一场次的排期变化，还是另一项演出。稳定 ID 不因译名、标题、日期或路径中的旧年份而改名；新的实体使用新的稳定 ID，不拿旧 ID 代表另一座城市或另一个人。

| 替换对象           | 唯一事实入口                                                                                      | 必须联动核对                                                                                         |
| ------------------ | ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 剧目               | `src/data/productions/`；显示正文在 `src/data/localized/`；活页来源集中在 `folio-source-texts.ts` | 剧目与场次引用、素材、官方活页逐字字段、九版本详情与搜索                                             |
| 地点／剧场         | `src/data/locations.ts` 与各版本 `programs.ts`                                                    | 城市身份、当时名称、场馆可用性、地址语气、关联座席；场馆文案不能另设一份地点事实                     |
| 场次／排期／状态   | `src/data/performances.ts` 及完整变体                                                             | `effectiveDateTime`、必要的 `previousDateTime`、`status`、原因及公告、票务、窗口派生；不在页面硬编码 |
| 购票／价格／座席   | 场次 `ticketAvailability`、`performance-offers.ts`、`ticket-seating-plans.ts`                     | 区域与拓扑、票价、平台品牌、列表／详情／票面可购买性；保持概念交互边界                               |
| 网站时点／获选集合 | `site-time.ts`、`content/root-sets.ts` 与构建上下文                                               | 时间层、公开窗口、本季／历史、首页焦点、搜索与票务闭包；不使用现实系统时间                           |
| 多语言             | 稳定实体对应的完整本地化单元                                                                      | 中文源修订、译文完整度、公告与检索文字、日期语义、正式批准摘要失效                                   |

具体处理顺序：先在作者侧确定内容及证据关系，再修改唯一领域来源和完整预览单元，补齐所有实际消费它的语言与依赖，最后验证同一快照派生结果。只按真实依赖扩散，不为了整齐批量改无关记录或刷新全部语言摘要。验证器按实际获选集合和依赖闭包检查，不把当前剧目／场次数量当作永久配额；官方活页逐字来源等确有固定约束的资料仍保留专门校验。

- **调期：** 保留同一场次身份，以现有字段表达新时间及原定时间，公告说明变动与原因；逐一核对旧日期在搜索词、正文和票面中的残留。多次调期后取消若现有单个 `previousDateTime` 无法无歧义表达，先提出有限的数据契约修改建议，不能让不同消费者各自猜“原定”指哪次。
- **待定／取消：** 状态与售票能力分别一致；不得仅因日期过去就标为已完成，也不得自动承诺退款、恢复营业、替代场地或公告发布时间。历史记录可以保留取消事实，不以删除记录模拟取消。
- **删除／撤选：** 默认从当前获选根集合和相关首页焦点撤下，保留实体。彻底删除只适用于没有引用、也不再被需保留的快照依赖的记录；同步清理对应本地化单元。删除前检查其他时间层、语言、剧目关联、首页、素材、搜索和票务；仍被快照需要的实体不得删除。变更造成的正式资格失效应保留，不能自动重签批准摘要。
- **更正已批准内容：** 沿用现有完整 baseline／preview 机制和逐单元摘要，不做字段级深合并，不借一次审查授予发布资格。

## 表站、里站和后续时点

替换规则按“实体身份＋快照上下文＋语言单元”工作，不以“表站名字替成里站名字”实现历史版本。当前表站与 1084 快照继续使用已有 `front / archive`、根集合和统一解析边界；审查记录不是额外运行时快照。

未来新增具体时点时，先明确捕获时刻、网站主体及所知范围、根集合、售票能力和返回路径，再按既有蓝图流程引入必要的显式上下文。现有 `SiteWorld` 只有两类，不能声称已经支持任意时点运行；也不提前建立通用时间数据库或复制整套站点。新快照应复用实体身份和受控完整变体，冻结其解析结果；原快照事实不能被“当前版本替换”追溯改写。

里站等级 0 的同期正文、现代档案目录对失效快照的说明、等级 1—3 的可逆污染是三个不同表达位置。1098 损毁不能写进 1084 的同期公告；污染投影也不能反向写入场次事实、正式检索或翻译批准。历史有售票信息不代表今天能连接当年的结算服务。

## AI 预览翻译与人工考据替换

新增或改写的演出文案，在中文事实与语境明确后，默认主动生成所有受影响预览版本的 AI 译文，不等待人工逐次批准“开始翻译”。这与现有九版本 preview 契约一致，不扩大 `release` 范围。

1. 优先复用已经确认、时代与实体身份相符的官方形式和项目已采纳译法；缺乏译名时结合所指、语用、发音、词源、文化与历史语境选择意译、音译或保留原名。现实文化是语言参考，不能反推泰拉政治、历史或人物身份。
2. 人名／代号／称号、旧城／新城、机构通名／品牌核心分别处理；完整句子翻译，不将词头机械拼接。校对性数格、称谓、否定、时态、专名重音／长音及英美差异；保留官方活页受保护字段与段落关系。
3. 在本次审查的 `localization` 结论或具体发现中记录涉及的单元、语言、AI 策略、所依据的来源及不确定性；必要术语候选写入既有研究结构。不要为每一句增设永久审批条目。没有足够语境就提出缺口；有来源的原名保护可以是明确标注的预览策略，但复制英语不是“已完成母语考据”。
4. 核对各版本完整译文与最新中文后，只更新已复核单元的源修订。摘要表示译文所依据的版本，不表示人工认可；绝不为通过检查而批量刷新旧译摘要。
5. 人工提供考据替换时仍保留稳定 ID，更新完整语言单元及相关显示／搜索；重新触发语义审查和译文新鲜度检查。只有明确人工授予的内容资格才进入既有批准清单，AI 审查记录不能代签。

字数变化影响界面时，按既有开发规范补做桌面、320px 窄屏及实际语言版式验证；本指南及离线审查通过本身不构成浏览器验收。
