# 文档中心

`docs/` 保存不会直接参与网站运行、但用于解释产品契约、工程结构、创作依据和工作方法的材料。网站可执行源码与运行时内容统一位于 `src/`。

## 目录导航

| 目录                                                    | 责任                   | 典型内容                                   |
| ------------------------------------------------------- | ---------------------- | ------------------------------------------ |
| [`architecture/`](architecture/repository-structure.md) | 当前工程结构与依赖边界 | 目录规范、模块职责、数据流                 |
| [`blueprint/`](blueprint/README.md)                     | 已采纳的正式项目契约   | 体验目标、行为边界、内容规则、阶段标准     |
| [`project/`](project/README.md)                         | 非运行时项目作者资料   | 内容候选目录、内部创作备注、比较样张       |
| [`sources/`](sources/README.md)                         | 外部来源事实与权利记录 | 官方逐字内容、来源身份、许可与稳定 ID 映射 |
| [`research/`](research/README.md)                       | 来源分析与设计转译     | 研究观察、推断、设计理由与排除项           |
| [`drafts/`](drafts/README.md)                           | 临时且非正式的工作区   | 蓝图、建议、创意草稿与一次性开发计划       |
| [`guides/`](guides/development.md)                      | 可重复执行的操作说明   | 本地运行、Git、制作、开发与验证流程        |

## 信息归属

| 信息问题                               | 唯一主要责任方                                          |
| -------------------------------------- | ------------------------------------------------------- |
| 网站当前实际执行什么                   | `src/`                                                  |
| 项目正式要求什么                       | `docs/blueprint/` 与 `docs/blueprint/traceability.json` |
| 外部官方原文、来源身份或素材权利是什么 | `docs/sources/`                                         |
| 外部资料为什么支持某项判断             | `docs/research/`                                        |
| 项目内部有哪些非运行时候选与比较材料   | `docs/project/`                                         |
| 尚未采纳的方向可能是什么               | `docs/drafts/`                                          |
| 人员应怎样重复完成开发或制作操作       | `docs/guides/`                                          |
| 文件实际放在哪里、允许怎样依赖         | `docs/architecture/`                                    |

`src/` 与 active 蓝图相左时属于契约漂移，不能由一方静默覆盖另一方。来源记录、研究分析、作者资料和草稿都不能替代正式蓝图，也不能因为被源码引用之外的文档提及而自动获得产品效力。

## 唯一事实与受控镜像

- 同一正文只归属一个文档责任方，其他文档通过稳定链接引用，不复制整段内容；
- 为运行时执行而必须复制的外部来源值可以在 `src/data/` 保存镜像，但必须明确上游来源并由验证器机械核对。当前官方活页剧目正文以 `docs/sources/official-folio-productions.md` 为人员来源记录，以 `src/data/productions/folio-source-records.ts` 为运行时镜像，`scripts/validate-content.mjs` 负责防止二者漂移；
- 页面数量、浏览器版本、测试结果、构建输出和翻译覆盖率属于运行或验证结果，不在多份长期文档写死；需要当前值时执行对应命令；
- README 可以提供入口级摘要，架构文档说明当前责任，指南说明操作步骤，蓝图说明正式结果；摘要不得发展为第二套完整规范；
- 项目原创设定进入运行时后由 `src/data/` 拥有；文档只保存其行为边界、作者输入或来源说明，不维护平行的可编辑运行时正文。

## 维护原则

- 文件名使用小写英文 kebab-case，正文默认使用简体中文；
- 新目录必须有稳定且不同于现有目录的职责，并保留 README 作为入口；
- 影响运行方式、目录结构或 Agent 行为的变化，同步检查根目录 `README.md`、本索引、架构说明和 `AGENTS.md`；
- 新增重要外部依据时，先判断它是需要逐字保存的来源记录还是分析材料，再分别进入 `sources/` 或 `research/`；
- 草稿通过人工门禁单向迁入正式责任目录，迁移成功后删除草稿来源，具体生命周期以 [`drafts/README.md`](drafts/README.md) 为准；
- Git 已保存历史，不建立迁移日志、已完成任务副本或周期性全文审计报告。

文档按独立变化原因拆分，不按行数、标题数或形式整齐拆分。开发命令见 [`guides/development.md`](guides/development.md)；Git 分支与晋级流程见 [`guides/git-branch-workflow.md`](guides/git-branch-workflow.md)。
