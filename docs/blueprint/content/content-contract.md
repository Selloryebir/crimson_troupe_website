# BP-CNT-CORE｜上线内容契约

## 用户结果

用户看到的剧目、档案、机构和服务信息来源明确、内部一致，不会把概念站原创内容误解为游戏官方事实。

## 边界

- 规定运行时内容的稳定 ID、类型、状态、来源和权利字段；
- 创意草案留在 `docs/creative/`，外部依据留在 `docs/references/`；
- `docs/` 不直接成为网站运行时输入；
- 不同时维护 TypeScript 数据和 Content Collections 两个事实源。

## 行为契约

- 同一实体在卡片、详情、搜索和衔接流程中复用稳定数据；
- 游戏已有事实、概念站原创和推演性内容必须可区分；
- 来源冲突通过备注保留，不静默选择或改写；
- 外部图片、字体、音频和视频在进入运行时前确认来源、许可与署名要求。

## Demo 基线

- 剧目、搜索和档案内容使用类型化 TypeScript 数据；
- 表单与服务文案明确标注概念交互；
- 当前视觉不依赖未经确认的第三方资产。

## Formal 增量

- 内容规模、Markdown 正文或编辑协作出现真实需求时，再迁移到单一内容集合；
- 为正式发布内容增加必要的审核状态、locale 状态和资产元数据，但不保存冗余审批过程。

## 验收

- 任一公开实体可以定位到唯一运行时来源；
- 草稿、研究矩阵和待确认翻译不会直接进入构建；
- 权利状态不明确的外部资产不会被发布。
