# BP-CNT-CORE｜上线内容契约

## 用户结果

用户看到的场次、剧目、档案、机构和服务信息来源明确、内部一致，并以可信的泰拉剧团内容而不是作者注释呈现。

## 边界

- 规定运行时内容的稳定 ID、类型、状态、来源定位、权利字段和口吻分类；
- 尚未采纳的文案与叙事蓝本留在 `docs/drafts/creative/`，外部依据留在 `docs/references/`；
- 已采纳的内容结构、叙事规则和文案边界进入 `docs/blueprint/content/`，实际展示文案进入唯一运行时内容源；
- 领域实体与字段归属由 `BP-FND-DOMAIN` 唯一定义，本蓝图不建立第二套语义；
- `docs/` 不直接成为网站运行时输入，不同时维护 TypeScript 数据和 Content Collections 两个事实源。

## 内容与口吻契约

- 同一实体在列表、详情、搜索和票务衔接中复用稳定 ID 与唯一来源；`Performance`、`Production` 及其关联遵守领域语言蓝图；
- 场次状态、世界视角、本季或历史归属和票务可用性均为显式内容，不根据浏览器现实时间推导；
- 表站机构内容克制、准确、面向观众；系统反馈直接说明结果；署名内容标示说话者与内容性质；里站不可靠叙事不得改写表站常规服务文案；
- 作者侧资料可以区分游戏已有事实、概念站原创、推演内容、表站公开信息和里站揭示信息，以维持依据与叙事节奏；这些内部分类不转化为访客侧逐项标签；
- 署名、引语、翻译和改写内容在内部资料中保留来源定位；来源冲突通过备注保留，不静默选择或改写；
- 非官方同人声明的逐字措辞和版权说明链接由内容源提供，其唯一展示位置、可读性和侵入边界由体验蓝图约束。

## 素材与票务数据

- 公开文字、图片、视频和其他素材以最终采用并审核通过的内容为准；外部图片、字体、音频和视频进入运行时前必须确认来源、许可、署名要求和内部审核状态；
- 制作管理中的来源、许可与审核信息不自动转化为正式页面中的二创解释；
- 票务从 `Performance` 读取日期时间、分区、`basePrice` 和可用性，从 `Production` 读取可复用剧目内容，不维护重复业务数据；
- 票面基础设计、可组合印章、替代文本和素材权利状态具有可定位来源；生成的结算总额、随机票号和二维码属于一次标签页体验结果，不回写内容源。

## Demo 基线

- 当前剧目、搜索和档案内容使用类型化 TypeScript 数据，核心实体具有稳定 ID；
- 当前混合 `Show` 数据尚未满足正式场次与剧目分离契约；
- 当前视觉不依赖未经确认的第三方资产。

## Formal 增量

- 将内容迁移到 `Performance`、`Production`、关联和世界视角清晰的单一类型化来源；
- 为简体中文正式范围补齐页面、元数据、替代文本、搜索文本、票务输入和必要素材审核状态；
- 内容规模、Markdown 正文或编辑协作出现真实需求时，再整体迁移到单一内容集合；
- 未来发布其他国家版本时增加必要的 locale 状态，但不保存冗余审批流水账。

## 验收

- 任一公开实体可以定位到唯一运行时来源，列表、详情、搜索和票务读取同一事实；
- 草稿、研究矩阵和待确认翻译不会直接进入构建；
- 访客侧没有逐项二创标签，全部已发布页面页脚都有可读的统一非官方声明；
- 权利状态不明确的外部资产不会被发布，内部来源冲突不会被静默覆盖。
