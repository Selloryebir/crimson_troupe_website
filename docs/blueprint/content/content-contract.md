# BP-CNT-CORE｜上线内容契约

## 用户结果

用户看到的场次、剧目、档案、机构和服务信息来源明确、内部一致，并以可信的泰拉剧团内容而不是作者注释呈现。

## 边界

- 规定运行时内容的稳定 ID、类型、状态、来源定位、权利字段和口吻分类；
- 尚未采纳的文案与叙事蓝本留在 `docs/drafts/creative/`，外部依据留在 `docs/references/`；
- 已采纳的内容结构、叙事规则和文案边界进入 `docs/blueprint/content/`，实际展示文案进入唯一运行时内容源；
- 领域实体与字段归属由 `BP-FND-DOMAIN` 唯一定义，本蓝图不建立第二套语义；
- `docs/` 不直接成为网站运行时输入，不同时维护 TypeScript 数据和 Content Collections 两个事实源。

## 内容与口吻契约

- 同一实体在列表、详情、搜索和票务衔接中复用稳定 ID 与唯一来源；`Performance`、`Production` 及其关联遵守领域语言蓝图；
- 活页剧目与原创剧目分别维护创作来源，再合并为一个运行时剧目注册表。`sourceKind = folio` 只表示采用人工确认的活页标题，不把本站补写的简介、主创、场馆或演出记录提升为活动官方事实；
- 语言无关领域事实与国家版本显示内容分开保存：稳定 ID、泰拉日期数值、场次编排、状态、分区和价格只出现一次；页面、消息、地点、场次和剧目显示文字按 `editionId` 组织；
- 场次状态、世界视角、本季或历史归属和票务可用性均为显式内容，不根据浏览器现实时间推导；
- 表站机构内容克制、准确、面向观众；系统反馈直接说明结果；署名内容标示说话者与内容性质；里站不可靠叙事不得改写表站常规服务文案；
- 作者侧资料可以区分游戏已有事实、概念站原创、推演内容、表站公开信息和里站揭示信息，以维持依据与叙事节奏；这些内部分类不转化为访客侧逐项标签；
- 署名、引语、翻译和改写内容在内部资料中保留来源定位；来源冲突通过备注保留，不静默选择或改写；
- 非官方同人声明的逐字措辞和版权说明链接由内容源提供，其唯一展示位置、可读性和侵入边界由体验蓝图约束。

## 机构证据与叙事语义

每个页面先完成一个正常剧团网站任务，再承载必要数量的线索；移除异常后，日期、地点、节目、搜索、票务状态和返回路径仍然成立。表站不能因埋伏笔而含糊或虚假，里站等级 `0` 也不以长文、解谜或随机触发作为核心内容前置。

内容可以使用三类声音，但不建立百科或第二套事实系统：

| 声音           | 表面职责                                   | 使用边界                                                 |
| -------------- | ------------------------------------------ | -------------------------------------------------------- |
| 剧团公开事务   | 邀请、节目、观演须知、场次、席位和机构说明 | 核心事实准确，不以双关替代日期、地点、价格或状态         |
| 外部制度声音   | 地方新闻、场地许可、行政或行业记录         | 只作为相关实体的次级材料，不冒充剧团自身事实或全面历史库 |
| 私人或内部见证 | 署名信件、制作便笺、排演批注和残片         | 标明文种与来源，不截断必要任务信息                       |

作者侧资料只在确有需要时记录来源或说话者、预期受众、泰拉时间可信度、表面用途及与其他记录的关系；这些字段用于避免无意矛盾，不要求全部公开显示、建立审批台账或保存逐篇注释。搜索只索引已经获准公开的文种和摘要。

里站叙事沿同一组剧场词义递进：邀请可以显露为筛选，观看可以显露为参演，地点可以显露为舞台，节目可以显露为现实先兆，机构称号与出版制度可以跨时期回响。等级 `0` 只保留可被再次理解的礼仪余韵；等级 `1` 建立一处重复关系；等级 `2` 显露艺术正在消费现实；等级 `3` 才显示档案正在编排访客。该语义不得识别访客真实身份，也不得未经决策把新旧剧团写成同一恶意主体。

## 演出地点内容边界

- 演出地点候选目录是后续内容开发的非排他优先参考，不是运行时白名单、发布清单或替换指令；其他地点可以在遵守相同来源、名称和审核边界后补充；
- 当前本地化技术阶段只从候选目录新增已经被运行时场次引用的稳定地点；既有地点记录不因本阶段节目替换而自动删除，也不因此成为候选目录的已采用项。本阶段里站等级 `0` 场次采用 `wiesheim`、`zwillingsturme`、`londinium`、`norport`、`montelupe` 与 `nuova-volsinii` 六个 `locationId`，并为炎国、东国和哥伦比亚预览提供对应显示内容；`calais-blason` 保留为等级 `3` 叙事投影地点，不进入稳定场次或等级 `0` 搜索索引；不得仅因候选目录批量新增其他地点或执行排他校验；
- 地点中文名、英文名和本国语名是独立显示形式，不互相推导。其他国家版本的地点写法仍属于对应版本的翻译范围，不以本国语名或英文名静默代替；
- 地点类型可以规范为多值枚举；地点、场馆、区域和地址的字段归属遵守领域语言蓝图，候选备注不得自动拼接为公开地址；
- 正式发布的场馆和地址说明必须是经人工审核的泰拉内文案；本阶段开发预览可以使用明确不具发布资格的 AI 测试内容。本阶段不建立地点详情页、地图、现实坐标或街道级真实性，也不把自动生成的地址免审发布；
- 搜索只消费已批准的标准名称和别名，不索引内部备注。备注中的剧情定位、现实捏他、名称冲突与推论只用于创作和来源判断，不得直接显示在沉浸式页面。

## 素材与票务数据

- 公开文字、图片、视频和其他素材以最终采用并审核通过的内容为准；外部图片、字体、音频和视频进入运行时前必须确认来源、许可、署名要求和内部审核状态；
- 制作管理中的来源、许可与审核信息不自动转化为正式页面中的二创解释；
- 票务从 `Performance` 读取日期时间、分区、`basePrice` 和可用性，从 `Production` 读取可复用剧目内容，不维护重复业务数据；
- 票面基础设计、可组合印章、替代文本和素材权利状态具有可定位来源；生成的结算总额、随机票号和二维码属于一次标签页体验结果，不回写内容源。

## Demo 基线

- 场次、剧目、双站页面、搜索和票务内容使用类型化 TypeScript 数据与稳定 ID；
- `Performance`、`Production` 及其关联分离，列表、详情、搜索和票务不维护冲突副本；
- 当前视觉只使用项目自有 HTML/CSS 表现，不依赖未经确认的第三方资产。

## Formal 增量

- 将内容迁移到 `Performance`、`Production`、关联和世界视角清晰的单一类型化来源；
- 以双来源分区和统一注册表保留六项原创剧目并加入当前采用的四项活页剧目，按九次 1091 场次替换旧里站引用；
- 将当前运行时地点迁移为稳定身份、国家归属与国家版本显示内容，不在本阶段把候选目录批量转成运行时数据；
- 为简体中文正式范围补齐页面、元数据、替代文本、搜索文本、票务输入和必要素材审核状态；
- 内容规模、Markdown 正文或编辑协作出现真实需求时，再整体迁移到单一内容集合；
- 未来发布其他国家版本时增加必要的 locale 状态，但不保存冗余审批流水账。

## 验收

- 任一公开实体可以定位到唯一运行时来源，列表、详情、搜索和票务读取同一事实；
- 表站可以采用活页或原创剧目，里站只引用活页剧目；未采用的标题不会形成空运行时内容；
- 当前场次引用的地点通过稳定 ID 与显示内容关联，候选目录未被误作排他白名单或自动发布内容；
- 草稿、研究矩阵和待确认翻译不会直接进入构建；
- 访客侧没有逐项二创标签，全部已发布页面页脚都有可读的统一非官方声明；
- 权利状态不明确的外部资产不会被发布，内部来源冲突不会被静默覆盖。
