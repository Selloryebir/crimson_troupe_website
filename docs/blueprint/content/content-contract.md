# BP-CNT-CORE｜上线内容契约

## 用户结果

用户看到的场次、剧目、档案、机构和服务信息来源明确、内部一致，并以可信的泰拉剧团内容而不是作者注释呈现；预览内容可以部署验证，但不会被误认为已经批准的正式内容。

## 边界

- 规定运行时内容的稳定身份、来源类别、变体、根集合、批准资格、权利字段和口吻分类；
- 领域实体、字段归属、场次时间与运营状态由 `BP-FND-DOMAIN` 唯一定义，国家版本闭包与翻译资格由 `BP-I18N-CORE` 负责；
- 尚未选入运行时的文案、叙事蓝本和替代方案留在 `docs/drafts/creative/`，外部依据和候选资料留在 `docs/references/`；
- 获选预览内容进入 `src/data/` 的唯一类型化来源，获选素材进入 `src/assets/`；`docs/` 不参与构建；
- 当前剧目、场次、地点、票价和逐字文案实例只由运行时数据拥有，正式蓝图不复制当前编排表；
- 不同时维护两棵全量内容树、TypeScript 与 Content Collections 两个事实源、字段级审批、任意版本历史或永久审批台账。

## 内容生命周期与资格

内容采用“创意候选 → 运行时预览 → 人工批准资格 → 正式构建”的单向主流程：

1. 创意候选不参与构建，也不产生页面、搜索结果或运行时资产；
2. 人工明确选择候选用于可部署验证后，它才成为满足 schema 的完整运行时变体；
3. 同一稳定身份保存一个完整基线和最多一个完整预览变体。基线本身可以尚未批准；预览变体替换完整可发布单位，不与基线执行字段级深合并；
4. 人工批准只授予明确稳定 ID、国家版本、素材与根集合的当前规范化摘要。“效果可用”、阶段验收、目录位置、分支合并或构建成功都不构成批准；
5. 正文、译文、素材、成员、顺序或焦点发生变化时，旧摘要自动失效。批准清单只保存当前资格，不保存人员、时间、批注或历史；
6. 修订已批准内容时，以新的完整预览变体并行验证；移除候选可以恢复仍然匹配摘要的基线，不直接覆写后继续沿用旧资格；
7. 内容批准、源码修改授权和 Git 授权彼此独立。

当前全部运行时内容统一属于未批准预览。只有人工以后明确批准具体对象和集合，且摘要仍匹配时，才获得 `approved-only` 构建资格。

## 根集合与统一构建快照

- 有序根集合只拥有选中的根 ID、页面需要的顺序、分组和明确首页焦点，不手写剧目、地点、翻译、封面、票务或其他依赖闭包；
- 根集合的每个成员及首页焦点都必须引用与该集合 `world` 一致的 `Performance`；front/archive 的任一双向错置都在静态路径生成前失败；
- 有限命名构建预设显式组合国家版本范围、根集合、`preview-ok / approved-only` 内容策略和回退策略，不开放自由组合矩阵；
- 构建上下文只保存稳定 `rootSetId`；唯一解析入口必须据此从显式注册表取得根集合并校验 ID，不允许调用者再传入默认根集合形成平行选择；
- 唯一内容解析边界根据构建上下文选择完整变体，求出领域对象、本地化、素材和票务依赖闭包，并返回本次构建不可变快照；
- 构建范围 API 按快照提供已解析本地化记录、规范化剧目 Artwork 元数据和座席拓扑，不把图片二进制或全部语言包复制进快照；页面、组件及面向页面的数据消费者不得绕开该 API 读取底层全局注册表；
- 列表、首页、详情路由、搜索、票务和验证器只能消费该快照，不分别遍历底层全局注册表；未来若实现站点地图，也必须消费同一快照；
- 同一构建中的一个稳定实体只有一个完整解析结果。集合外内容可以留在内容库，但不得产生页面、搜索入口、票务候选或产物资产；
- 九枚已注册国家版本徽记是允许常驻所有构建产物的全局品牌基础资产，不属于 Performance 根集合闭包；该豁免不延伸到剧目封面、票务素材或其他内容资产，也不为未构建国家产生页面或入口；
- 首页焦点和内容顺序由根集合显式拥有，不依赖对象或模块导入顺序；严格模式下必要素材缺失不得被组件占位静默掩盖。

批准资格使用三类相互独立的规范化摘要：站点公共单元覆盖全站共享可见内容，根集合单元覆盖成员、顺序与焦点，场次闭包单元只覆盖该场次真实消费的领域事实、本地化、座席、素材和权利状态。最终 Artwork 摘要至少包含资产内容摘要、来源与权利状态，以及 `focalPoint`、`safeCrop`、`memoryColor`、`titleTone`、`altIntent` 和全部污染参数；无关页脚变化不得伪装成每个场次分别变化，集合外记录和纯文件路径重排也不得使场次资格失效。

## 内容与口吻契约

- 同一实体在列表、详情、搜索和票务衔接中复用稳定 ID 与唯一运行时来源；
- 活页剧目与原创剧目分别维护来源，再合并为一个运行时剧目注册表。`sourceKind = folio` 只表示采用人工确认的活页标题，不把本站补写的简介、主创、场馆或场次提升为游戏活动官方事实；
- 语言无关领域事实与国家版本显示内容分开保存。稳定 ID、泰拉日期数值、编排、状态、分区和价格只出现一次；页面、消息、地点、场次和剧目显示文字按 `editionId` 组织；
- `ProductionContent` 保存可复用的完整剧目介绍，承担暗线、彩蛋、文学表达与剧目身份；`PerformanceContent` 不复制剧目介绍，只保存场次显示资料及确有需要的一则运营公告；
- 运营公告通过日期、地点、原定排期和原因，以中性剧团事务口吻承载天灾改线、场馆异象或时间线联动，不另建解释世界观的面板；
- 表站机构内容克制、准确、面向观众；系统反馈直接说明结果；署名内容标示说话者和内容性质；里站等级 `0` 原网站正文使用捕获时的同期运营立场，现代馆藏外壳与污染投影分别维护，不得互相覆盖或改写表站常规服务文案；
- 作者侧可以区分游戏已有事实、概念站原创、推演内容、表站公开信息和里站揭示信息，但这些内部分类不转化为访客侧逐项标签；
- 署名、引语、翻译和改写在内部资料中保留来源定位，来源冲突通过备注保留，不静默覆盖；
- 非官方同人声明的逐字措辞和版权链接由内容源提供，其唯一展示位置、可读性和侵入边界由体验蓝图约束。

## 机构证据与叙事语义

每个页面先完成一个正常剧团网站任务，再承载必要数量的线索。移除异常后，日期、地点、节目、搜索、票务状态和返回路径仍然成立；表站不能因伏笔而含糊，里站等级 `0` 也不以长文、解谜或随机触发作为核心内容前置。

| 声音           | 表面职责                                   | 使用边界                                                 |
| -------------- | ------------------------------------------ | -------------------------------------------------------- |
| 剧团公开事务   | 邀请、节目、观演须知、场次、席位和机构说明 | 核心事实准确，不以双关替代日期、地点、价格或状态         |
| 外部制度声音   | 地方新闻、场地许可、行政或行业记录         | 只作为相关实体的次级材料，不冒充剧团自身事实或全面历史库 |
| 私人或内部见证 | 署名信件、制作便笺、排演批注和残片         | 标明文种与来源，不截断必要任务信息                       |

作者侧只在确有需要时记录来源或说话者、预期受众、泰拉时间可信度、表面用途及与其他记录的关系；这些字段不要求全部公开显示或建立逐篇审批台账。搜索只索引当前构建快照允许公开的文种和摘要。

里站叙事沿同一组剧场词义递进：邀请可以显露为筛选，观看可以显露为参演，地点可以显露为舞台，节目可以显露为现实先兆，机构称号与出版制度可以跨时期回响。等级 `0` 只保留可被再次理解的礼仪余韵；等级 `1` 建立一处重复关系；等级 `2` 显露艺术正在消费现实；等级 `3` 才显示档案正在编排访客。该语义不得识别访客真实身份，也不得未经决策把新旧剧团写成同一恶意主体。

## 场次、地点与时间层内容边界

- 本季或历史集合由 `BP-MOD-TERRA-TIME` 提供的网站泰拉时间与 `effectiveDateTime` 派生；运营状态不改变时间分类；
- 运营状态、原定排期、原因类别和本地化公告共同参与完整变体、批准摘要与译文新鲜度检查；列表、详情、首页、搜索和票务从同一快照读取，不在组件中固定状态；
- 表站场次可以引用 `folio` 或 `original`，1091 里站等级 `0` 场次只允许引用 `folio`；未被集合采用的参考标题不生成空实体或页面；
- 里站等级 `0` 保存完整 1091 同期网站事实，场次票务可用性、分区和价格反映捕获时状态；历史快照与原结算服务的失联属于档案页面能力，不回写 `Performance`。污染等级 `1—3` 只产生可逆展示投影，不回写运行时内容、翻译、批准摘要或搜索索引；
- 稳定场次、等级 `0` 国家版本内容和正常搜索索引不得出现克莱布拉松演出信息。等级 `3` 可以按页面职责投影克莱布拉松与请柬，但不生成新的 `Performance`、URL 或正常索引事实；
- 等级 `3` 投影由一份语言无关身份与按国家版本完整本地化的运行时内容记录驱动，至少包含统一剧目、短句、请柬时间、克莱布拉松林地城堡、邀请正文、继续／关闭标签和页面职责所需变体。它是可替换的完整预览单元，不与等级 `0` 记录深层合并，不因本阶段可部署而取得逐字文案或正式内容资格；
- 演出地点候选池位于 `docs/references/performance-location-reference.md`，它是非排他参考而非运行时白名单。采用地点时使用稳定 ID，内部备注不公开、不参与搜索，也不自动拼接为地址；
- 地点中文名、英文名和本国语名是独立显示形式，不互相推导。场馆和地址必须是经人工审核的泰拉内内容；开发预览可以使用明确不具发布资格的 AI 测试文案。

## 素材与票务数据

- 公开文字、图片、视频和其他素材以最终采用并审核通过的内容为准；外部资产进入运行时前必须确认来源、许可、署名和内部审核状态；
- 制作管理中的来源、许可和审核信息不自动成为正式页面中的二创解释；
- 票务从构建快照中的 `Performance` 读取有效排期、状态、分区、基础价格和可用性，从 `Production` 读取剧目内容，不维护重复业务数据；表站购票模组和里站静态席位页消费相同领域语义，但不共享会话状态机；
- 场馆拓扑、分区关系、费用路线、讽刺节拍、存单与票面印章行为只由票务蓝图拥有；拓扑可以包含多个楼层与同等级多区域，但分区可售性和价格只由 `Performance.ticketAvailability.offers` 拥有。本蓝图只规定其内容来源和批准资格；
- 本阶段五个里站可售场次的人工候选报价集中在一份语言无关的“`productionId` × 场馆报价键”稀疏矩阵，以固定 `[C, B, A, S, BOX]` 五元组保存正整数或 `'-'`；`'-'` 表示该组合不存在对应分区。唯一转换边界生成最终 `TicketOffer[]`，页面、本地化和场次消费者不解析字符串或重复数字；表站继续使用票务蓝图已经确定的逐场报价，本阶段不为统一存储而扩大迁移范围；
- 场馆报价键只标识当前报价使用的具体剧场、厅或舞台，不提前建立完整 `Venue` 实体。矩阵只保存实际使用的组合；同一组合未来需要日期特价或覆盖时必须先修订内容契约，不静默改变矩阵语义；
- 当前逐场 LMD 数值属于已获可部署验证资格但尚未正式批准的预览内容；正式发布前仍须逐场人工确认。价格、实际分区或拓扑变化参与既有内容摘要和批准资格失效，不建立平行的 Demo／Formal 内容树；
- 正式定价公式当前不启用，不新增空字段、规则引擎或运行时计算。未来若启动定价规划，分钟数、幕数、制作规模和场馆条件必须先成为语言无关事实，不能解析本地化显示文字计算价格；
- 票面设计、替代文本和素材权利状态具有可定位来源；结算总额、随机票号和二维码属于一次标签页体验结果，不回写内容源。

## Demo 基线

- 场次、剧目、双站页面、搜索和票务使用类型化 TypeScript 数据与稳定 ID；
- `Performance`、`Production` 及其关联已经分离；页面、路由、搜索、票务与验证器统一消费由当前构建上下文解析的不可变快照；
- 当前全部运行时内容属于可部署预览，不存在已批准正式基线。

## Formal 增量

- 建立完整变体、有序根集合、批准摘要、有限命名预设和唯一不可变构建快照；
- 让列表、首页、详情路由、搜索、票务与验证器统一消费快照，移除平行注册表遍历和硬编码矩阵；未来站点地图沿用同一入口；
- 增加聚焦内容检查，覆盖稳定身份、完整变体、依赖闭包、翻译新鲜度、必要素材、派生集合和正式资格；
- 当前内容规模、Markdown 正文或编辑协作出现真实需求时，再整体迁移到单一 Content Collections，不提前引入 CMS 或数据库。

## 验收

- 任一公开实体能够定位完整变体、根集合成员资格、依赖闭包和当前批准资格；
- 同一构建的列表、详情、搜索、票务、首页焦点与最终资产不存在不同集合或不同版本；
- 同 ID 改稿不与旧基线按字段拼合，正文、译文、素材、成员、顺序或焦点变化会使旧批准失效；
- 同一稳定身份可定位完整 baseline 与最多一个完整 preview 变体；移除候选后恢复的 baseline 只有在摘要仍匹配时保留资格；
- 场次、根集合和站点公共摘要分别失效，Artwork、座席和权利状态的可见变化不会沿用旧资格，无关站点文字不会制造逐场重复失效；
- 把集合从三个未来场次扩展为五个未来与十二个历史场次时，不需要复制页面、逐项配置路由或维护第二份验证矩阵；
- 草稿、集合外记录、旧译、必要素材缺口和未批准内容不会进入 `approved-only` 产物；
- 表站可以采用活页或原创剧目，里站只引用活页；克莱布拉松不会在等级 `0—2` 稳定内容中泄露；
- 同一 `TicketZone` 的多个空间区域不会产生重复报价；删除分区后，图形、控件、票篮、结果和票面都不能从其他来源保留该分区；
- 报价矩阵五元组长度固定，只接受正整数或 `'-'`；转换后的有效分区非空、无重复，并按实际存在的 `C → B → A → S → BOX` 顺序严格递增；
- 访客侧没有逐项二创标签，全部已发布页面页脚都有统一、可读且低干扰的非官方声明；
- 权利状态不明确的外部资产不会发布，内部来源冲突不会被静默覆盖。
