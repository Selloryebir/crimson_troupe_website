# 体验蓝图

## 核心问题

如果一位泰拉人搜索“猩红剧团”，会打开怎样的网站，并在什么时刻意识到它不只有一个时间层？

## 双时间层

| 维度 | 表站：新剧团 | 里站：旧剧团 |
| --- | --- | --- |
| 首要目标 | 建立可信、专业的巡演机构体验 | 让用户发现被掩埋的旧档案仍在呼唤观众 |
| 信息结构 | 乐季、剧目、观看方式、剧团、手记、预约 | 恢复记录、异常演员表、邀请与返回路径 |
| 视觉语法 | 纸色、猩红、编辑式留白、秩序化网格 | 黑红、扫描线、破损编号、侵入式但可退出的反馈 |
| 用户关系 | 被服务的观众 | 被辨认并试图招募的“演员” |
| 安全边界 | 信息明确、操作可预期 | 可以不安，不得真实欺骗、困住或伤害用户 |

## 核心旅程

1. 用户通过主视觉理解剧团气质；
2. 在演出季筛选城市和月份；
3. 阅读剧目详情、观演提示与无障碍信息；
4. 选择现场、城市转播或延时讯道；
5. 通过页脚编号、快捷键或异常搜索结果进入旧档案；
6. 浏览记录并接受或拒绝邀请；
7. 随时返回当前时间。

## 扩展点

- 新剧目：追加 `src/data/shows.js` 数据、HTML 节目卡和必要的原创视觉变体；
- 新搜索内容：追加 `src/data/search-index.js` 的非剧目条目；
- 新档案：在 `archive.js` 中注册记录内容，并在里站结构中提供语义化触发器；
- 新观看渠道：先在本蓝图明确泰拉内合理性，再扩展表站服务区；
- 多页面或后端：只有内容规模、真实预约或发布需求成立时再设计路由、API 和构建层。

## 非目标

- 复刻官方游戏界面或现实剧院网站；
- 伪造真实购票、支付、账号或个人信息处理；
- 把旧剧团做成无法退出的惊吓页面；
- 将当前原创剧目或角色描述为《明日方舟》官方设定。
