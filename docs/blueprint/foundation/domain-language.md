# BP-FND-DOMAIN｜领域语言与演出语义

## 用户结果

人员、智能体、蓝图和源码对表站、里站、场次、剧目、票篮及泰拉时间使用同一含义，不因自然语言别名产生错误路由、数据关系或功能实现。

## 边界

- 本蓝图是产品与演出领域定义、内部英文名、允许别名、消歧规则及字段归属的唯一来源；
- 别名只用于理解输入，正式蓝图和源码优先使用规范中文名与内部英文名；
- 不规定逐字 UI 文案、各语言标准译名、搜索别名或普通实现细节；
- i18n 术语契约负责多语言显示形式，不重复定义本蓝图的产品和数据语义。

## 规范术语

| 规范中文名 | 内部英文名      | 允许识别的别名                         | 精确定义                                                                                         | 需要避免的混用                                                          |
| ---------- | --------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| 表站       | `front`         | 新剧团网站、新酒神版本、新酒神剧团网站 | 新酒神时期重新组建的猩红剧团官网；时间参照点为叙事语义上的“现在”                                 | `front` 是网站时间层标识，不是国家版本、页面主题或固定年份              |
| 里站       | `archive`       | 旧剧团网站、旧酒神版本、1091 历史快照  | 旧酒神时期猩红剧团官网在当前可访问快照记录所定义时刻捕获的历史网站                               | `archive` 是网站时间层标识，不等同于历史演出栏目，也不表示 URL 不可直达 |
| 场次       | `Performance`   | 演出场次、完整演出                     | 在具体泰拉日期时间和地点举行的一次完整演出，由一个或多个按顺序编排的剧目组成                     | 不得用单个剧目或 `productionId` 代指场次                                |
| 剧目       | `Production`    | 单独剧目、作品                         | 完整演出中的一个独立剧目，可以被一个或多个场次编排使用                                           | 不得用剧目表示具体日期、地点、票价或购票单位                            |
| 剧目来源   | `sourceKind`    | 活页剧目、原创剧目                     | `folio` 表示采用人工确认活页标题的剧目，`original` 表示概念站原创剧目；只描述来源类别            | 不表示详情和场次均为官方内容，也不直接表示剧目所属时间层                |
| 地点       | `Location`      | 城市、地区、举办地                     | 可被多个场次引用的城市或地区锚点，使用稳定 `locationId` 对应各国家版本显示名                     | 不等同于某场次的场馆、厅室、地址详情或国家版本                          |
| 演出       | 无独立数据类型  | 节目、演出内容                         | 自然语言中的上位称呼；进入结构化规划、代码或路由讨论时必须明确指场次还是剧目                     | 不得把“演出”静默映射为 `Performance` 或 `Production`                    |
| 票篮       | `TicketBasket`  | 购票篮                                 | 单次票务体验中已选择的一个或多个场次及其分区集合                                                 | 不等同于订单、存单、账号资产或长期购买记录                              |
| 泰拉时间   | `TerraDateTime` | 泰拉日期、泰拉日期时间                 | 未经人工另行说明时，规划、蓝图、页面内容和领域数据中所有时间表达所使用的《明日方舟》世界观内时间 | 不得默认转换为现实公历、UTC、浏览器时区、构建时间或 Git 时间            |
| 本季演出   | 无独立实体类型  | 未来演出、待演场次                     | `effectiveDateTime` 不早于当前时间层 `siteTerraNow` 的全部 `Performance` 集合                    | 运营状态不改变时间分类；里站不能按表站、浏览器或现实时间判断            |
| 历史演出   | 无独立实体类型  | 已演场次、过往演出                     | `effectiveDateTime` 早于当前时间层 `siteTerraNow` 的全部 `Performance` 集合                      | 不等同于里站 `archive`，也不表示场次必然正常举行或完成                  |

一个别名若可能指向多个概念，必须结合上下文消歧；无法可靠消歧时应请求澄清，不能静默选择。内部规范标识不强制成为访客界面的逐字文案，也不直接决定公开 URL。

## 实体与时间契约

- `Performance` 与 `Production` 均使用稳定 ID。一个 `Performance` 必须按演出顺序引用一个或多个 `productionId`；同一 `Production` 可以被多个 `Performance` 复用；
- `performanceId` 表达不可变身份，不从可能改动的日期、地点或场馆动态生成。现有包含旧日期或地点片段的 ID 作为不再解释组成的冻结身份保留，不为形式统一批量改写 canonical URL；
- `Production.sourceKind` 是语言无关事实。活页剧目与原创剧目可以由各自源模块维护，但必须合并为一个平坦运行时注册表；页面、场次、搜索和票务只消费统一注册表，不维护两套剧目逻辑；
- 活页剧目的稳定 ID 与来源标题映射以 `docs/references/production-title-reference.md` 为唯一参考。ID 写入后冻结，不在运行时从任一国家版本标题生成，也不因显示标题勘误自动改写；
- 表站 `Performance` 可以引用 `folio` 或 `original`，1091 里站 `Performance` 只允许引用 `folio`。该约束必须由数据或构建验证检查，不依赖命名习惯；未被运行时场次采用的参考标题不产生空实体或页面；
- 有效排期、可选原定排期、`locationId`、场馆、厅室或地址详情、场次状态、公告原因、票务可用性、分区、基础价格和票务分区示意引用属于 `Performance`；这些票务字段表达所属时间层在网站时钟处的场次事实，不表达历史快照与原结算服务是否仍然连通。分区示意只关联场次票务展示资料，不改变 `Location` 或建立独立 `Venue`；标题、完整剧目简介、基础主创、剧目视觉和通用观演提示属于 `Production`；
- `Location` 只保存可复用的城市或地区身份及稳定 `countryEditionId`，不伪造完整地址；`countryEditionId` 复用国家版本注册中的实体 ID，只表达地点所属国家，不决定显示语言或构建范围。场馆名称、可选区域和可选地址说明继续属于具体 `Performance`；同一场馆形成真实复用需求前，不建立独立 `Venue` 实体；
- 场次运营状态为 `scheduled | pending | completed | cancelled`，与内容成熟度无关；改期使用新的 `effectiveDateTime`，并可保留 `previousDateTime` 与原因类别；
- 稳定 ID、泰拉日期数值、编排顺序、运营状态、原因类别、分区枚举和价格属于语言无关事实；日期显示、地点与场馆名称、地址说明、剧目简介、运营公告、按钮和状态文字属于当前国家版本内容；
- 只对某一场次成立的卡司、版本、时长或演出顺序信息属于场次与剧目的关联数据，不复制或改写剧目本体；
- 本季演出和历史演出以 `Performance` 为集合成员，由 `BP-MOD-TERRA-TIME` 解析的 `siteTerraNow` 与 `effectiveDateTime` 在构建快照中派生。运营状态不改变分类，浏览器现实时间不参与当前分类；
- 技术 locale 只控制数字、字段顺序和本地化文案，不改变泰拉纪年、快照视角或场次当地时间；
- 构建时间、Git 时间、测试时间和浏览器现实环境必须显式称为“现实时间”；`TerraDateTime` 使用结构化内容字段保存，不直接转换为现实 UTC 时间戳。

## Demo 基线

- 类型化内容以稳定 ID 分离 `Performance` 与 `Production`，并使用有序 `productionIds` 建立关联；
- 列表、详情、搜索和票务从同一领域数据派生；当前世界与排期显式，集合仍由迁移前手写字段承载。

## Formal 增量

- 以独立、类型化的 `Performance` 与 `Production` 及其有序关联替换混合模型；
- 为 `Production` 增加显式来源类别，以双来源模块和单一注册表同时保留活页及原创剧目，并机械阻止里站引用原创剧目；
- 让 `Performance` 通过稳定 `locationId` 引用当前采用的 `Location`，并把地点、场馆与地址显示移入国家版本内容；
- 让 `Location` 保存稳定国家归属，使内容和验证不从译名、场馆或演出文案推断国家；
- 由相同领域数据派生列表、详情、搜索和票务输入，不建立并行事实源；
- 让世界视角、有效排期、运营状态、票务可用性和网站泰拉时间均成为显式事实，并从单一时钟接口派生集合；
- 让里站场次保留捕获时的同期票务事实，并把快照结算端连通状态留给档案能力，不把访问时的失联倒写为 `Performance` 不可售；
- 将场次长篇叙事留在 `ProductionContent`，让 `PerformanceContent` 只增加确有需要的本地化运营公告。

## 验收

- 一个场次可以按顺序引用多个剧目，同一剧目可以被多个场次复用；
- 修改场次独有字段不会改写剧目本体，修改剧目本体会由所有引用方读取同一结果；
- 修改地点显示名不会改变场次身份、场馆或其他国家版本内容，多个场次不复制同一地点译名；
- 原创剧目继续可被表站采用，里站引用原创剧目会被机械拒绝；来源分类不要求消费者分叉，也不会把概念站扩写误判为官方事实；
- “演出”存在歧义时不会被静默实现为错误实体；
- 表站与里站的本季、历史集合只依据各自 `siteTerraNow` 与有效排期生成，取消、待定或未完成状态不会改写时间分类；
- 改期、状态和票务资格在列表、详情、搜索及票务中读取同一构建快照，不出现固定 `scheduled` 或无条件购票入口。
