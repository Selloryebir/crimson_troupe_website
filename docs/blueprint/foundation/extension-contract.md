# BP-FND-EXTENSION｜功能扩展契约

## 用户结果

新增或移除一个独立能力时，既有页面、模组和核心阅读路径保持稳定。

## 边界

- 定义功能单元如何装配、依赖基础状态并安全降级；
- 不要求每个辅助函数成为模组，也不引入运行时远程插件；
- 不用全局事件总线替代清晰的一对一函数依赖。

## 行为契约

- Astro 结构在构建期装配，客户端能力由明确入口初始化；
- 模组不得读取或修改其他模组的私有状态；
- 确定的一对一协作使用显式、类型化接口；只有真实的一对多状态广播才使用事件；
- 模组缺失或初始化失败时，基础内核和表站核心内容仍可使用。

## Demo 基线

- 当前功能按用户能力拆分脚本，并由单一入口按明确顺序初始化；
- 追踪表能够从功能源码定位主要及相关蓝图。

## Formal 增量

- 当至少两个模组出现重复装配需求时，再引入类型化注册表和启停配置；
- 小游戏等高交互能力优先延迟加载，并声明键盘、动效、存储和退出策略。

## 验收

- 新能力不需要修改无关模组内部实现；
- 移除增强脚本不会令核心内容不可读；
- 抽象由已经出现的重复需求驱动，而非假设性扩展。
