# BP-FND-EXPERIENCE｜双时间层体验系统

## 核心问题

如果一位泰拉人搜索“猩红剧团”，会打开怎样的网站，并在什么时刻意识到它不只有一个时间层？

## 体验契约

| 维度     | 表站：新剧团                           | 里站：旧剧团                                 |
| -------- | -------------------------------------- | -------------------------------------------- |
| 首要目标 | 建立可信、专业的巡演机构体验           | 让用户发现被掩埋的旧档案仍在呼唤观众         |
| 信息结构 | 乐季、剧目、观看方式、剧团、手记、预约 | 恢复记录、异常演员表、邀请与返回路径         |
| 视觉语法 | 纸色、猩红、编辑式留白、秩序化网格     | 黑红、扫描线、破损编号、侵入式但可退出的反馈 |
| 用户关系 | 被服务的观众                           | 被辨认并试图招募的“演员”                     |
| 安全边界 | 信息明确、操作可预期                   | 可以不安，不得真实欺骗、困住或伤害用户       |

两层共享品牌线索，但拥有独立的信息结构、文案语气和交互反馈。颜色、动效或装饰不能成为识别状态和完成操作的唯一方式。

## 核心旅程

1. 用户通过主视觉理解剧团气质；
2. 在演出季筛选城市和月份；
3. 阅读剧目详情、观演提示与无障碍信息；
4. 选择现场、城市转播或延时讯道；
5. 通过馆藏编号、快捷键或异常搜索结果进入旧档案；
6. 浏览记录并接受或拒绝邀请；
7. 随时返回当前时间。

新增观看渠道必须先证明其泰拉内合理性，再扩展表站服务区。新增暗线必须说明入口、触发、反馈和返回路径。

## 非目标

- 复刻官方游戏界面或现实剧院网站；
- 伪造真实购票、支付、账号或个人信息处理；
- 把旧剧团做成无法退出的惊吓页面；
- 将当前原创剧目或角色描述为《明日方舟》官方设定。

## Demo 基线

- 表站作为专业剧团官网独立成立；
- 里站具有明确入口、独立语气和可靠退出；
- 桌面、窄屏、键盘与减少动态效果路径均可理解。

## Formal 增量

- 建立一致的语义设计令牌和组件状态，不依赖页面级补丁维持视觉；
- 在内容扩大时保持信息架构、焦点顺序和多语言布局稳定。

## 验收

- 用户不进入彩蛋也能完成表站核心旅程；
- 用户进入里站后始终能识别并执行返回；
- 两层差异同时体现在信息、文案、交互和视觉上。
