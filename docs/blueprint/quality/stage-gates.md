# BP-QLT-STAGES｜实现成熟度

蓝图使用统一阶段描述实现成熟度，不为 Demo 和 Formal 维护两套图纸。具体检查命令只在 `AGENTS.md` 和开发指南维护，本文件不复制测试清单或运行记录。

## 阶段

- `planned`：目标和边界已明确，尚无完整用户闭环；
- `demo`：最小用户闭环可部署、可浏览，已知缺口在同一蓝图的 Formal 增量中说明；
- `candidate`：目标契约已经实现，正在验证正式内容、可靠性和发布条件；
- `formal`：正式范围内的内容、无障碍、性能、安全、权利和失败路径均达到发布要求。

`status` 与阶段不同：`draft`、`active`、`superseded` 表示蓝图本身是否有效，不能用来表达代码完成度。

## 晋级原则

- 晋级依据少量可观察结果，不要求问卷、会议记录或重复摘要；
- Formal 不等于必须接入后端，可靠的静态能力也可以正式发布；
- 暂无真实需求的后台、账号、遥测、实时插件和复杂抽象不能作为晋级前置条件；
- 未通过的条件保留为明确差距，不通过反复改写蓝图掩盖；
- 阶段变化只更新追踪表中的单一字段，不复制蓝图正文。

## 全阶段不变量

- 表站核心内容可理解，里站始终可以退出；
- 不伪造真实服务，不收集未声明的数据；
- 交互具有键盘路径，动画遵守减少动态效果；
- 项目原创、游戏已有事实和外部参考保持责任分离；
- 验证强度与实际改动风险相称。
