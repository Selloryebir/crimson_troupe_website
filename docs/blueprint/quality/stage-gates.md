# BP-QLT-STAGES｜实现成熟度与正式门禁

## 用户结果

人员可以用统一阶段和证据规则判断一个能力是否仍在规划、可部署验证、进入正式候选或已经满足正式发布要求，而不需要在质量蓝图中维护第二套功能规格。

## 边界

- 本蓝图只定义成熟度、证据组合、跨能力不变量和晋级条件；
- 搜索、污染、票务、内容、本地化和视觉的具体行为与验收条件由各自 active 蓝图唯一拥有，本文件不复制其参数、状态转移、内容数量或页面清单；
- 具体命令和日常验证强度只在 `AGENTS.md` 与 `docs/guides/development.md` 维护，本文件不复制命令表、运行日志、浏览器版本或构建页面数；
- `docs/blueprint/traceability.json` 是每个蓝图当前 `stage` 的唯一机器事实源。

## 阶段

- `planned`：目标和边界已明确，尚无完整用户闭环；
- `demo`：最小用户闭环可部署、可浏览，已知缺口由所属蓝图的 Formal 增量说明；
- `candidate`：目标契约已经实现，正在验证正式内容、可靠性和发布条件；
- `formal`：正式范围内的内容、无障碍、性能、安全、权利和失败路径均达到发布要求。

`status` 与阶段不同：`active` 表示当前有效约束，`retired` 表示已经终止且不再约束开发；二者不能表达实现完成度。尚未采纳的蓝图留在 `docs/drafts/blueprint/`。

## 晋级原则

- 晋级依据可重复的自动检查与有限人工证据，不要求问卷、会议记录或重复摘要；
- 技术检查通过只证明对应检查成立，不替代内容、翻译、艺术和发布决定；
- Formal 不等于必须接入后端，可靠的静态能力也可以正式发布；
- 暂无真实需求的后台、账号、遥测、实时插件和复杂抽象不能成为晋级前置条件；
- 未通过的条件保留为明确差距，不通过反复改写蓝图、降低浏览器范围或删除失败路径掩盖；
- 阶段变化只更新 `traceability.json` 中的单一字段，不复制到 README、架构快照或研究文档。

## 全阶段不变量

- 手机端与桌面端完成相同核心任务，最低覆盖 320 CSS 像素；不出现页面级横向内容丢失、主要操作遮挡、文本脱离容器或仅可通过 hover 完成的任务；
- 表站与等级 `0` 里站核心内容在无 JavaScript 时可读，里站和高交互模组始终可退出或返回；
- 交互具有键盘路径，焦点与语义可靠，动画遵守减少动态效果；颜色、装饰和运动不是唯一信息载体；
- 不进行真实交易，不收集未声明数据，不以污染或小游戏为由实施恶意下载、强制全屏、自动音频、虚假紧迫或无法退出；
- 官方来源、项目作者资料、研究分析、草稿、正式蓝图和运行时内容保持责任分离；未批准内容不得因目录位置、分支合并或构建成功获得正式资格；
- 验证强度与实际改动风险相称，阶段收口只执行一次完整门禁，不用重复构建或全量截图代替风险判断。

## 能力证据归属

| 能力范围               | 具体契约与验收责任方                                                                | 本阶段只聚合的证据                             |
| ---------------------- | ----------------------------------------------------------------------------------- | ---------------------------------------------- |
| 内容资格与构建快照     | `BP-CNT-CORE`                                                                       | 来源、闭包、批准摘要、根集合与产物一致性       |
| 国家版本与术语         | `BP-I18N-CORE`、`BP-I18N-TERMS`                                                     | 完整度、零回退、语言标注、字体与人工译审状态   |
| 双站体验与剧目视觉     | `BP-FND-EXPERIENCE`、`BP-CNT-PRODUCTION-VISUAL`、`BP-CNT-PRODUCTION-VISUAL-CATALOG` | 双站辨识、页面模式、素材权利与跨视口可读性     |
| 里站、污染与邀请       | `BP-FND-NARRATIVE`、`BP-MOD-ARCHIVE`                                                | 状态确定性、任务保护、可逆投影与可靠退出       |
| 票务、凭单与纪念票     | `BP-MOD-TICKETING`                                                                  | 状态收束、价格不变量、媒介一致、本地化与降级   |
| 搜索、节目与泰拉时间   | `BP-MOD-SEARCH`、`BP-MOD-PROGRAMS`、`BP-MOD-TERRA-TIME`                             | 分域索引、稳定实体关系、时间派生与无脚本路径   |
| 平台内核与扩展失败边界 | `BP-FND-CORE`、`BP-FND-DOMAIN`、`BP-FND-EXTENSION`                                  | 路由、领域一致性、模块隔离与加载失败后的可用性 |

每个责任蓝图的验收条件在其自身文件修改和审查。质量阶段只要求当前发布范围内所有相关条件取得证据，不把这些条件重新抄入本文件。

## 浏览器、响应式与性能证据

- 自动化以 Playwright Chromium、Firefox 与 WebKit 覆盖三种引擎，并以实际 Google Chrome 与 Microsoft Edge 稳定版复核品牌通道；每项证据记录引擎与版本，单一引擎通过不得外推；
- Linux Playwright WebKit 只作为 Safari 前置代理。涉及平台字体、媒体、输入或渲染差异的正式 Safari 结论仍需在 macOS 当前稳定版复核；
- 浏览器矩阵复用同一组代表任务和断言，不为某个引擎维护较弱功能清单，也不建立“全语言 × 全路由 × 全视口”的无界截图系统；
- 响应式证据联合检查页面 `scrollWidth`、关键元素边界、当前焦点和任务完成性；隐藏横向溢出或截图看似完整不能单独作为通过证据；
- 跨引擎性能比较使用相同视口、页面状态和交互轨迹。CPU、网络与 CDP 渲染指标只用于 Chromium 系，不把缺失指标补成零或伪装为跨引擎数据；
- 无障碍、减少动态效果、无 JavaScript、脚本初始化失败、下载与打印只按实际能力范围选择代表路径，但正式范围中的关键失败路径不得省略。

## 内容与发布门禁

- `showcase` 和 `preview` 可以包含未批准内容，但必须对各自范围达到完整闭包、零旧译和零回退；`release` 只接受摘要匹配且已经人工批准的内容；
- 列表、首页、详情路由、搜索、票务和验证器消费同一构建快照；集合外实体不得通过深层 URL、搜索、票务或内容资产泄漏；
- 人工继续负责逐字文案、翻译质量、艺术方向、素材权利与发布选择；自动摘要只检查当前精确版本，不冒充人工内容审核；
- 项目内容、源码、正式蓝图、追踪关系与来源边界必须在晋级前一致。研究分析、作者资料和草稿不能作为缺失正式契约的替代物；
- 正式产物中的 URL、站内链接、本地资源、`lang`、canonical、robots、重复 ID 与禁止的远端运行时请求必须通过对应产物门禁。

## 候选与正式验收

- `candidate` 至少完成一次完整仓库门禁、当前风险所需的浏览器验证和关键用户旅程人工浏览；同一轮不重复已经包含的子门禁；
- 每个相关 active 蓝图的当前阶段承诺与验收条件均已实现，或以明确、不会被发布结果掩盖的差距阻止晋级；
- 内容、翻译、视觉或素材仍为预览时，可以保持 `candidate` 并部署受控预览，但不得标记为 `formal` 或进入不接受预览内容的发布集合；
- 只有正式范围内所有相关能力满足各自验收、跨能力不变量和发布资格，并获得人工发布确认后，才更新相应阶段或进入稳定发布主线。
