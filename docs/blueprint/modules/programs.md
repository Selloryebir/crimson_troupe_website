# BP-MOD-PROGRAMS｜场次、剧目与观演衔接

## 用户结果

用户能够在表站或里站浏览本季与历史场次，打开场次和剧目详情，并在表站从可购买的未来场次进入稳定票务入口。

## 边界

- 负责本季与历史 `Performance` 列表、筛选与空状态，`Performance` / `Production` 详情，以及表站票务衔接；
- 消费领域语言蓝图定义的实体、字段归属和时间参照，不在本蓝图重定义领域模型；
- 场次与剧目数据是列表、详情、搜索和票务输入的共同来源；
- 不拥有票篮、票务分支、纪念票、搜索范围或全局污染状态。

## 行为契约

- `Performance` 列表相对当前世界的时间参照显式分为本季与历史，不根据浏览器现实时间自动判定；
- 场次详情使用稳定 `performanceId`，显示其泰拉日期时间、地点、状态、票务可用性及有序剧目编排；剧目详情使用稳定 `productionId`，显示可复用的剧目内容；
- 页面与跨国家版本对应关系使用稳定 ID，不根据标题、译名或显示文本生成实体身份；
- 筛选状态提供可理解的数量和空结果反馈；视觉类型同时考虑列表、详情和窄屏表现；
- 表站可购买的未来场次提供指向同国家版本 `/tickets/` 的次级衔接；未开票、不可购买或票务模组失效时仍到达有效页面并提供返回路径；
- 里站本季与历史场次都属于 1091 快照，当前全部不可购买，只进入里站不可用票务页；
- 新观看渠道必须先满足体验蓝图中的泰拉内合理性，不通过复制数据或引入真实交易实现。

## Demo 基线

- 当前原型支持按城市和月份筛选，并由同一 `Show` 数据生成卡片、详情、搜索条目和概念预约选项；
- 当前混合模型和浮层详情尚未区分 `Performance`、`Production` 及其独立页面。

## Formal 增量

- 迁移到领域蓝图规定的 `Performance`、`Production` 与有序关联，并生成各自稳定详情页；
- 为表站与里站建立各自的本季、历史集合、筛选和空状态；
- 将观看或预约衔接替换为稳定票务页入口；内容规模需要 Markdown 或编辑协作后再评估 Content Collections。

## 验收

- 同一领域数据在列表、详情、搜索和票务入口中没有冲突副本；
- 一个场次可以编排多个剧目，同一剧目可在多个场次中复用；
- 本季、历史、详情和票务衔接在键盘及窄屏下可完成，合法详情 URL 可直接访问；
- 表站与里站依据各自时间参照形成不同集合，`archive` 不被误作历史演出栏目。
