# BP-MOD-PROGRAMS｜场次、剧目与观演衔接

## 用户结果

用户能够在表站或里站浏览本季与历史场次，打开场次和剧目详情；表站可购未来场次进入购票体验，里站场次进入同期静态席位页。

## 边界

- 负责本季与历史 `Performance` 列表、筛选与空状态，`Performance` / `Production` 详情，以及双站各自的票务衔接；
- 消费领域语言蓝图定义的实体与字段，并从 `BP-MOD-TERRA-TIME` 取得当前网站泰拉时间，不在页面中重定义时间算法；
- 场次与剧目数据是列表、详情、搜索和票务输入的共同来源；
- 不拥有票篮、票务分支、纪念票、搜索范围或全局污染状态。

## 行为契约

- 两站首页的本季场次使用首页专属的纵向编辑行，不复用完整列表页的网格密度：桌面端奇数行封面左、文字右，偶数行反向；窄屏统一封面在前、文字在后。每行仍表示一个 `Performance`，封面取首个 `Production`；日期、地点、运营状态和必要公告留在该行稳定信息区。行宽、封面比例、文字起线和行间边界一致，交替不改变语义顺序、场次顺序或链接；
- 首页模式必须由显式页面变体启用，不能顺带改变本季与历史完整列表、筛选、空状态或详情页；表站和里站只共享逐行交替的空间规律，各自保留现代编辑与旧式登记的视觉语言；
- `Performance` 列表按构建快照已经派生的本季与历史集合展示，不读取浏览器现实时间，也不使用运营状态替代时间分类；
- 场次详情使用稳定 `performanceId`，显示有效泰拉日期时间、地点、运营状态、可选改期公告、票务可用性及有序剧目编排；剧目详情使用稳定 `productionId`，显示可复用的完整剧目内容；
- `Performance` 通过稳定 `locationId` 关联城市或地区，并保留该场次特有的场馆、可选区域与可选地址说明；列表可以只显示日期、地点和场馆短名，详情及票务按版面需要组合这些信息；
- 页面与跨国家版本对应关系使用稳定 ID，不根据标题、译名或显示文本生成实体身份；
- 剧目列表与详情从 `BP-CNT-PRODUCTION-VISUAL` 定位对应时间层资产、焦点与裁切资料；本地化标题继续由 HTML 呈现，图片不复制剧目身份或显示文字；
- 表站场次可以编排 `folio` 或 `original` 剧目；1091 里站场次只允许编排 `folio`。列表、详情与搜索继续消费统一剧目注册表，不按来源类别复制页面或消费者；
- 筛选状态提供可理解的数量和空结果反馈；视觉类型同时考虑列表、详情和窄屏表现；
- 只有处于未来集合、运营状态允许且票务可用性明确开放的表站场次提供同国家版本 `/tickets/` 衔接；待定、取消、历史、未开票或模组失效时仍到达有效页面并提供返回路径；
- 里站本季与历史场次都属于当前日期快照并可进入同期静态席位页；页面按捕获时的 `ticketAvailability` 呈现可售、闭幕、取消、待定或未开票状态，但最终结算固定失联，不进入表站 `TicketBasket` 或成功流程；
- 里站等级 `3` 只把已派生的场次列表与详情可见字段投影为同一剧目、请柬时间和克莱布拉松林地城堡；原 `Performance` / `Production` 数量、集合归属、排序、稳定 ID、URL 和链接不变，不为投影创建平行领域实体；
- 当前具体剧目、地点、日期和场次集合只由运行时内容与根集合拥有；现有原创剧目可以保留，但不得被里站场次引用；
- 新观看渠道必须先满足体验蓝图中的泰拉内合理性，不通过复制数据或引入真实交易实现。

## Demo 基线

- 表站与里站分别提供本季、历史、场次详情和剧目详情的稳定页面；
- `Performance` 与 `Production` 使用独立类型化来源及有序关联，列表、筛选、详情、搜索和票务衔接读取同一事实；
- 筛选具有数量与空结果反馈，表站可购买场次进入稳定票务页，里站进入同期静态席位页且不能完成结算。

## Formal 增量

- 迁移到领域蓝图规定的 `Performance`、`Production` 与有序关联，并生成各自稳定详情页；
- 为表站与里站建立各自的本季、历史集合、筛选和空状态；
- 为双站首页增加不影响完整列表的交替编辑行变体，并验证桌面、最低 320px 与语义顺序；
- 将观看或预约衔接替换为稳定票务页入口；内容规模需要 Markdown 或编辑协作后再评估 Content Collections。
- 增加剧目来源类别和里站来源约束验证，在不改变统一列表、详情、搜索与票务接口的前提下接入本阶段活页节目。
- 为实际可见剧目接入独立视觉身份与时间层资产，不为未进入页面的标题生成空素材或视觉特例。
- 从网站时钟与有效排期派生本季和历史，增加待定、完成、取消、改期公告及对应票务衔接，不长期维护手写集合事实。

## 验收

- 同一领域数据在列表、详情、搜索和票务入口中没有冲突副本；
- 一个场次可以编排多个剧目，同一剧目可在多个场次中复用；
- 本季、历史、详情和票务衔接在键盘及窄屏下可完成，合法详情 URL 可直接访问；
- 首页交替只改变视觉方向，完整列表与筛选保持既有职责；里站席位衔接不会误入表站票篮或结局状态机；
- 表站与里站依据各自时间参照形成不同集合，`archive` 不被误作历史演出栏目。
- 未来取消场次仍在本季，历史取消场次仍在历史；改期只改变有效排期，不改变稳定 URL。
- 里站引用原创剧目会在数据或构建验证中失败，表站采用任一来源类别仍使用相同页面和衔接流程。
- 每个实际可见剧目的列表与详情使用同一视觉身份，跨国家版本只替换 HTML 标题和替代文本，不复制资产关系。
