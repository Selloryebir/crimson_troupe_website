# BP-MOD-TICKETING｜表站购票互动

## 用户结果

用户能够在表站建立购票篮，经历包含选择与概率的泰拉内模拟购票流程，并在成功时获得存单及每场演出的可下载、可打印纪念票；模组不可用时仍能到达有效票务页。

## 边界

- 负责表站票务页、`TicketBasket`、购票尝试、结局、价格计算、成功存单和纪念票；
- 只消费可购买的未来 `Performance` 及其分区、基础价格和内容数据，不复制稳定场次或剧目信息；
- 不设置浏览者身份，不收集信息，不进行真实交易、扣款、远端票务请求、兑换或长期保存；
- 不负责里站异常购票。1091 里站在当前正式范围内始终不可购买。

## 入口与降级

- 表站未来场次和观看服务通过同国家版本的稳定 `/tickets/` 工具页进入本模组；它是次级服务入口，不加入四项主导航；
- 模组未实现、未启用、无 JavaScript 或加载失败时，全部入口仍指向该真实存在的页面。页面以泰拉内口吻显示“暂未开票”，并提供返回未来演出等有效路径；
- 启用或停用只改变稳定票务页承载的能力，不改变场次源数据、URL、站内链接或其他页面职责；
- 未开票页随已发布国家版本静态生成，无 JavaScript 时也能读取状态。

## 场馆与分区示意

- 每个可购 `Performance` 通过语言无关的分区示意引用关联自身场馆拓扑；示意资料只表达舞台方向、分区关系和图形锚点，不建立现实测绘、具体座号或独立 `Venue` 实体；
- `TicketOffer` 是分区可售性和 `basePrice` 的唯一运行时来源。图形、图外表单、价格计算和纪念票必须消费同一组报价，不得在示意资料中维护第二份价格或可用性；
- 特里蒙大剧院主舞台采用宽扇形池座与上层看台，维谢海姆宫廷剧院镜厅采用窄长马蹄形围合，诺伯特郡旧车站临时舞台采用站台改造的纵向可拆看台；前两者可以提供 `C / B / A / S / BOX`，旧车站当前只提供 `C / B / A / S`；
- 内联 SVG 只呈现空间关系，图外语义化表单承担完整名称、价格和选择能力。图形与表单双向同步且不以颜色作为唯一状态载体，不可售分区不显示为可操作对象；
- 多场次票篮一次只展开当前操作场次的示意，收起或切换示意不得清空其他场次选择；最低 320px 使用纵向布局，无 JavaScript 时不留下空交互壳；
- 每张示意明确标示舞台方向以及“分区示意，非逐座位选座”或当前国家版本的等价说明，不虚构剩余座位点阵、疏散图、街道地址或第三方地图。

## 状态与生命周期

模组使用三个职责分离的状态：

1. **购票篮：** 从当前可购买的未来 `Performance` 中选择至少一个场次；每个场次只能选择 `C / B / A / S / 包厢` 中的一个分区，且一次体验中按 `performanceId` 限购一张。总票数随当前可购场次数量变化；
2. **购票尝试：** 承载排队、验证、库存变化、价格分支和讽刺性互动；一次尝试不直接修改购票篮；线路、互斥结果、报价变体和旅程标签分开保存，以类型约束排除普通线路携带优先报价等无效组合；
3. **结局：** 至少包括购票成功、购票失败和网络波动。失败或网络波动后可以使用原购票篮重试；成功不得因重复提交重复生成同一次结果。

- 购票篮在失败、网络波动、线路选择、取消线路、同标签页内页面切换和主动重试之间保持；
- 成功后状态冻结为只读结算结果，不能因生成票面而立即清空；只有用户明确开始新一轮、清空或结束本次体验时才重置；
- 限购只约束单次“购票篮 → 购票 → 出票”体验。完成或结束后可以重新开始，不形成账号级、设备级或永久购买限制；
- 全部状态只属于当前标签页，不跨标签页或设备同步，也不写入长期持久化存储。关闭标签页即结束体验；关闭流程界面或离开票务页不隐式清空同标签页状态。
- 票篮、尝试和冻结结果只保存 `performanceId`、分区、阶段、线路、报价变体、互斥结果、尝试次数、上次结果、一次性挽留、旅程标签、差额与印章语义 ID、金额、票号等稳定 ID、枚举和数值，不保存分区、差额、印章、状态或票面显示字符串；
- 在当前阶段切换国家版本不重置同标签页票篮、尝试或冻结结果，目标版本以相同语义状态重新解析全部显示文字。未来如需按国家版本隔离状态，必须先修改本蓝图，不能在选择器或存储实现中静默改变；
- 同一体验不得连续两次得到网络波动；挽留报价最多出现一次；最多经历三个需要重新提交的结果节点，达到上限后以“席位回流”或“人工复核”收束为普通线路成功。测试可以注入结果序列稳定复现边界，正式运行仍由同一状态入口消费随机结果；
- 拒绝优先线路并返回普通线路后，可以在上述次数上限内以“原渠道出现回流席位”收束；该结果保留拒绝和回流旅程语义，但不改变基础票价；
- 当前普通线路首轮基线为 `32%` 成功、`36%` 席位不可用、`32%` 网络波动，优先线路为 `58%` 成功；这些数值用于本阶段实现与测试，不得以反复调参代替体验验收；
- 会话状态结构升级时提高版本并安全重置旧版本，不为一次性开发状态保留长期兼容分支。

## 分支与价格契约

- 流程同时包含用户选择和概率结果。普通线路失败后可以重试、修改票篮或查看站内“联合席位回流通道”；拒绝合作通道后只显示一次挽留，仍然拒绝则返回票篮；优先线路可能成功或生成失败服务记录；
- 讽刺对象是抽象的票务暗黑模式，例如库存反复变化、费用叠加、无意义验证、强制等待和伪稀缺提示；不得复制现实网站名称、商标、文案、独特构图或代码；
- 价格使用整数龙门币（LMD），并保持四种数据语义：
  - `basePrice`：某场次某分区的单张基础票面价；
  - `baseTotal`：购票篮内全部 `basePrice` 之和；
  - `adjustments`：流程分支产生的加价、费用或其他差额明细；
  - `settledTotal`：`baseTotal` 与全部 `adjustments` 金额之和；
- `baseTotal` 与 `settledTotal` 均从来源数据计算，不作为可独立编辑的重复事实；纪念票直接显示对应分区 `basePrice`，不受差额或结算总额影响；
- 成功结算按场次列出 `basePrice`，并汇总 `baseTotal`、`adjustments` 和 `settledTotal`，使单张票面价、基础总额与模拟结算总额可以区分。
- 优先线路原报价为 `baseTotal` 的 `150%`，即差额为 `50%`；一次性挽留把差额降为 `48%`，最终报价为 `148%`。界面必须在接受前同时显示基础总额、差额、最终报价、结果仍可能失败和绝对 LMD 金额；
- 优先线路失败显示屏幕内“失败服务记录”：获配席位为 `0`，模拟服务费为 `baseTotal` 的 `25%`。该记录不生成存单、纪念票或下载入口，不写入账户，也不声称发生真实扣款；
- 价格百分比统一由整数 LMD 派生函数计算，不在内容或组件中维护第二套金额。优先线路及失败记录不得修改来源 `TicketOffer` 或纪念票 `basePrice`。

## 成功存单与纪念票

- 成功结局显示一个屏幕内存单，汇总本次全部场次、分区、基础总额、差额、结算总额和结局信息；存单就是结算画面，不生成独立订单或存单下载文件；
- 存单下方按场次逐一显示纪念票，每个场次生成一张具有自身基础设计的独立票面，不把多个场次压缩到同一票面；
- 每张票至少包含场次、日期时间、分区、`basePrice`、LMD 单位、虚构票号和二维码，并分别提供直接下载和打印入口；
- 屏幕、下载和打印版本使用同一票务内容；版式可以适配媒介，但不得遗漏或裁切场次、时间、分区、基础票价、票号或二维码；
- 票面由“场次基础票面 + 可组合印章”生成。同一次结局只产生一组印章语义并作用于全部票面；所有成功票具有核心入场章，并按实际旅程叠加普通／优先线路、网络恢复、回流席位、一次性优惠或人工复核语义；各基础票面可以调整安全落点，但表达的支线结果必须一致；
- 印章不得覆盖或改写场次信息、基础票价或二维码。成功后不得要求登录、填写身份、二次抽取、分享、兑换或其他附加任务；
- 二维码只承载与票面旁侧显示一致的随机数值，不作为订单号、排序号、唯一键、验证或兑换凭据，也不链接支付、追踪或真实票务系统；数值不全局去重，不同用户可以取得相同号码。
- 组合印章由最终线路和少量旅程标签派生，不建立完整结果组合枚举；网络恢复可以表现为轻微二次套印，回流席位使用行政附章，优惠使用票券缺口或注销痕迹，人工复核使用编号或审核短线。差异不能只依赖颜色，也不显示成就、稀有度或未收集项目；
- 使用现有十二位票号作为稳定种子派生票纹、细线或打孔节奏，不增加持久随机字段。相同冻结结果跨国家版本重新渲染时，票号、二维码、票纹和印章语义保持一致；
- 优先失败的作废语义只出现在屏幕失败记录；不为失败生成可下载票，也不为组合状态维护完整图片资产或新增 PNG 导出。

## 内容、本地化与安全

- 购票篮、流程、存单和纪念票不填写、不预设、不随机生成或选择姓名、证件、联系方式、地址、支付账户及用户画像；
- 泰拉内沉浸感由剧团、场次、票务规则和界面语言建立，不依赖虚构身份或伪造真实支付能力；
- 成功结算画面页脚以小字说明“仅为小游戏内容，不产生任何兑换责任”。该说明不写入纪念票、不扩张为流程常驻提示，也不替代全站页脚同人声明；
- 场次、剧目、分区、价格、时间和翻译来自类型化内容数据；结算与票面语言跟随当前国家版本，并受本地化发布门禁约束；
- 客户端只接收当前国家版本的票务消息和当前票面内容，不加载全站翻译包，也不保留中文默认反馈；
- 所有结局提供继续、重试或退出路径，不使用无限排队或无法跳过的倒计时。减少动态效果只削弱排队、抖动和库存变化动画，不删除规则、反馈或结局。

## Demo 基线

- 表站稳定票务页可以建立多场次票篮，并进入包含失败、网络波动、加价线路和成功结果的模拟流程；
- 失败与重试保持票篮，成功结果冻结并生成存单、逐场纪念票、SVG 下载和打印表现；
- 无 JavaScript 或初始化失败时显示“暂未开票”静态降级，里站始终保持不可购买。

## Formal 增量

- 先建立全部表站入口共用的静态未开票页，再按上述状态模型启用完整模组；
- 基于同一类型化结果生成屏幕存单、逐场纪念票、下载和打印表现；
- 以可复现方式验证选择、概率、失败重试、成功冻结、生命周期和降级，不引入账号、后端或真实交易能力。
- 验证炎国建立的票篮与冻结结果在切换哥伦比亚后保持同一事实，并以哥伦比亚内容重新呈现；旧状态版本可以安全重置，不保留一次性兼容分支。
- 为三个可购场次建立不同的分区示意并校正实际可售分区；用有限状态流程、明确费用不变量和组合印章替换无限重试与固定扁平印章；
- 继续使用原生 TypeScript、内联 SVG、会话存储和现有凭据媒介，不为本增量引入前端框架、外部平台、长期成就或新的下载格式。

## 验收

- 失败、网络波动、取消支线和主动重试不会丢失购票篮，成功后重复提交不会重复生成结果；
- 国家版本切换不会丢失当前票篮、尝试或冻结结果，状态中不存在国家版本显示字符串；
- 三个场次的图形、图外选择、价格计算和纪念票只消费各自实际 `TicketOffer`；键盘和 320px 路径能够完成与图形点击相同的任务；
- 网络波动不连续出现，一次性挽留不重复，一次体验最多三个需重新提交的结果节点；确定性测试可以复现直接成功、网络恢复、普通重试、拒绝优先后的回流和人工复核收束；
- 存单正确区分基础总额、差额和结算总额，每张票只显示对应 `basePrice`；
- 优先报价、挽留报价和失败服务费分别满足 `150%`、`148%` 和 `25%` 的金额不变量；失败服务记录不生成票或真实交易暗示；
- 每个成功场次都有无需身份或附加任务即可下载、打印的独立纪念票，且必要内容不被裁切；
- 普通直接成功、网络恢复、回流成功和优先成功具有可区分但不遮挡关键信息的组合印章，相同冻结结果跨国家版本和媒介保持语义稳定；
- 模组关闭、脚本关闭或加载失败时，稳定票务页、不可用反馈和返回路径仍成立，表站其他任务不受影响。
