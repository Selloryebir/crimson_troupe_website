# BP-MOD-TICKETING｜表站购票互动

## 用户结果

用户能够在表站建立购票篮，经历包含选择与概率的泰拉内购票互动流程，并在成功时获得席位受理凭单及每场演出的可下载、可打印纪念票；模组不可用时仍能到达有效票务页。

## 边界

- 负责表站官网票篮、虚构第三方处理页面、`TicketBasket`、购票尝试、结局、价格计算、成功凭单和纪念票；
- 只消费构建快照中属于未来集合、运营状态允许且 `ticketAvailability` 明确开放的 `Performance` 及其分区、基础价格和内容数据，不复制稳定场次或剧目信息；
- 不设置浏览者身份，不收集信息，不进行真实交易、扣款、远端票务请求、兑换或长期保存；
- 不负责里站同期席位页或异常购票；前者由 `BP-MOD-ARCHIVE` 拥有并只复用稳定分区与报价类型，后者仍须未来独立规划。里站不会进入本模组的 `TicketBasket`、概率流程、结算结果或纪念票。

## 入口与降级

- 表站未来场次和观看服务通过同国家版本的稳定 `/tickets/` 工具页进入本模组；它是次级服务入口，不加入四项主导航；
- 官网 `/tickets/` 只负责场次、分区、票篮和提交确认；有效票篮提交后进入同国家版本的 `/tickets/partner/`，由虚构第三方票务平台“水稻网”承载连接、库存、路线、结果、凭单和失败记录；
- `/tickets/partner/` 是同一静态站点内的独立服务表面，不执行真实跳转或远端请求。直接访问、状态损坏、无 JavaScript 或没有有效票篮时显示明确说明，并提供返回官网票篮的合法路径，不留下伪支付控件；
- 模组未实现、未启用、无 JavaScript 或加载失败时，全部入口仍指向该真实存在的页面。页面以泰拉内口吻显示“暂未开票”，并提供返回未来演出等有效路径；
- 启用或停用只改变稳定票务页承载的能力，不改变场次源数据、URL、站内链接或其他页面职责；
- 未开票页随已发布国家版本静态生成，无 JavaScript 时也能读取状态。

## 虚构平台与品牌素材

- 第三方票务平台使用稳定身份“水稻网”，负责标准渠道、连接与库存反馈、结算和凭单；黄牛抢票平台使用稳定身份“跳楼机”，只在标准渠道失败后提供直接加价或一次性优惠的优先线路；
- 水稻网页面页眉持续同时展示水稻网名称与 Logo；其连接、网络异常和结算提示框使用含水稻网名称的可见标题，并在框内展示水稻网 Logo。跳楼机邀请、挽留、成功和失败提示框同样同时展示跳楼机名称与独立 Logo，不退化为无来源的通用提示；
- 两个平台的稳定 ID、语言无关 Logo 资产和按国家版本提供的显示名分开维护，通过显式映射装配；名称不得写入状态机、控制器、CSS 或 Logo 图片，Logo 也不得成为平台身份的唯一可访问信息；
- 平台引用稳定资产身份和统一装配槽位，不从文件名或路径推导。当前两枚原创 Logo 已获人工批准并通过正式资产映射、替代文本和批准资格接入；后续候选仍须以预览身份隔离，不改平台 ID、状态机、路由或组件接口，`approved-only` 不得采用临时资产；
- 水稻网采用更鲜亮的商业配色、圆角卡片、胶囊标签和圆润系统字体表达“表面亲民”；跳楼机使用独立构图表达急迫与加价诱导。两枚 Logo 不得只是同形换色，也不得复制现实平台、第三方商标、游戏徽记或独特构图；
- 品牌提示使用语义化 `dialog` 或等价结构，具备可理解标题、拒绝／关闭路径、`Escape` 行为和焦点恢复；品牌风格不得以低对比度、误导焦点或无法退出实现讽刺。

## 场馆与分区示意

- 每个可购 `Performance` 通过语言无关的分区示意引用关联自身场馆拓扑；示意资料以稳定楼层和空间区域表达舞台方向、楼层、分区关系与图形锚点，不建立现实测绘、具体座号或独立 `Venue` 实体；
- `TicketOffer` 是分区可售性和 `basePrice` 的唯一运行时来源。图形、图外表单、价格计算和纪念票必须消费同一组报价，不得在示意资料中维护第二份价格或可用性；
- 每个空间区域拥有稳定区域身份、所属楼层、`TicketZone`、独立路径和必要标签锚点；同一 `TicketZone` 可以分布在多个不相连区域或楼层，包厢可以是多个独立块。所有同等级区域共享一个 `TicketOffer` 与选择结果；
- 图形必须以分隔清楚的楼层小图或等价结构区分池座、楼座和包厢，不把带透明度的楼层叠在同一平面；区域数量和几何形状不成为第二份价格或可售性来源；
- 特里蒙大剧院主舞台采用宽扇形池座、U形上层看台和多个包厢块；靠近舞台且正对中心的区域等级最高，同距离侧区至少降低一级，后区比中前区更宽。维谢海姆宫廷剧院镜厅采用窄长池座与分层马蹄形围合，中心池座、两侧围合、上层环廊和多个包厢分别绘制。两者可以提供 `C / B / A / S / BOX`；
- 诺伯特郡旧车站临时舞台采用单层或低层纵向可拆看台，体现容量较小与设施简化，只提供 `C / B / A`，不提供 `S / BOX`，也不画成等宽线性条带；
- 蒙特卢佩巡演剧场主厅采用池座、马蹄形楼座与分散包厢，提供 `C / B / A / S / BOX`；临渠巡演剧场主厅采用单层扇形主座与侧翼看台，只提供 `C / B / A / S`；
- 伦蒂尼姆巡演剧场主厅采用宽池座、两层 U 形楼座与多组包厢，提供 `C / B / A / S / BOX`；青隧巡演剧场主厅采用纵深池座、侧廊与上层正座，只提供 `C / B / A / S`；
- 内联 SVG 只呈现空间关系，图外语义化表单承担完整名称、价格和选择能力。图形与表单双向同步且不以颜色作为唯一状态载体，不可售分区不显示为可操作对象；
- 多场次票篮一次只展开当前操作场次的示意，收起或切换示意不得清空其他场次选择；最低 320px 使用纵向布局，无 JavaScript 时不留下空交互壳；
- 每张示意明确标示舞台方向以及“分区示意，非逐座位选座”或当前国家版本的等价说明，不虚构剩余座位点阵、疏散图、街道地址或第三方地图。

## 状态与生命周期

模组使用三个职责分离的状态：

1. **购票篮：** 从当前构建快照解析的可购买未来 `Performance` 中选择至少一个场次；每个场次只能选择 `C / B / A / S / 包厢` 中的一个分区，且一次体验中按 `performanceId` 限购一张。总票数随当前可购场次数量变化；
2. **购票尝试：** 承载排队、验证、库存变化、价格分支和讽刺性互动；一次尝试不直接修改购票篮；线路、互斥结果、报价变体和旅程标签分开保存，以类型约束排除普通线路携带优先报价等无效组合；
3. **结局：** 保存有序 `endingHistory`、当前或最终 Ending ID 以及是否终止本轮；非终止结果保留购票篮继续探索，成功冻结同一结果且不得因重复提交重复生成。

- 每个可购场次进入选择阶段时即拥有一个有效默认预选分区；图外分区控件和示意图始终可操作，不由场次复选框控制 `disabled`。未勾选时切换分区只更新该场次的预选与视觉反馈，不隐式入篮；
- 勾选场次时把当前预选分区及其来源 `basePrice` 加入票篮；已入篮场次切换分区时同步更新票篮。取消勾选只移除票篮项，不重置页面预选；同一页面流程返回选择阶段时保留控件值；
- 票篮为空时提交仍失活；反馈分别表达“正在查看的分区”和“已经加入票篮的场次”。图形点击不代替勾选，且图形与图外表单具有等价键盘能力；
- 购票篮在失败、网络波动、线路选择、取消线路、同标签页内页面切换和主动重试之间保持；
- 成功后状态冻结为只读结算结果，不能因生成票面而立即清空；只有用户明确开始新一轮、清空或结束本次体验时才重置；
- 限购只约束单次“购票篮 → 购票 → 出票”体验。完成或结束后可以重新开始，不形成账号级、设备级或永久购买限制；
- 全部状态只属于当前标签页，不跨标签页或设备同步，也不写入长期持久化存储。关闭标签页即结束体验；关闭流程界面或离开票务页不隐式清空同标签页状态。
- 票篮、尝试和冻结结果只保存 `performanceId`、分区、阶段、线路、报价变体、互斥结果、尝试次数、有序 Ending 历史、一次性挽留、旅程标签、差额与印章语义 ID、金额、票号、冻结的泰拉受理时间等稳定 ID、结构、枚举和数值，不保存分区、差额、平台、印章、状态或票面显示字符串；
- 成功状态形成时从 `BP-MOD-TERRA-TIME` 的表站时钟取得一次 `siteTerraNow` 并冻结为受理时间；重复渲染、恢复会话或切换国家版本只改变格式化，不重新取时，也不得读取浏览器现实时间或设备时区；
- 在当前阶段切换国家版本不重置同标签页票篮、尝试或冻结结果；目标版本重新解析官网、水稻网和凭单界面文字，纪念票保持举办地语言主层，并以目标网站语言重新渲染辅助层。未来如需按国家版本隔离状态，必须先修改本蓝图，不能在选择器或存储实现中静默改变；
- 同一体验不得连续两次得到网络波动；挽留报价最多出现一次；最多经历三个需要重新提交的结果节点，达到上限后以“席位回流”或“人工复核”收束为普通线路成功。测试可以注入结果序列稳定复现边界，正式运行仍由同一状态入口消费随机结果；
- 拒绝优先线路并返回普通线路后，可以在上述次数上限内以“原渠道出现回流席位”收束；该结果保留拒绝和回流旅程语义，但不改变基础票价；
- 当前普通线路第一次提交的基线为 `12%` 成功、`56%` 席位不可用、`32%` 网络波动，使首次体验更常进入既有处理分支；后续普通重试仍为 `32%` 成功、`36%` 席位不可用、`32%` 网络波动，优先线路仍为 `58%` 成功。次数上限和可靠收束不随首轮调整延长；这些数值用于本阶段实现与测试，不得以反复调参代替体验验收；
- 会话状态结构升级时提高版本并安全重置旧版本，不为一次性开发状态保留长期兼容分支。

路线结果使用以下稳定闭集；显示名称与文案属于国家版本内容，不写入状态：

| Ending ID                 | 触发                                       | 终止本轮 | 后续能力                     |
| ------------------------- | ------------------------------------------ | -------- | ---------------------------- |
| `ENDING_NETWORK_ERROR`    | 标准渠道发生叙事网络波动                   | 否       | 保留票篮并重试               |
| `ENDING_NORMAL_SUCCESS`   | 标准渠道成功，包括次数上限后的普通成功收束 | 是       | 进入凭单与纪念票             |
| `ENDING_REJECT_RESCALPER` | 拒绝跳楼机并再次拒绝一次性优惠             | 否       | 返回标准渠道                 |
| `ENDING_SCALPER_SUCCESS`  | 直接接受跳楼机并成功                       | 是       | 进入含渠道项目的凭单与纪念票 |
| `ENDING_SCALPER_FAILED`   | 直接接受跳楼机但失败                       | 否       | 显示失败服务记录并重试       |
| `ENDING_DISCOUNT_SUCCESS` | 首次拒绝后接受优惠并成功                   | 是       | 进入含减让项目的凭单与纪念票 |
| `ENDING_DISCOUNT_FAILED`  | 首次拒绝后接受优惠但失败                   | 否       | 显示失败服务记录并重试       |

网络波动、拒绝和失败是可继续的阶段结果；只有三个成功 Ending 生成纪念票。既有“席位回流”和“人工复核”属于到达上限后的收束旅程语义并归入 `ENDING_NORMAL_SUCCESS`，不得扩张为第八或第九种 Ending。

## 第三方处理节拍

- 有效票篮进入水稻网后依次呈现连接平台、核对库存和确认结果等有限阶段，再显示路线结果；当前预览整体感知等待约为 `1.5—3` 秒并由集中参数管理，确定性测试可以注入零延迟调度器；
- 一次提交只抽取并锁定一次结果；重复点击、进度更新、组件重渲染或恢复页面不得重新抽取；
- 有实际阶段比例时使用语义化进度状态，旋转图形只作辅助装饰，不伪装可证明的真实网络进度；
- `prefers-reduced-motion` 下停止旋转和非必要过渡，但保留状态文字与有限处理节拍，不退化为无反馈的瞬间跳转；
- 等待不使用无限排队、倒计时焦虑或重复点击提高概率，流程阶段变化继续满足焦点与简短 live 状态要求。

## 分支与价格契约

- 流程同时包含用户选择和概率结果。标准渠道失败后可以继续通过水稻网按原价抢票、返回票篮修改选择，或转至跳楼机查看加价抢票方案；查看方案不等于接受，必须在独立报价页再次明确接受或拒绝；拒绝后只显示一次挽留，仍然拒绝则返回标准渠道；跳楼机的直接或优惠线路均可能成功或生成失败服务记录；
- 标准抢票与查看加价方案在失败页使用同尺寸且均清晰可见的控件，不以实体按钮和低显著度文字链接制造无法比较的层级。平台、价格后果与动作必须由文字直接表达；颜色只辅助区分中性原价路线和警示加价路线；
- 讽刺对象是抽象的票务暗黑模式，例如库存反复变化、费用叠加、无意义验证、强制等待和伪稀缺提示；不得复制现实网站名称、商标、文案、独特构图或代码；
- 价格使用整数龙门币（LMD），并保持四种数据语义：
  - `basePrice`：某场次某分区的单张基础票面价；
  - `baseTotal`：购票篮内全部 `basePrice` 之和；
  - `adjustments`：流程分支产生的加价、费用或其他差额明细；
  - `settledTotal`：`baseTotal` 与全部 `adjustments` 金额之和；
- `baseTotal` 与 `settledTotal` 均从来源数据计算，不作为可独立编辑的重复事实；纪念票直接显示对应分区 `basePrice`，不受差额或结算总额影响；
- 表站票务候选从统一快照及逐场 `ticketAvailability` 派生，并满足表站、本季、运营状态和开票资格；`homepagePerformanceIds` 不充当第二份开票注册表；
- 逐场报价不复用组件内标准价格数组，也不从场馆或城市属性动态计算。实际存在的分区保持 `C < B < A < S < BOX`；缺少的等级不生成报价。旧车站只比较 `C < B < A` 且共享等级价格明显低于正式剧院，其他场次也使用与自身拓扑对应的不同候选价格；
- 本阶段具体 LMD 数值属于未批准预览内容，正式发布前由人工逐场审核。调整报价通过既有内容摘要使旧批准资格失效，不建立 Demo／Formal 双价格路由；
- 成功凭单按场次列出 `basePrice`，并由 `baseTotal`、`adjustments` 和 `settledTotal` 计算对外票款小计、渠道项目、减让和应付合计；内部字段名不得直接成为访客文案。
- 优先线路原报价为 `baseTotal` 的 `150%`，即渠道附加为 `50%`；一次性挽留的最终报价为 `148%`。挽留成功在凭单中分别显示原始 `50%` 渠道附加与使最终附加降至 `48%` 的负向减让，所有展示行与 `settledTotal` 必须精确相加；接受前仍同时显示票款小计、渠道附加、最终报价、结果可能失败和绝对 LMD 金额；
- 优先线路失败显示屏幕内“失败服务记录”：获配席位为 `0`，席位检索受理费为 `baseTotal` 的 `25%`。该记录不生成凭单、纪念票或下载入口，不写入账户；底部只说明未发生扣款且记录不构成费用或席位凭证，不反复使用“模拟服务”等开发视角措辞；
- 价格百分比统一由整数 LMD 派生函数计算，不在内容或组件中维护第二套金额。优先线路及失败记录不得修改来源 `TicketOffer` 或纪念票 `basePrice`。

## 成功凭单与纪念票

- 成功结局显示一个屏幕内“席位受理凭单”或当前国家版本中的等价运营称谓；它是结算画面，不包装成具有现实税务或兑换效力的发票，也不生成独立订单或凭单下载文件；
- 凭单顶部显示冻结的泰拉受理时间、配发渠道和席位已经配发的受理状态。每个票篮项目形成一条演出席位明细，包含当前网站语言下的剧目标题、演出日期时间、城市与场馆、席区和该票的票面金额；普通成功没有渠道项目时直接省略该行，不显示“差额：无”；
- 炎语凭单使用“演出席位票款”“票款小计”“优先席位调度服务”“即时确认减让”“应付合计”“配发渠道”和“受理状态”；其他国家版本提供语义等价本地化，不暴露 `baseTotal`、`adjustments`、`settledTotal` 或 Ending ID；
- 凭单下方按场次逐一显示纪念票，每个场次生成一张具有自身基础设计的独立票面，不把多个场次压缩到同一票面；
- 屏幕中的每张纪念票采用上下结构：完整票面占据卡片上方全部可用宽度，场次、日期时间、场馆、席区、票价、票号与操作集中在下方信息区；窄屏进一步收为单列，不把票面重新压回左右分栏；
- 每张票至少包含场次、日期时间、分区、`basePrice`、LMD 单位、虚构票号和二维码，并分别提供直接下载和打印入口；
- 屏幕、下载和打印版本使用同一票务内容；版式可以适配媒介，但不得遗漏或裁切场次、时间、分区、基础票价、票号或二维码。票面生成器必须输出可以作为独立 XML 文档解析的合法 SVG；HTML 对无值属性等宽松语法的容忍不构成媒介有效性；
- 全部纪念票固定采用左侧票钳三孔制式；它不是玩家选择、会话状态、稀有变体或重新抽取结果，三个孔位不得遮挡票面字段；
- 纪念票标题、地点和日期使用确定性的 Unicode 字素或合法语言断点换行，并设可读字号下限；不得按 UTF-16 下标拆分日文无空格文本、俄文长词或带组合符的希腊文。达到字号下限后增加受控行或内容区域，不用省略号静默删除关键事实；
- 双语票面按语义字段组排列：举办地主标题与当前网站辅助标题相邻，剧目类型位于完整标题组之后；主辅日期时间组成一组，主辅城市与场馆组成一组，席区标签与共享分区值组成一组。缺少辅助层时不保留空行；换行或字号调整只改变当前字段组高度，后续字段从实际边界继续排布，不得让剧目类型、日期或场馆插入错误的翻译配对；
- 票面由“场次基础票面 + 单枚七构件组合印章”生成。同一次结局只产生一组印章语义并作用于全部票面；最终成功 Ending 决定核心授权构件，较早经历的网络、拒绝或失败结果激活外围构件，各基础票面可以调整安全落点，但表达的 Ending 历史必须一致；
- 结算页不另行展开完整路线日志、印章构件图例或隐藏路线说明；事务必需事实由凭单和票面直接表达，过程痕迹只通过组合印章克制保留；
- 印章不得覆盖或改写场次信息、基础票价或二维码。成功后不得要求登录、填写身份、二次抽取、分享、兑换或其他附加任务；
- 二维码只承载与票面旁侧显示一致的随机数值，不作为订单号、排序号、唯一键、验证或兑换凭据，也不链接支付、追踪或真实票务系统；数值不全局去重，不同用户可以取得相同号码。
- 组合印章预留七个稳定视觉构件，分别映射七个 Ending；以中央纹章、外环缺口、套印偏差、端点记号、箭头、编号位或边框残缺等非文字方法激活实际经历，未经历部分保持结构性留白或弱化，不显示结局名称、成就、稀有度、收集进度或“未收集”状态；
- 回流席位和人工复核只改变 `ENDING_NORMAL_SUCCESS` 构件内部的行政纹理，不新增独立收集位。必要的无障碍名称可以直接描述实际路线，费用和成功事实仍由凭单正文表达，不要求访客解读印章；
- 使用现有十二位票号作为稳定种子派生票纹、细线或打孔节奏，不增加持久随机字段。相同冻结结果跨国家版本重新渲染时，票号、二维码、票纹和印章语义保持一致；
- 优先失败的作废语义只出现在屏幕失败记录；不为失败生成可下载票，也不为组合状态维护完整图片资产或新增 PNG 导出。

## 内容、本地化与安全

- 购票篮、流程、凭单和纪念票不填写、不预设、不随机生成或选择姓名、证件、联系方式、地址、支付账户及用户画像；
- 泰拉内沉浸感由剧团、场次、票务规则和界面语言建立，不依赖虚构身份或伪造真实支付能力；
- 票务入口、处理状态、报价、失败记录和成功凭单使用剧团、水稻网与跳楼机各自的泰拉内运营口吻，不在正常步骤中反复显示“模拟体验”“模拟流程”“模拟服务”或“模拟结算”。本规则只约束票务状态说明，不删除剧目观演提示中“模拟礼炮”“模拟降雪”等真实内容语义；
- 成功结算画面页脚以小字说明“仅为小游戏内容，不产生任何兑换责任”。该说明不写入纪念票、不扩张为流程常驻提示，也不替代全站页脚同人声明；
- 场次、剧目、分区、价格、时间和翻译来自类型化内容数据；网站界面、平台提示和凭单操作文案跟随当前国家版本。纪念票大字主层由 `locations[performance.locationId].countryEditionId` 决定，小字辅助层由访客当前选择的网站 `editionId` 决定，不读取浏览器系统语言；
- 主辅版本属于同一实际语言时不重复辅助层；当前至少将 `en-GB` 与 `en-US` 视为同一英语语言族。炎语网站购买维谢海姆场次显示莱塔尼亚语大字与炎语小字，购买特里蒙场次显示哥伦比亚语大字与炎语小字；莱塔尼亚语网站购买维谢海姆场次只显示莱塔尼亚语；
- 双语只覆盖剧目标题、城市、场馆、日期／分区标签和必要行政文字；票价、`LMD`、分区值、场次编号、票号与二维码等共享事实只显示一次。屏幕、SVG 下载和打印读取同一票面投影，并为每段文字提供准确语言属性与系统字体；
- 票面日期时间从同一结构化 `TerraDateTime` 分别按主辅 locale 集中格式化，不在消息包或 SVG 模板中维护日期副本；炎语采用自然年月日顺序，其他版本遵循自身日期顺序、月份表达、标点和时制。字段标签只表达“日期与时间”，不附加 `Terra`、`泰拉` 或对应译法；
- 票号在屏幕说明和票面字段中均使用当前语言下“票号”“TICKET NUMBER”“券番号”等语义等价称谓，不称为“票面数值”或矩阵编号。二维码可以承载相同数值，但不改变该字段的票号语义；
- `pending`、`cancelled`、历史场次、票务未开放场次和全部里站场次不能进入本模组的表站票篮；改期后的资格只读取有效排期与当前状态。里站同期可售事实只供其静态席位页展示，不构成本模组候选；
- 客户端只接收当前国家版本的界面消息，以及当前可购买场次所需的举办地主层／当前网站辅助层票面投影；主辅同语时省略辅助层，不加载其他国家版本页面、完整消息包或搜索索引，也不保留炎语默认反馈；
- 每次流程阶段转换后，焦点进入由当前本地化动态标题命名的区域或标题本身；live 状态只简短报告实际分支，不把焦点放入无名结果容器；
- 所有结局提供继续、重试或退出路径，不使用无限排队或无法跳过的倒计时。减少动态效果只削弱排队、抖动和库存变化动画，不删除规则、反馈或结局。

## Demo 基线

- 表站稳定票务页可以建立多场次票篮，并进入包含失败、网络波动、加价线路和成功结果的模拟流程；
- 失败与重试保持票篮，成功结果冻结并生成凭单、逐场纪念票、SVG 下载和打印表现；
- 无 JavaScript 或初始化失败时显示“暂未开票”静态降级；里站由档案能力提供无脚本可读、结算失联的静态席位页。

## Formal 增量

- 先建立全部表站入口共用的静态未开票页，再按上述状态模型启用完整模组；
- 基于同一类型化结果生成屏幕凭单、逐场纪念票、下载和打印表现；
- 让票务候选与页面、搜索共同消费统一构建快照，移除对完整场次注册表的平行筛选；
- 以可复现方式验证选择、概率、失败重试、成功冻结、生命周期和降级，不引入账号、后端或真实交易能力。
- 验证炎国建立的票篮与冻结结果在切换哥伦比亚后保持同一事实，官网、水稻网与凭单界面使用哥伦比亚内容重新呈现，纪念票保持各场次举办地主层并以哥伦比亚语重新渲染辅助层；旧状态版本可以安全重置，不保留一次性兼容分支。
- 为当前全部可购场次建立与自身场馆对应的分区示意并校正实际可售分区；用有限状态流程、明确费用不变量和组合印章替换无限重试与固定扁平印章；
- 将分区预选与场次入篮解耦，并用分层、多区域拓扑和逐场候选报价替代线性分区与共享价格数组；
- 以水稻网独立页面、跳楼机品牌提示、有限处理节拍和七种 Ending 替代同页瞬时通用结果；当前正式原创 Logo 已替换布局验证候选，业务接口保持不变；
- 让纪念票按举办地语言与可选当前网站语言生成受限投影，并让发布门禁覆盖每个可购买场次真实消费的主辅票面依赖；
- 让成功结果冻结网站泰拉受理时间，以完整演出席位明细、渠道项目、减让与应付合计替代直接暴露内部金额字段的旧凭单；
- 以泰拉内运营文案和结果明确的路线按钮替代流程中的重复“模拟”提示、抽象“原线路”与低显著度加价入口；
- 让屏幕、下载与打印共用的 SVG 票面通过真实 XML 解析和图像解码验证，不再只检查字符串标记；
- 继续使用原生 TypeScript、内联 SVG、会话存储和现有凭据媒介，不为本增量引入前端框架、外部运行时服务、长期成就或新的下载格式。

## 验收

- 失败、网络波动、取消支线和主动重试不会丢失购票篮，成功后重复提交不会重复生成结果；
- 国家版本切换不会丢失当前票篮、尝试或冻结结果，状态中不存在国家版本显示字符串；
- 当前全部可购场次的图形、图外选择、价格计算和纪念票只消费各自实际 `TicketOffer`；键盘和 320px 路径能够完成与图形点击相同的任务；
- 未勾选场次时仍可查看和切换分区且不会入篮；勾选、改区、取消和返回选择阶段保持预选与票篮边界一致，空票篮不能提交；
- 全部可购场馆的楼层和区域关系可辨，多个同等级区域得到同一选择结果，没有透明楼层重叠或已删除分区残留；旧车站只出现 `C / B / A`，临渠与青隧不出现 `BOX`，逐场候选价格从选择到票面保持唯一来源；
- 网络波动不连续出现，一次性挽留不重复，一次体验最多三个需重新提交的结果节点；确定性测试可以复现直接成功、网络恢复、普通重试、拒绝优先后的回流和人工复核收束；
- 七种 Ending 均可通过注入结果序列复现；一次提交只抽取一次结果，水稻网处理阶段不会因重复点击或重渲染改变结果；
- 凭单逐场显示排期、场馆、席区和票面金额，并正确汇总票款小计、渠道项目、负向减让和应付合计；普通成功省略空渠道项目，每张票只显示对应 `basePrice`；
- 优先报价、挽留报价和失败服务费分别满足 `150%`、`148%` 和 `25%` 的金额不变量；失败服务记录不生成票或真实交易暗示；
- 每个成功场次都有无需身份或附加任务即可下载、打印的独立纪念票，且必要内容不被裁切；
- 票面显示举办地语言大字与当前网站语言小字，二者同语时不重复，`en-GB` 与 `en-US` 视为同一英语语言族；同一多场次凭单允许每张票按自身举办地选择主层，切换网站国家版本只重新解析凭单和辅助层，不改变票号、二维码、价格、印章或主层归属；
- 异语票面的主辅标题、主辅日期与主辅场馆分别相邻且不会被剧目类型或其他字段拆开；同语票面不留下辅助层空位。九个国家版本使用自然日期时间格式和准确票号术语，不残留 `TERRA DATE AND TIME`、对应本地化前缀或“票面数值”；
- 日文、现代希腊文和俄文长文本在屏幕、SVG 下载与打印中不破坏字素、不覆盖二维码，完整场次、地点、分区和价格同时保留在可见凭单与可访问替代中；
- 屏幕票面完成图像解码，下载 SVG 可被独立 XML 解析器接受，打印版本与二者使用同一冻结事实和组合印章；
- 标准成功、直接／优惠优先成功及此前经历过的网络、拒绝或失败具有可区分但不露骨书写结局的七构件印章，相同冻结结果跨国家版本和媒介保持语义稳定；
- 水稻网页眉与自身提示框同时展示名称和正式独立 Logo；跳楼机邀请、挽留与结果提示框同时展示名称和另一枚正式 Logo。后续临时预览资产不能通过 `approved-only`，正式 Logo 替换不要求修改平台身份、状态机或布局；
- 模组关闭、脚本关闭或加载失败时，稳定票务页、不可用反馈和返回路径仍成立，表站其他任务不受影响。
