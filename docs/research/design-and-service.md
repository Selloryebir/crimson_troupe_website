# 机构网站设计与服务能力分析

记录日期：2026-08-20

本文件记录公开机构网站的能力分析、可迁移原则和排除项。它提供设计依据，不描述当前实现；已经采纳的产品结果只由 active 蓝图和源码拥有。

## 参考对象

- [Vienna Philharmonic / 维也纳爱乐乐团](https://www.wienerphilharmoniker.at/)
- [Royal Ballet and Opera / 英国皇家芭蕾舞团与歌剧院](https://www.rbo.org.uk/)
- 人工提供并指定时期归属的《明日方舟》官方视觉材料：新剧团侧参考《红丝绒》支线剧情插图，旧剧团侧参考《傀影与猩红孤钻》集成战略插图；临时分析素材不进入仓库或运行时

## 借鉴并转译的内容

### 1. 从品牌吸引到演出决策的连续路径

维也纳爱乐首页在机构介绍之外突出当前新闻、乐季亮点，并将观众引向完整音乐会日历。由此可提炼的项目路径是：

1. 用主视觉和剧团宣言建立品牌印象；
2. 紧接本季演出与实际日期；
3. 提供月份、巡演城市筛选；
4. 从剧目详情进入相关场次，再衔接席位预约。

若项目采用这一顺序，界面、演出名称、城市、日期和文案仍须原创，不能复刻参考站的卡片样式或日历布局；剧目与具体场次应使用不同实体承担各自信息。正式采用情况见 `BP-FND-EXPERIENCE` 与 `BP-MOD-PROGRAMS`。

### 2. 可检索、可筛选的演出档案

维也纳爱乐的音乐会日历可按指挥、作曲家、地点等字段筛选，并把长期演出档案作为机构历史的一部分。可迁移原则是使用结构化节目数据和有限、任务相关的筛选，不照搬完整字段集合。

“历史快照”还可以同时承担馆藏入口和双时间层裂缝，但规范路径、发现方式与返回能力属于正式产品契约，只在 `BP-MOD-ARCHIVE` 中维护。

### 3. 观看方式的责任边界

RBO 首页将内容区分为现场演出、影院放映、线上串流和其他活动。可迁移原则是不同观看方式必须有清楚状态和入口；是否采用某种方式以及怎样与票务衔接，只由 `BP-MOD-PROGRAMS` 与 `BP-MOD-TICKETING` 决定。

影院放映、线上串流及其泰拉化形式不能因为出现在研究对象中就形成隐藏待办。未来若确有需求，应独立说明内容状态、入口、失败路径和双时间层影响。

### 4. 剧目详情的信息完整度

RBO 的剧目详情集中呈现观看方式、日期、地点、时长、语言、内容提示、剧情、主创和无障碍资源。可迁移的是“决策信息集中且可以继续行动”的责任，而非页面外观。适合本项目领域模型的分工是：

- 场次详情列出日期、地点、场次与票务状态及有序剧目编排；
- 剧目详情呈现独立视觉、简介、时长、语言、主创和观演提示；
- 剧目通过相关场次连接具体日期与地点，可购买场次再进入统一票务页。

研究对象提供但项目尚未正式拥有的数据不能由本文件代为宣称；场馆无障碍服务等能力若被采用，必须进入正式内容及审核范围。

### 5. 搜索作为服务，也作为叙事

维也纳爱乐提供全站搜索和多语言入口。两者适合被转译为相互独立的“分域检索”与“国家版本导航”能力，不能因共享入口而混合索引、内容身份或状态。正式范围与污染协作分别见 `BP-MOD-SEARCH`、`BP-I18N-CORE` 和 `BP-MOD-ARCHIVE`。

### 6. 视觉层面的抽象原则

两个参考站都把演出内容置于视觉中心，使用明确的标题层级、克制的机构导航、充足留白，以及编辑内容与事务信息之间的节奏变化。本站吸收了这些抽象原则，并继续使用自身既有的猩红、纸色、黑色系统和 CSS 舞台装置语言。

### 7. 双时期官方视觉材料的抽象转译

人工指定的新、旧剧团时期材料只用于识别多张图反复出现的艺术规律：两站共享剧场、帷幕、面具、聚光、猩红和框景母题；表站材料以宽银幕裁切、近远景遮挡、斜向运动、猩红轨迹、冷色轮廓光和电影制作图形支持“当代编辑系统 + 受控电影舞台”，里站材料以正面轴线、门廊、画框、舞会、旧金、烛光和深色帷幕支持“仪式档案剧场 + 逐级受控污染”。

第二次材料复核专门纠正了两种表面化理解：表站的明亮不等于全页浅色极简，里站的古老不等于通用暗色复古或预先损坏。两站都需要页面环境、内容表面和舞台或档案焦点三层空间，但分别通过电影化裁切与礼仪化框景实现。

这些结论不授予素材使用权，也不要求网站复刻角色、场景、标题字形、活动包装或独特构图。具体行为边界以 `BP-FND-EXPERIENCE` 和 `BP-MOD-ARCHIVE` 为准，运行时继续优先使用项目自有 HTML/CSS 图形和权利清晰的素材。

### 8. 国家版本选择与语言技术参考

- [MediaWiki Universal Language Selector](https://www.mediawiki.org/wiki/Extension%3AUniversalLanguageSelector) 与 [ULS Specification](https://www.mediawiki.org/wiki/Universal_Language_Selector/Specification)：只借鉴以本国语言称谓帮助识别语言、保持浏览上下文以及提供关闭和键盘路径的原则，不复制其大规模语言搜索、布局、字体或代码；
- [W3C：在 HTML 中声明语言](https://www.w3.org/International/questions/qa-html-language-declarations.html) 与 [WHATWG HTML Standard](https://html.spec.whatwg.org/multipage/semantics.html)：用于页面及局部 `lang` 和 UTF-8 边界；
- [W3C CSS Fonts Module Level 4](https://www.w3.org/TR/css-fonts-4/)：用于系统字体顺序匹配与缺字回退；该来源本身不要求引入远端字体或通用字体平台。

### 9. 剧目出版物与猩红印版的抽象证据

人工提供的成组剧目物料只用于归纳跨样本反复出现的制度：稳定题签与外围出版边界、彼此不同的中央隐喻、深墨轮廓与色块、旧金细线、剧目记忆色、封面下方中轴的固定归属标记，以及猩红版本中外围煤黑、半透明焦红烟版、重复裂口和不规则物件轮廓的协作。普通与猩红物料在本站被转译为“同一剧目身份、两个时间层各自装帧”，不被解释为损坏、修复、升级或污染前后；固定标记的出版职能由项目原创的舞台口、帷幕与光束负形承担，不重画参考徽记。

正式创作规则见 [`BP-CNT-PRODUCTION-VISUAL`](../blueprint/content/production-visual-language.md) 与作者指南；本文件不另存第二套制作规范。原始样本不进入仓库、不作为网页资产或图生图输入，也不复制其中的角色、徽记、题签字形、边框、内部图形或独特构图。

## 明确没有借鉴的内容

- 没有下载或使用参考站的图片、视频、图标、字体、Logo 或其他品牌资产；
- 没有复制参考站的 HTML、CSS、JavaScript、组件代码或接口；
- 没有逐字使用其标题、宣传语、剧目介绍或事务说明；
- 没有复刻其网格尺寸、页面顺序、动画参数或购票流程；
- 没有伪装成参考机构，也没有建立任何附属或合作关系；
- 不以研究对象为由引入真实付款、个人信息收集或伪装合作关系。

## 后续使用规则

若继续参考其他文化机构网站，应追加记录：参考对象、抽象能力、泰拉化方式和排除项。任何官方图片、音频、字体或商标资产都不得因“参考”而直接进入仓库。
